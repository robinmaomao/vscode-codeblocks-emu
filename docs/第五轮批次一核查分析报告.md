## 1. 逐项分析

### P1 工程树 Find file…（快速查找定位）

**CB 源码行为**（`projectmanagerui.cpp:2560-2665`）：

1. `ListNodes(sel)` 收集选中节点（工程/文件夹/工作区）下的**全部文件名**；工作区选择时额外加入各 `.cbp` 文件名
   并映射为工程标题（`fileNameMap`）。
2. 弹出 `GotoFile` **增量搜索对话框**（输入即过滤，列宽 300）。
3. 底部 **`Open file` 复选框**（记住设置 `/project_manager/find_file_open`，默认 **false**）。
4. 确认后：勾选 → 打开文件；未勾选 → **在工程树中逐级展开并定位（select/ensure visible）**该文件。

**扩展现状（复核）**：

- 无任何查找命令（第五轮 0 命中确认）。
- 已有可复用件：`projectTreeView.reveal`（VS Code TreeView API）、虚拟文件夹节点（provider `kind: 'virtualFolder'`）。
- **注意**：provider 未实现 `getParent`（全文件 0 命中）——`treeView.reveal` 展开祖先需要它（或需按路径构造节点）。

**VS Code 原生评估**：`Ctrl+P`（Go to File）为**工作区级**模糊搜索：不能限定单个 .cbp 工程/文件夹、不显示虚拟文件夹归属、
**不会定位工程树节点**。VS Code 自定义树视图**没有**原生增量过滤/查找。→ 原生不可替代。

**实施方案**：

- 命令 `codeblocks.findFile`（Search 菜单 + 工程树（工程/文件夹/虚拟文件夹/文件分组）右键 `Find File…`）。
- UI：`showQuickPick`（fuzzy、显示虚拟文件夹路径 + 相对路径；工作区模式附加 `.cbp` 项）。
- 行为对齐 CB：默认**定位**（reveal + select + expand）；设置 `codeblocks.ui.findFileOpen`（boolean，默认 false）为 true 时
  定位后同时打开文件（对应 CB 的 `Open file` 复选框 + 持久化语义）。
- 需补 provider `getParent`（或单文件查找 API `findNode(project, rel)`）以支持 reveal；成本含此项。

**测试**：命令存在性 + 菜单接入（menu-structure 测试）；纯函数部分（文件列表构造：工程/文件夹/工作区三态 + 虚拟夹路径）单测；
reveal 行为人工验收（树为 VS Code 宿主对象，不可 headless 断言）。

### P2 Add files recursively…（递归添加目录）

**CB 源码行为**（`projectmanagerui.cpp:1625-1711`）：

1. 基准目录 = 点击的文件夹节点（否则工程根）；`ChooseDirectory` 选择目录。
2. `wxDir::GetAllFiles(dir, &array, "", wxDIR_FILES|wxDIR_DIRS)` 递归枚举。
3. **过滤**：目录本身、`.git/.hg/.svn/CVS` 目录内容、`*.cbp`。
4. `MultiSelectDlg` 多选（通配符来自工程「文件类型/类别掩码」）。
5. `SetupTargets`：**多构建目标时弹出目标选择**（单目标直接指定）。
6. `AddMultipleFilesToProject(files, prj, targets)`（带进度对话框 + 插件通知）+ `RebuildTree()`。

**扩展现状（复核）**：

- `codeblocks.addFile` 仅多选**文件**（`showOpenDialog`），无目录枚举；无目标选择步骤（写入隐式全目标）。
- 已有可复用件：`buildUnitXml`（按扩展名写 compilerVar）、`writeUnitsToCbp`（文本插入保留原格式）、
  去重 `existing: Set(relativeFilename)`、`persistProjectAndReload`。

**VS Code 原生评估**：无「目录 → 自定义工程模型」概念；`showOpenDialog({ canSelectFolders })` 可复用为目录选择；
文件枚举可自写 `fs.readdir` 递归（`workspace.findFiles` 需相对化且受 files.watcherExclude 影响，不采用）。→ 原生不可替代。

**实施方案**：

- 命令 `codeblocks.addFilesRecursively`（Project 菜单 + 工程/文件夹节点右键）。
- 流程：选目录 → 递归枚举（过滤 SCM/隐藏/`obj|bin`*/`.cbp`/已收录）→ `showQuickPick(canPickMany)`（扩展名白名单过滤，
  默认全选）→ 多目标时目标 `showQuickPick(canPickMany)`（默认全部；单目标直接该目标）→ 写 `.cbp` → 重解析刷新。
- 白名单与 `addFile` 现有过滤器一致（c/cpp/cc/cxx/c++/h/hpp/hh/rc/s/S + 常见附加），可在 QuickPick 说明中展示计数。

**测试**：纯函数（递归枚举 + 过滤规则）+ 写回往返（临时目录夹具：嵌套 + .git + obj + 重复文件 + 目标选择三态）。

### P3 Rename file…（重命名磁盘文件 + 更新工程引用）

**CB 源码行为**（`projectmanagerui.cpp:2852-2916`）：

1. **拒绝自动生成文件**：`if (pf->AutoGeneratedBy()) → "Can't rename file because it is auto-generated..."`。
2. 输入新名（默认原名）。
3. 若编辑器已打开该文件：询问 `"The file must be closed before renaming, continue?"` → 关闭编辑器。
4. Windows 允许**大小写仅变体**的重命名（`wxRenameFile(..., old.Lower()==new.Lower())`，即允许覆盖同 CI 名）。
5. `wxRenameFile` 失败 → 响铃返回；成功 → `pf->Rename(newName)`（更新对象名等）+ `RebuildTree()`；
   `.cbp` 落盘随工程保存（CB 后续保存时写入新路径）。**不改其它工程中的同名引用**。

**扩展现状（复核）**：

- 无重命名命令；当前用户流程 = 移除文件 + 重新添加 → **丢失** compilerVar/compile/link/weight/virtualFolder/
  自定义构建命令/目标归属（重新添加按默认值写入）。
- **VS Code 原生 F2 改名**：仅改磁盘名，`.cbp` 不更新 → 下次构建报「源文件缺失，跳过」警告——**现状比“没入口”更危险**（静默破坏）。
- 已有可复用件：`removeUnitFromCbp`/`setUnitOptionInCbp`（`<Unit>` 文本手术模式）、`normalizePath`、`persistProjectAndReload`、
  `buildInProgress` 构建互斥守卫。

**实施方案**：

- 命令 `codeblocks.renameFile`（文件节点右键，置于 `1_file@0`）。
- 流程（逐步对齐 CB + VS Code 适配）：
  1. 守卫：自动生成文件 → 报错拒绝；构建进行中 → 拒绝；只读文件 → 拒绝。
  2. 输入新文件名（`showInputBox`，默认原名，校验非法字符）。
  3. 若 VS Code 有打开该文件的编辑器（`workspace.textDocuments` 匹配 fsPath）：
     警告「需先关闭编辑器」，确认后 `workbench.action.closeActiveEditor`/关闭对应文档。
  4. `vscode.workspace.fs.rename`（同目录；大小写仅变体 → 允许，失败回退两段式改名）。
  5. 文本手术更新 `.cbp`：仅该 `<Unit filename="old">` → new（保留全部子 `<Option>`）。
  6. **其它已打开工程引用同一绝对路径** → 状态栏提示列表（不自动改，对齐 CB 只改当前工程；可选后续增强）。
  7. 重解析 + 刷新树 + 提示；打开新文件（可选，对齐 VS Code 习惯）。
- 记录项：旧对象文件不迁移（CB 同）；`Clean` 只删新对象名（与 CB 一致）。

**测试**：文本手术单测（含带 `<Option>` 子节点保留、特殊字符文件名）、拒绝路径（autoGenerated/构建中）、
往返（重命名后 reparse 归属/选项不变）。

### P4 虚拟文件夹管理（新增 / 改名 / 删除 [+ 拖动入夹]）

**CB 源码行为**：

- 命令（`projectmanagerui.cpp:2699-2760`）：`Add new virtual folder...`（输入「folder path」，可多级）；
  `Rename this virtual folder`（禁 `; \ /`，同名 no-op）；`Delete this virtual folder`。
- 语义（`cbproject.cpp:1051-1097`）：
  - `RemoveVirtualFolders(folder)`：列表移除（**`StartsWith` 含子级**）+ 所有文件 `virtual_path` 前缀匹配**清空**（文件回根，**不删文件**）+ `SetModified(true)`；
  - `ReplaceVirtualFolder(old, new)`：列表与文件 `virtual_path` **前缀替换**（保留子路径）。
- 拖动（`ProjectVirtualFolderDragged`）：文件拖到文件夹 → 仅改**模型的 `virtual_path`**（磁盘不动）。

**扩展现状（复核）**：

- **已具备**：模型 `Project.virtualFolders: string[]` + `ProjectFile.virtualFolder`；writer 写出 `<Option virtualFolder>` 与
  `<Option virtualFolders>`；工程树按虚拟夹嵌套分组（`kind: 'virtualFolder'`）+ **空文件夹也显示**（`mergeEmptyVirtualFolders`）；
  面板「文件」tab 可逐文件编辑 virtualFolder；测试 `test-vfolder-sim`/`test-tree-lazy2`。
- **缺失**：三命令 + 拖拽入夹 + 面板批量入口。

**实施方案**：

- 命令 3 个：`codeblocks.newVirtualFolder` / `codeblocks.renameVirtualFolder` / `codeblocks.deleteVirtualFolder`
  （工程/虚拟夹节点右键 + Project → Project tree 子菜单）。
  - New：`showInputBox`（路径，允许多级 `a/b`；禁 `; \`）。
  - Rename：`showInputBox` 默认当前名；**精确前缀替换**（`old` 本身或 `old/` 前缀——CB 用裸 `StartsWith` 会误伤 `ab`，扩展取
    精确前缀为保护性差异并记录）。
  - Delete：确认对话框（提示 N 个文件将移回根，**不删文件**）→ 列表移除（含子级）+ 相关文件 `virtualFolder` 清空。
- 拖动：扩展 `ProjectDragAndDropController.handleDrop`——目标为 `virtualFolder`/`folder`/`project` 且拖源为文件（或
  面板选中的多文件？VS Code 拖拽为单源多元素——支持多选拖动）→ 批量改 `file.virtualFolder`（拖到工程根=清空）→ 写回。
- 写回统一走 `serializeProject`（含 virtualFolders 列表与文件属性）+ `persistProjectAndReload`。

**测试**：三命令的模型变换纯函数（含子级、精确前缀、同名 no-op、非法字符）+ 写回往返 + 树分组快照（复用 vfolder-sim 模式）。

### M3 文件节点 Properties…（直达面板文件页）

**CB**：`projectmanagerui.cpp:1101` 文件右键 `Properties...` → 文件属性对话框（compilerVar/compile/link/自定义命令/目标归属）。

**扩展现状**：工程属性面板「文件」tab 已含**全部**对应字段（compilerVar/compile/link/weight/虚拟夹/自定义命令/目标归属）；
工程节点右键已有 `Properties…`；**文件节点**缺直达入口（需：打开面板 → 切「文件」tab → 翻找行）。

**实施方案**：命令 `codeblocks.fileProperties`（文件节点右键 `0_properties@1`）→
`ProjectPropertiesPanel.show(project, uri, onSave, 'files', focusFile=<relativeFilename>)`：面板在渲染后切换到 files tab
并**滚动/高亮**该文件行。成本 XS（≈35 行，含 `show()` 可选参数与面板脚本 3 行）。

**测试**：面板 HTML 脚本语法（`test-html-syntax`）+ 参数透传断言。

## 3. VS Code 原生替代评估（不可替代的原因）

| 原生能力 | 评估 |
|---|---|
| `Ctrl+P` Go to File | 工作区级模糊搜索；**不限定工程**、不显示虚拟夹、**不 reveal 工程树** → P1 仍需实现 |
| Explorer F2 重命名 | 只改磁盘名，**不更新 .cbp**（工程变“源缺失”）→ P3 必须由扩展接住 |
| 自定义树过滤/查找 | VS Code **无** 树视图增量过滤 API → P1 需自建 QuickPick |
| `workspace.fs.rename` | 可复用为 P3 的改名原语（含大小写变体处理） |
| TreeView `reveal` / TreeDnD | 可复用（P1 定位 / P4 拖拽）——P1 需补 `getParent` |
| QuickPick（fuzzy / canPickMany / matchOnDescription） | P1/P2 的主 UI |

## 5. 风险与边界（实现时注意）

1. **P1**：`treeView.reveal` 需 `getParent`（懒加载树）；工作区模式含 `.cbp` 项应打开工程而非文件。
2. **P2**：`obj/`、`bin/`、`.git/` 等必须过滤（否则几百个对象文件入工程）；目标选择仅在多目标时出现（对齐 `SetupTargets`）。
3. **P3**：构建中拒绝；打开编辑器先关（否则 Windows 上 fs.rename 可能 EPERM）；`<Unit>` 之外**不可**残留旧引用
   （`external_deps`/`additional_output` 不涉及文件项，核对通过）；跨工程引用仅提示。
4. **P4**：删除必须**只动模型**（绝不删磁盘文件）；前缀匹配用精确语义（`a` vs `ab`）；`;`/`\` 禁入名称；DnD 需同时支持
   多选拖动与「拖到工程根=清空」。
5. **M3**：面板为单例，重复调用应复用现有实例并仅切换 tab/行高亮。
