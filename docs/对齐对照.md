# 与 Code::Blocks 对齐对照表

> 本扩展的定位是**原生移植 Code::Blocks 的构建/调试内核**：直接解析 `.cbp` / `.workspace`、
> 内置 Code::Blocks 的命令模板与宏展开引擎、直接派生进程执行编译/链接/调试，**不是**
> `.cbp → tasks.json/launch.json` 桥接。本文档以表格逐项记录扩展与 Code::Blocks 的对齐依据
> （对应 `codeblocks-src/` 中的源码位置）、已对齐实现，以及有意保留的差异与尚未实现的限制。
> 最后更新：0.8.22-dev（2026-09-25）。

## 1. 构建链路对齐

| 项 | Code::Blocks 依据 | 扩展实现 |
|---|---|---|
| 编译单元收集 | `directcommands.cpp GetCompileFileCommand`：compile=true 且可编译类型/自定义命令/PCH/生成器 | `buildEngine.buildTarget` 1b：compile=false 跳过；自定义 buildCommand、可编译类型、supportsPCH 头文件、生成器文件纳入 |
| 链接对象收集 | `GetTargetLinkCommands`：`GetProjectFilesSortedByWeight(target,false,true)` 只过滤 !link + 文件类型 | 1a：`file.link===false` 与 `isLinkableFileType` 双重过滤；资源文件独立 `$link_resobjects` |
| weight 排序 | `MySortProjectFilesByWeight`（weight 升序，同 weight 字节序 CmpNoCase/Cmp） | `compareFilesByWeight`（字节序比较，不用 localeCompare） |
| COMPILER_WAIT 屏障 | 同 weight 并行，跨 weight 串行 | `runInParallel` 按 weight 分组；组内 PCH 先编译 |
| 增量编译 | `IsObjectOutdated`：源/头依赖 mtime；源缺失跳过；时间戳读取失败回退编译 | `isUpToDate` + `depsNewestMtime`（含注释/字符串剥离的 #include 扫描） |
| deps 扫描目录 | `DepsSearchStart`：项目+目标 include 目录（不含编译器全局目录） | `getIncludeDirs`（宏展开后扫描） |
| 链接跳过 | `GetTargetLinkCommands` 时间戳检查（输出 ≥ 所有对象） | `linkObjectsUpToDate`；Windows 无扩展名输出 `.exe` 回退 |
| 外部依赖强制重链 | `AreExternalDepsOutdated`：库/`external_deps`/`additional_output` 比输出新 → 重链，缺失 → WARNING | `areExternalDepsOutdated`（含「目标已最新」路径，对齐 CB 先查外部依赖再跳过的顺序） |
| 链接命令类型映射 | `GetTargetLinkCommands` ttConsoleOnly/ttExecutable/ttDynamicLib/ttStaticLib/ttNative → ct* | `linkCommandType` |
| 选项关系合并 | `GetOrderedOptions`（5 种关系，项目/目标合并顺序） | `combineOptions` + `OptionsRelation` |
| 链接库构造 | `FixupLinkLibraries`/`SetupLinkLibraries`：项目+目标库 + 编译器全局库追加；含路径库原样保留；剥前缀后才剥扩展；needsLibExtension 补扩展；needsPathResolved 库目录解析；逐库引号 | `setupLinkLibraries`/`fixupLinkLibrary`/`pathSearchLibrary` |
| 编译器开关 | `forceFwdSlashes`（逐组件 `\`→`/`，跳过 `\ `）；`Use83Paths` 源文件短路径（文件存在时）；`UseFullSourcePaths=false` 时 `$file` 相对路径 | `fixSep` / `shortPathWin` / `relativeFilename` |
| 编译器全局搜索目录 | `compiler.cpp LoadSettings`：default.conf `/compiler_sets/<id>` include_dirs/library_dirs/res_include_dirs/link_libs，追加在项目/目标后 | `CodeBlocksConfig.searchDirs` + `commandGenerator.setup*Dirs` 追加 |
| 宏展开顺序 | `compilercommandgenerator.cpp`：$compiler→$options→$file*→$objects_output_dir→$object→… | `renderTemplate` 同序；`replaceAllMacros` 迭代替换（≤5 轮） |
| C/C++ flag 过滤 | `GetCPPOnlyFlags/GetCOnlyFlags` 移除 | `filterOutFlags` |
| 响应文件 | `CheckForToLongCommandLine`：超长分割 + `\\` 转义 + `@file`；命名=对象目录/源文件名.respFile、对象输出目录/\<title\>_link.respFile | `applyResponseFile(command, respBase)` |
| PCH | 三模式对象命名 + 旧 .gch 删除 + 组内屏障 | `pchObjectRelative`（mode 0/1/2）+ 编译前 del |
| pre/post 脚本 | `GetPreBuildCommands/GetPostBuildCommands` + 状态机：项目 pre 一次（首目标上下文）、每目标 pre/post、项目 post 一次且 `hasCommands` 门控 | `engine.build` 项目级一次；`buildTarget` 目标级；`hadCommands` 门控 |
| 生成文件（GenFilesHackMap） | `cbproject.cpp AddFile`：编译器 XML gen 属性、延后编译、对象命名、clean 删本体 | `generatedFiles.ts applyGeneratedFiles` + deferredUnits |
| 对象命名 | `projectfile.h pfDetails::Update/GetObjName`：flat/extended/.res/PCH/公共顶层 | `objectPathRelative`/`pchObjectRelative` |
| 静态库/import/def 命名 | lib 前缀 + 扩展 + `GetStaticLibFilename`/`GetDynamicLibDefFilename` | `computeStaticOutput`/`computeLibOutput` |
| Clean 范围 | `GetTargetCleanCommands`：对象 + 输出 + 生成文件本体 + 动态库 import 库 | `cleanTarget`（CommandsOnly 不删输出） |
| 构建 EnvVars | 不应用到编译命令（仅 Run/Debug） | 同样仅 Run/Debug |
| UseFullSourcePaths | gcc/clang XML 默认 true → 源文件绝对路径 | 始终绝对路径 |
| 资源文件短路径 | `GetCompileFileCommand`：windres 空格 bug → GetShortPath | `shortPathWin`（cmd %~sI + 缓存） |
| Use83Paths 目录 | `GetOrdered*Dirs` 目录存在时短路径 | `finalizeDir` |
| 编译随时停止 | Code::Blocks 工具栏 Stop Build（中断队列 + 杀进程） | 通知 ❌ 按钮 + `Code::Blocks: Stop Build`，`taskkill /T /F` 进程树强杀 |
| Rebuild 确认 | Rebuild 前确认对话框 | 模态确认框（关闭 = 无动作） |
| 项目自定义变量 | `cbproject SetVariable` + macrosmanager ReplaceMacros | parser 解析 `codeblocks_project_custom_variables` + 迭代替换 |
| 输出文件名宏展开 | `ReplaceMacros(outputfilename, target)` | `expandedOutputFilename` |

## 2. 输出与交互对齐

| 项 | Code::Blocks | 扩展 |
|---|---|---|
| Banner | `PrintBanner`（bsTargetPreBuild，项目 pre-build 之后，每目标一次）：`-------------- Build: … --------------` | 同顺序同文案（每目标一次） |
| up-to-date 提示 | "Target is up to date." | 「目标已是最新」 |
| post-build 门控 | 最后目标 `hasCommands` 或 alwaysRunPostBuildSteps 才跑项目 post | `hadCommands` 同语义 |
| 脚本命令编号 | 无（直接打印命令） | `[script 1-3]` 编号（有意增强，防链接误判） |
| 编译进度 | 逐文件 `Compiling/Compiled` | 单行完成式 `✓ [Compiled] 123-248 xxx.c (2.0s)`（有意增强，无交错） |
| 错误/警告解析 | 编译器 XML 正则 + 严重级别 | 同正则移植 + 官方日志级别着色 |
| 快捷键 | F9/Ctrl+F9/Ctrl+F10/Ctrl+F11/Ctrl+Shift+F9/F8/F4/Shift+F4 | 全部对齐 |

## 3. 有意的差异（保留，不追求逐字节一致）

| 差异 | 原因 |
|---|---|
| 编译器程序展开为**带引号完整路径**（CB 为裸名 + PATH 注入） | 防 PATH 注入失效时命令找不到；功能等价 |
| 引号规则更宽（空格 + cmd 元字符 `& \| < > ^ ( )`；CB 仅空格） | shell 二次解析防护；含空格库名的双层引号与 CB NeedQuotes 字节一致 |
| 脚本编号 `[script 1-3]`、单行完成式日志、Emoji 汇总块、最慢 Top3 | VS Code 环境下的可读性增强（用户已确认） |
| 中文日志文案 | 面向中文用户 |
| CommandsOnly 目标 post 执行一次（CB 因 ttCommandsOnly 分支会执行两次） | CB 怪癖，不复制 |

## 4. 尚未实现（已知限制）

| 功能 | 说明 |
|---|---|
| 跨卷对象路径 | 对象文件位于不同盘符时的相对路径处理未实现 |
| makefile 项目模式 | `<Option makefile_is_custom="1"/>` 未支持 |
| Squirrel 构建脚本 | `<Script file="*.script"/>` 未支持（警告跳过） |
| console runner | Code::Blocks 的 cb_console_runner 未移植 |
| 单文件编译 / 单文件 Clean | `CompileFile` 右键功能未实现 |
| `include_prj_cwd` / `include_file_cwd`（compiler 配置） | 追加项目根目录/文件目录到 include 搜索目录的开关未实现（默认 false） |
| `forceCompilerUseQuotes` / `forceLinkerUseQuotes` | CB 命令生成中本身未使用该开关（仅读取/保存/UI），故不实现 |
| DAP 深层成员赋值 | 调试变量赋值仅顶层 + 一层成员 |
| 其他工程模板 | sdl/glfw/qt/wxwidgets 等模板未移植 |

## 5. 测试保障

- 全量回归脚本（`test-*.js`，33+ 断言组）覆盖：解析/序列化/选项关系/对象命名/权重排序/响应文件/静态库/生成文件/取消源/外部依赖/自定义变量等。
- 无头真实构建校验（`test-project/headless-build-check.js`）：驱动 GCC 真实编译/链接静态库→可执行链路、外部依赖 touch 强制重链、双目标项目脚本执行次数与顺序。
