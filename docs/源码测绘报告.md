# Code::Blocks 源码测绘报告（第一阶段）

> 本报告基于 `codeblocks-src/`（Code::Blocks 25.03, SVN rev 13644）实际阅读产出，是「原生移植到 VS Code 扩展」P0 阶段的解耦依据。

## 1. 核心机制总览

Code::Blocks 的构建链路是一条清晰的流水线，与 UI 完全解耦的部分正是我们要移植的：

```
.cbp/.workspace (XML)
   → ProjectLoader::Open()        [src/sdk/projectloader.cpp]
   → cbProject / cbWorkspace / ProjectBuildTarget / ProjectFile  (内存对象图)
   → CompilerCommandGenerator::Init(project)   [src/sdk/compilercommandgenerator.cpp]
   → GenerateCommandLine()  ←  命令模板($compiler $options...) + 宏展开
   → DirectCommands::GetCompileCommands/GetTargetLinkCommands()  [compilergcc/directcommands.cpp]
   → 派生进程执行 → 输出按 RegExStruct 分类(错误/警告) → Diagnostics
```

## 2. 关键数据模型（.cbp 解析）

### ProjectLoader 解析入口与顺序（projectloader.cpp）
- `Open(filename)`：解析根 `<CodeBlocks_project_file>`，读 `<FileVersion>`（第 98 行）
- 顺序：`DoProjectOptions` → `DoCompilerOptions` → `DoResourceCompilerOptions` → `DoLinkerOptions` → `DoIncludesOptions` → `DoLibsOptions` → `DoBuildTarget`（每个 `<Target>`）→ `DoUnitFiles`
- 选项以 `<Add option="..." />` 子元素承载（第 704/734/764/828/850 行）
- 文件以 `<Unit filename="..." />` 承载（第 1251 行 `FirstChildElement("Unit")`，循环 `NextSiblingElement`）
- 虚拟文件夹：`Option` 节点的 `virtualFolders` 属性，以 `;` 分隔（第 445-446 行）

### 目标类型（compiletargetbase.h）

### 编译器/链接器选择（compilercommandgenerator.cpp 第 260-340 行）
- 按文件扩展名选择 C/CPP 编译器；`compilerVar`（CC/CPP/WINDRES）决定
- 链接器按 `LinkerExecutableOption`（CCompiler/CppCompiler/Linker/AutoDetect）+ 是否含 C++ 文件选择

## 3. 命令生成核心（最高价值移植点）

### 命令模板（options_gcc.xml 第 147-174 行）
```
CompileObject:   $compiler $options $includes -c $file -o $object
GenDependencies: $compiler -MM $options -MF $dep_object -MT $object $includes $file
LinkConsoleExe:  $linker $libdirs -o $exe_output $link_objects $link_resobjects $link_options $libs
LinkExe:         $linker $libdirs -o $exe_output $link_objects $link_resobjects $link_options $libs -mwindows
LinkDynamic:     $linker -shared -Wl,--output-def=$def_output -Wl,--out-implib=$static_output -Wl,--dll $libdirs ...
LinkStatic:      $lib_linker -r -s $static_output $link_objects
```

### 命令类型枚举（compiler.h 第 160-180 行）
```cpp
enum CommandType { ctCompileObjectCmd, ctGenDependenciesCmd, ctCompileResourceCmd,
  ctLinkExeCmd, ctLinkConsoleExeCmd, ctLinkDynamicCmd, ctLinkStaticCmd, ctLinkNativeCmd, ctCount };
```

### 宏展开（GenerateCommandLine 第 445-460 行，核心替换表）
```
$compiler $linker $lib_linker $rescomp
$options $res_options $link_options
$includes $res_includes $libdirs $libs
$file $file_name $file_dir $file_ext $file_basename
$object $resource_output $objects_output_dir $dep_object
$exe_output $exe_name $exe_dir $exe_ext
$static_output $def_output
$link_objects $link_flat_objects $link_resobjects
$+link_objects $-link_objects $-+link_objects $+-link_objects
$all_link_objects_quoted
```

### 宏替换顺序（关键！须严格遵守，否则 `$object` 会吞掉 `$objects_output_dir`）
1. 先替换 `$compiler/$linker/$lib_linker/$rescomp`
2. 再替换 `$options/$res_options/$link_options/$includes/$res_includes/$libdirs/$libs`
3. 文件相关 `$file*`、`$dep_object`
4. `$objects_output_dir`（**必须在 `$object` 之前**）
5. `$object`、`$resource_output`
6. `$exe_output/$exe_name/$exe_dir/$exe_ext`
7. `$link_resobjects/$link_objects/$link_flat_objects` + 4 个 QUICK HACK 变体
8. `$all_link_objects_quoted`
9. 静态/动态库特判 `$static_output/$def_output`（含 `-Wl,--out-implib=` 特例清空）
10. 最后 `MacrosManager::ReplaceMacros()`（用户自定义宏 + 环境变量）

## 4. 错误/警告解析（RegExStruct → problemMatcher）

- `RegExStruct`（compiler.h 第 100-155 行）：`desc` + `lt`(类型) + `msg[3]`(子表达式序号) + `filename` + `line`
- `CompilerLineType`：`cltNormal/cltWarning/cltError/cltInfo`
- 正则来源：`options_common_re.xml`（`<RegEx type="error/warning/info" msg file line>` + CDATA 正则）
- 典型 GCC 错误正则（第 122-130 行）：
  `([...]+):([0-9]+):[0-9]+:[[:blank:]](.*)` → file=1, line=2, msg=3
- POSIX 字符类 `[[:blank:]]` 需转换为 JS 等价（`[ \t]`）；wxRegEx 语义与 JS RegExp 差异需注意

## 5. 编译器选项 XML 结构（options_gcc.xml）

- `<Program name="C|CPP|LD|LIB|WINDRES|MAKE|DBGconfig" value="..."/>`（含 `<if platform="windows">` 分支）
- `<Switch name="..." value="..."/>` → 映射到 `CompilerSwitches` 成员
- `<Option name option supersedes checkAgainst additionalLibs/>` → 编译选项
- `<Command name="CompileObject|GenDependencies|..." value="$compiler ..."/>` → 命令模板
- `<Common name="warnings|architecture|cmds|re|sort"/>` → 引用 `options_common_*.xml` 公共片段
- 编译器继承：`options_gcc.xml` 无 extends；`options_gcc-mingw32.xml` 等通过 `extends` 继承（compiler.cpp `LoadDefaultOptions(extends)`）

## 6. 依赖隔离分级（解耦策略）

| 级别 | 内容 | 处理 |
|------|------|------|
| 纯逻辑（零 wx） | 宏展开、命令模板、RegExStruct 匹配、TargetType/OptionsRelation 枚举 | TypeScript 直接重写 |
| 弱 wx 依赖 | wxString/wxArrayString（可等价 std::string/string[]）、TinyXML | TS 原生 JSON/XML 重写 |
| 强 wx UI 依赖 | 对话框、树控件、wxScintilla 编辑器 | 重写为 VS Code Webview/TreeView |
| 平台进程 | 派生编译进程、读 stdout/stderr | Node `child_process` |
