## 1. 高优先级发现（建议尽快处理）

### 1.1 VSIX 误打包 `release/` 旧产物（464 KB）+ 未做打包压缩

- **证据**：`npx vsce ls` / `vsce package` 输出包含 `release/ (1 file) [464.23 KB]`，即 `release/codeblocks-vscode-0.8.92-dev.zip`（旧版打包 zip）被装入 VSIX；该目录在 `.gitignore` 中被忽略（`*.zip`），但 **`.vscodeignore` 未排除 `release/**`**，导致发布产物内混入历史压缩包（占 VSIX 体积约 48%）。
- **同时**：vsce 输出 WARNING——"This extension consists of 189 files, out of which 108 are JavaScript files. For performance reasons, you should bundle your extension"（当前 `node_modules` 中 fast-xml-parser 等连同 CLI 文件整包进入 VSIX，扩展冷启动需加载 108 个 JS 文件）。
- **建议**：
  1. `.vscodeignore` 增加 `release/**`（可选：`*.zip`）——一行修复；
  2. 评估 esbuild/webpack 打包（vsce 官方建议），可显著缩小体积、加快激活；
  3. `node_modules` 可进一步瘦身（仅保留运行必需文件）。

### 1.2 测试汇总器"永久 FAIL=1"掩盖真实失败

- **证据**：`tests/test-writer.js:9` 是**需要 `<cbp>` 参数的辅助脚本**（无参数时 `console.log('用法: …')` 后 `exit(1)`），`tests/run-all.js` 无差别执行 `test-*.js` → 每次全量回归固定 `TOTAL=105 FAIL=1`。历次记录均以"仅 test-writer.js 预期失败"备注（`docs/开发进度.md:287`、各 `docs/release/*.md`）。
- **风险**：一旦将来新增真实失败，报告仍显示 `FAIL=1`，噪音与真实信号混淆；且 `package.json` **没有 `test` 脚本**（只有 `pretest`），`npm test` 实际不可用（`scripts` 仅 compile/watch/package/pretest）。
- **建议**：
  1. `run-all.js` 增加 `KNOWN_MANUAL = ['test-writer.js']` 跳过清单（或按"无参数可自检"改造：缺参时自动使用 `test-project/hello-cb.cbp` 走 parse→serialize→reparse 往返）；
  2. `package.json` 增加 `"test": "node tests/run-all.js"`，让 `npm test` 可用。

### 1.3 四个日志/行为设置首次读取后缓存，运行中修改不生效

- **证据**：`src/build/logLang.ts:12-32` `buildLogPrefs()` 把 `build.plainCbLog`、`log.english`、`build.strictQuoting`、`ui.quietSuccess` 读入**模块级 cache**（`let cache`），全文件无清空/失效导出；`src/extension.ts` 的多个 `onDidChangeConfiguration`（:150/:360/:372/:1413/:1423）均未触碰该缓存。
- **影响**：用户在会话内修改这 4 个设置（含"构建日志英文/纯 CB 模式/严格引号/成功静默"）不生效，须重载窗口；与其余设置"实时读取"的体验不一致（例如 `ui.buildLogAutoFocus`/`quietFailure` 是实时的）。
- **建议**：`logLang.ts` 导出 `resetBuildLogPrefsCache()`，在配置变更监听中对 `codeblocks.build.plainCbLog` 等四个键调用；或改为每次读取（读取开销极小）。

## 2. 中优先级发现

### 2.1 makefile 项目的 `askRebuildNeeded` 同步阻塞且无超时

- **证据**：`src/extension.ts:4934` `spawnSync(askCmd, { cwd, shell: true, windowsHide: true, encoding: 'utf8' })`——无 `timeout` 参数、同步执行。而后续正式构建 `runMakeBuild()`（:5864）是异步 + 取消句柄注册（`BuildCancelSource`）。
- **风险**：make 命令若挂起（等待输入、文件锁、网络盘、超大工程依赖检查），**扩展宿主主线程被无限期阻塞**（整个窗口无响应），且"停止构建"命令无法中断该同步调用。
- **建议**：改为异步 `spawn` + 超时（如 10–30s）+ 注册到 `currentBuildCancel`，与 `runMakeBuild` 语义对齐（超时按"未命中最新"继续正常构建）。

### 2.2 `getCompiler()` 每次调用可能重复同步执行 `<gcc> --version`

- **证据**：`src/extension.ts:3934` `getCompiler()` 每次构造新的 `Compiler` 实例；`:3986-3988` 当 `supportsPCH`（`resources/compilers/options_gcc.xml:37` = true）且实例无 `versionString` 时执行 `queryCompilerVersionString()` → `spawnSync(exe, ['--version'], { timeout: 8000 })`（:3925）。
- **影响**：构建/运行/清理路径上 `getCompiler()` 有多处调用（:4828/:4894/:4947/:5845…），每次都可能同步 spawn 一次（典型 30–100ms；异常环境最高 8s）。属可感知的固定开销。
- **建议**：模块级 `Map<string, string|undefined>`（key = 解析后的 exe 路径）缓存版本号，或在 `getCompiler` 外层缓存 Compiler 实例；`userPrograms` 早退分支（:3968）同样接入（当前该分支不查询版本，行为上与 CB 默认 4 的回退一致，可保持不变）。

### 2.3 快捷键面板 WebView 无 CSP，且启用 `retainContextWhenHidden`

- **证据**：`src/ui/keybindingPanel.ts:46` `{ enableScripts: true, retainContextWhenHidden: true }`；面板 HTML 未见 `<meta http-equiv="Content-Security-Policy">`（对比：`src/ui/projectPropertiesPanel.ts:411`、`src/ui/compilerOptionsPanel.ts:78` 均已配置 CSP）；面板内多处 `innerHTML` 拼装设置/命令数据（:230/:250/:277）。
- **影响**：安全基线不一致（VS Code WebView 最佳实践要求 CSP）；`retainContextWhenHidden` 常驻内存为已知代价。风险等级低（本地数据自产自用），但属一致性/健壮性问题。
- **建议**：与另两个面板统一补 CSP；评估移除 `retainContextWhenHidden`（或仅保留到首次渲染）。

### 2.4 AStyle 格式化同步阻塞主线程

- **证据**：`src/tools/astyle.ts:34` `spawnSync(astyle, options, { input: source, encoding: 'utf8' })` 对整篇文档文本同步执行。
- **影响**：大文件（数万行）格式化可秒级阻塞窗口。
- **建议**：异步化（`execFile` + Promise），失败回退 VS Code 内置格式化的既有逻辑不变。

### 2.5 无 CI / Lint 门禁

- **证据**：仓库无 `.github/`（无 workflow）、无 ESLint/Prettier 配置（`.eslintrc*` / `eslint.config.mjs` / `.prettierrc` 均不存在）；`tsc` 依赖人工执行；vsce 打包告警（见 1.1）无人自动捕获。
- **建议**：引入最小 GitHub Actions：`npm ci` → `npm run compile` → `node tests/run-all.js`（含 headless 可选）→ `vsce package --no-dependencies` 冒烟；Lint 可后置（先保证类型与回归）。
