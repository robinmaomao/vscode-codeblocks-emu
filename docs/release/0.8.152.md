# 0.8.152

> 发布日期：2026-11-16 ｜ 体验版（0.8.151 → 0.8.152）
> **主题**：Build options / Properties 第二轮逐项对齐 Code::Blocks（源码级复核 + 人工复核调整）

## 概述

0.8.151 把 `Build options…` / `Properties…` 的版式与启用联动对齐了 CB，本轮再次以 CB 源码为准逐项复核：

- `codeblocks-src/src/src/resources/project_options.xrc` + `projectoptionsdlg.cpp`
- `codeblocks-src/src/plugins/compilergcc/resources/compiler_options.xrc` + `compileroptionsdlg.cpp`
- `codeblocks-src/src/sdk/editpairdlg.cpp`、`globals.cpp`、`resources/select_target.xrc`

共修掉 **11 项功能差异 + 6 项视觉/文案差异**，并在人工复核后追加 3 项调整（Import/Definition 占位符、脚本校验文案、类型改写不再受自动勾选限制）。

## 一、Build options

- **Compiler Flags ↔ Other linker options**（`OptionsToText` / `TextToOptions`）：勾选参数的 `additionalLibs` 以**整串**写入 `Other linker options`（旧实现错写进 Link libraries 且按空格拆分）；载入时按整串反向勾选并从文本隐去；取消勾选而文本仍保留时弹 `Enable compiler flags?`（Yes 保留 / No 移除）。
- **构建脚本提示**：工程或任一目标存在构建脚本时显示 CB 的 `lblBuildScriptsNote` 红字。
- **Linker executable**：只在目标作用域渲染（CB `Show(m_pTarget != nullptr)`），工程作用域整行隐藏；文案与 tooltip 用 CB 原文。
- **Custom variables**：Add/Edit 改为 `EditPairDlg` 式键值对话框（键名 `^[[:alnum:]_]+$` 才可确定、值可浏览目录、含空格询问是否加引号）；删除/清空用 CB 文案确认。
- **覆盖层按钮**：属性面板内的 Build options 覆盖层由单一「关闭」改为 `确定 | 取消`（取消丢弃本次修改，点遮罩等同取消）；独立面板保持 `保存 | 保存并关闭 | 还原设置`。
- **编译器切换**：未保存改动先问「应用改动后再切换？」（是/否/取消）；目标作用域提示建议完整重建；工程作用域询问是否同步到所有目标，再提示需要完整重建。

## 二、Properties

- **目标类型切换**（`OnProjectTypeChanged`）：GUI/Console → `.exe`、Dynamic → `.dll` + `libExtension` + `.def`、Static → `libExtension` + `lib` 前缀、Native → `.sys`，非动态类型清空 Import/Definition。与 CB 一致**不看**「自动生成文件名前缀/扩展名」复选框（生成器对已带扩展名/前缀的名字幂等），含 `$(...)` 宏的文件名同样在末尾追加扩展名。
- **目标命名**（`ValidateTargetName`）：Add / Rename / Duplicate 先询问名称（复制默认 `Copy of <title>`），拒绝空名（=取消）、重名、与虚拟目标同名、含 `; , ! @ # $ % ^ & * " ' ~ = ? \ > <` 或反引号的名称。
- **列表点击**：`collectTargetForm` / `collectVTForm` 不再在 `change` 时重建列表，修复「编辑字段后第一次点击另一个目标无效」。
- **启用联动**：`Selected file properties` 只依赖文件列表有无选中行，自定义 Makefile 下恢复可用；构建脚本 `↑/↓` 改为「有选中且条目数 > 1」才可用。
- **字段展示**：`导入库文件名 / 定义文件文件名` 空值改为灰色占位符提示 `$(TARGET_OUTPUT_DIR)$(TARGET_OUTPUT_BASENAME)`（CB 中为空，占位符不写盘）。
- **构建脚本校验**：按 CB `DoCheckScripts` 三行文案列出全部问题（`Invalid build script:` / `First seen in:` / `Error:`），全部通过显示 `All scripts seem to be valid!`；修好多行结果被挤成一行。
- **视觉/文案**：`工程的依赖… / 工程的构建选项…` 左对齐；目标类型 0 改 `GUI application`；补「执行结束时暂停」tooltip；`对象文件名生成`（2 行）与 `检查外部修改的文件`（3 行）红字按 CB 分行；双击目标行打开该目标的 Build options、双击文件行打开文件属性。

## 五、兼容与边界

- **保留的有意差异**：底部按钮 `保存 | 保存并关闭 | 还原设置`（vs CB `OK / Cancel`）；属性面板固定 6 页签（CB 4 核心页 + 插件页）；非 Console 目标保留 `use_console_runner` 原值（CB 会强制写 false 丢数据，不复刻）；未安装编译器用红字 + 禁用页面（CB 弹选择框）；文件属性省略 `Included files` / glob 行（CB 自身隐藏）；构建脚本校验一次列出全部问题（CB 遇错即停）。
- **数据影响**：类型改写只作用于用户主动切换类型的字段；导入库/定义文件空值不再写入默认宏；脚本校验只读，不执行 Squirrel。
