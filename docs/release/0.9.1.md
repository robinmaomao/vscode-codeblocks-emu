# 0.9.1

> 发布日期：2026-11-19 ｜ 补丁版（0.9.0 → 0.9.1）
> **主题**：clangd 重启路径可靠性修复（合并 0.9.0 后复查发现）

## 概述

0.9.0 把「重启合并器（main）」与「重启判定（Agent）」合到一起后，两层各自正确、组合起来仍有两个可观测问题：
一次慢重启会被下一次请求叠加（再次触发 `command 'clangd.applyFix' already exists`），
以及「日志说在重启、执行层其实静默跳过」。本版只修这条链路，不改其它行为。

## 🛠 修复

- **单飞（P2）**：`createClangdRestartCoalescer` 在一次 `restart` 未结束时不再并发排期，改为**结束后补跑一次**。
  慢重启（等客户端启动最长 20s + 2s 稳定期 + 撞车重试 5s）不会再与下一次执行重叠。
- **跳过留痕（P1）**：执行层在「未安装 clangd 扩展 / 扩展未激活 / 语言客户端已停止」三种情况下各输出一行明确日志，
  不再出现「打印正在重启、实际没有任何动作」的矛盾现象。
- **有限重试（P4）**：客户端迟迟未就绪时按 2s / 4s 重试最多 2 次（`nextClangdRestartRetry`），
  不再静默丢弃一次必要重启；手动重启（`Code::Blocks: Restart clangd`）与扩展停用会清理未到期的重试。
- **文案对齐（P3）**：启动恢复期间「仅配置变化」的跳过日志改为如实描述（不再声称 clangd 仍在启动）。
- **整洁（P5）**：`tools/clangdRestart.ts` 分节注释（合并器 / 状态门 / 重试策略 / 判定真值表）、
  合并重复 import、`restartClangdReason` 复用导出的 `ClangdRestartReason` 类型。
