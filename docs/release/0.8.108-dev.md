# 0.8.108-dev

## 主题：UNC 对象路径卷拆 server/share 两段

## 背景与证据

- 用户确认方案 A。
- CB 侧证据（codeblocks-src）：
  - `wxFileName::SplitVolume` 的 UNC 分支（`volume = from.GetString().Mid(0, posFirstSlash)`）产出**整段共享路径** `\\server\share`；
  - `pfDetails::Update`（projectfile.cpp:474-492）：diffVolume 时 `objOut += fileVol`（GetVolume 结果**不含冒号**）；
  - 同时 diffVolume 分支里 `file.Remove(...)` 去卷写的是 `wxAFTER_FIRST`（含分隔符），两者都是共享路径整段 → 双重拼接 server/share 段的怪路径（`obj\Debug\server\share\server\share\src\f.o`）。
- 结论：完全复刻 CB 会产出不可用的重复段路径；修正为**拆两段**对齐 CB 的 `objOut += fileVol` 意图。

## 代码修改

- `src/build/compiler/*`（BuildEngine）：
  - UNC 绝对路径的卷段拆分：`\\server\share\...` → 对象目录下追加 `server`、`share` 两段（`obj\Debug\server\share\...\f.o`）；
  - 跨卷分支去卷逻辑保持 CB 语义。

## 测试

- `tests/test-cross-volume-object.js`：新增 U1/U2/U3 三条 UNC 命令级断言（对象绝对路径 / 编译 `-o` / 链接对象均含 `server\share` 两段）→ 14 断言全过。
