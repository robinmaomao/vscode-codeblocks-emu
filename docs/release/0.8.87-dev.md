# 0.8.87-dev

> 第四轮编译链接对齐核查 · L2 修复：编译失败「失败即停」策略（对齐 CB OnJobEnd 清队列语义）。

## 背景

第四轮核查发现 L2（高价值）：Code::Blocks 在任一编译命令失败时清空命令队列、停止派发后续命令
（`compilergcc.cpp:4005-4017`：`m_CommandQueue.Clear()` + `ResetBuildState()` + 清空
`m_BuildJobTargetsList`），仅已在跑的并行任务自然结束；本扩展此前会继续编译完剩余全部单元再汇总失败。

## 修复内容

- **`src/build/buildEngine.ts`**：
  - `runInParallel` 新增失败即停短路——任一单元失败后不再派发新单元
    （PCH 子组第二调用、后续 weight 组、`deferredUnits` 批次均检查），in-flight 任务自然完成；
  - `results` 初值由 `false` 改为 `undefined`：未派发单元不计入 `failedCount`；
  - `compiledCount` 改按实际编译成功数统计（未派发单元不计）；
  - 失败时输出「剩余 N 个单元未派发（失败即停，对齐 CB 清队列）」提示行；
  - 取消（cancel）≠ 失败语义保持不变。

## 验证

- 真实 MinGW gcc 8.1 串行实测（parallelJobs=1）：`✗ [Failed] 1-3 bad.c` 后不再出现后续 `[Compiled]`；
  统计 `{compiledCount:0, failedCount:1}`；未尝试链接。
- 新增 `tests/test-fail-fast.js`（14 断言）：串行首错停止、跨 weight 组停止（前组成功→中组失败→后组不派发）、
  全部成功回归（计数/链接不受影响）。
- tsc 0 错；全量 83 测试仅 `test-writer.js` 预期失败；headless 真机构建 `EXIT 0`。
