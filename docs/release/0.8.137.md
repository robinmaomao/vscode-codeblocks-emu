# 0.8.137

> 发布日期：2026-11-04 ｜ 正式版（0.8.136 → 0.8.137 里程碑汇总）
> **主题**：外部修改检测 · 编译输出编码 · 面板可用性
> 设置项与命令见 [使用说明](../guide/usage.md) §5.1 / §13；测试结果见 [测试报告-0.8.137.md](../testing/test-report-0.8.142.md)；
> 对齐依据见 [对齐对照.md](../guide/alignment.md)。

本版把三处「Code::Blocks 有、扩展没有或不工作」的地方补齐：

1. **`.cbp` 被外部程序修改**时不再沉默（对齐 CB 的 `CheckForExternallyModifiedProjects`）；
2. **编译输出乱码**按完整行逐行判定编码（中文 Windows 下 GCC 的 GBK 路径 + UTF-8 源码摘录混排也能正确显示）；
3. **工程属性面板**（保存静默失效 / 窄面板按钮竖排 / 英文界面脚本失效）与**编译选项面板**（应用不落盘）修复。

## 1. `.cbp` 外部修改检测

**现象**：在外部编辑器改 `.cbp` 后，扩展不检测也不更新；而 Code::Blocks 打开中的工程被其它程序改过会弹窗询问是否 reload。

**根因**：`cbpWatcher` 只订阅 `onDidCreate` / `onDidDelete`，没有 `onDidChange`；`openProject` 对已打开工程直接 return；
也没有 CB 的「应用激活时比较 mtime」这条兜底。

**实现**：

- 新增设置 `codeblocks.detect.checkExternalChanges`：`prompt`（默认，弹窗「重新加载 / 忽略 / 不再提示」）/ `auto`（直接重载 + 状态栏提示）/ `off`；
- 新增命令 `codeblocks.reloadProject`（`Code::Blocks: 从磁盘重新加载工程`，工程树右键 / Menu → Project）；
- 监听 `.cbp` 的 create / change / delete（含"原子保存：先写临时文件再替换"与"文件仍在的 delete"），并窗口重新获得焦点时兜底比较 mtime+size；
- 扩展自身写盘前刷新基准（`projectChangeTracker.remember`），自写盘不弹窗；XML 损坏时保留旧模型且不反复报错；
- 「忽略」等价 CB 的 `cbProject::Touch`（更新基准，同一内容不重复弹）；重载后保留活动工程与选中目标（含虚拟目标）。

## 2. 编译输出编码治理

**现象**：中文 Windows 下构建日志出现 `����`、汉字被拆成错字。

**根因（实测）**：同一条 GCC stderr 里**路径按 GBK、源码摘录按 UTF-8**；旧实现用「首块/首行」决定整条命令的编码，
按数据块独立解码又会把跨块的多字节字符拆开。

**实现**：`src/tools/encoding.ts` 新增 `decodeOutputLines` / `OutputLineDecoder`（整段 UTF-8 快路径 + 按完整行逐行判定 + 跨块残行保留），
覆盖主构建、pre/post 脚本（stdout/stderr 各一个解码器）、Makefile 构建、自定义工具输出、GDB 调试输出；
工具侧输出捕获（探测 / 版本 / 反引号 / 8.3 短路径 / clangd）统一改 buffer + `decodeText`；
超长命令的响应文件按系统 ANSI 代码页写出（`iconv-lite`，含中文路径 GCC 可读）；`.cbp` / `.workspace` 读取与原文回写保留原编码。

## 3. 工程属性面板与同类配置页

**现象 1**：点「保存」没有任何反应。

**根因**：`doSave()` 无条件收集 9 个 tab 的表单，而文件 / 构建选项 / 搜索目录 / 脚本 / 设置 / 备注 / 虚拟目标表单**只在切到对应 tab 时才渲染**；
未访问过的 tab 元素为 `null` ⇒ `collectFileForm` 抛 `TypeError` ⇒ 保存中断且无提示。

**现象 2**：窄面板里按钮变成竖排单字。

**根因**：`.list-actions` 无 `flex-wrap`、`button` 无 `white-space: nowrap`、`.layout` 用 `240px 1fr`（表单列不能收缩）。

**现象 3**：英文界面下整个面板不工作（tab/按钮全失效）。

**根因**：英文译文 `compiler's` / `CB's` 的撇号截断了内联脚本里的 `'…'` 字符串 ⇒ `<script>` 整段语法错误。

**实现**：

- `doSave` 加 `try/catch`（异常写顶栏状态区，悬停看全文）；9 个收集函数都加元素存在性守卫；
  目标被删除后目标级 tab 的作用域索引失效时跳过收集；目标改名/删除同步 `remote_debugging`（标题索引，避免孤儿节点）；
- CSS：`button{white-space:nowrap}`、`.list-actions{flex-wrap:wrap}`、`.toolbar{flex-wrap:wrap}`、`.layout{minmax(200px,240px) minmax(0,1fr)}`，`<720px` 时列表与表单上下堆叠；
- 修正两条英文词条，并新增「中英两态内联脚本必须可编译」的守卫用例；
- **编译选项面板**：「应用」此前只改内存模型（重开工程即丢），改为经宿主 `persistProjectAndReload` **立即写回 `.cbp`** 并重绑重解析后的工程/目标；
  只管理 `options_<id>.xml` 内的选项（手写自定义选项如 `-pipe` 原样保留）；应用时目标已被外部改名/删除则报错（不写盘、不改内存）；
  连点「应用」经 promise 队列串行落盘；快捷键面板与编译选项面板同步补 `nowrap` / `flex-wrap`。

## 兼容性 / 行为边界

- 不改编译、链接、清理、调试流程与命令行生成；不写工作区 `.vscode/settings.json`；
- `.cbp` / `.workspace` 读写保留原编码（旧 ANSI 工程不会被静默转成 UTF-8）；
- 外部修改检测只作用于**已打开工程**的 `.cbp`；`.workspace` 的外部修改检测未实现（见 [未实现功能待办](../dev/backlog.md)）；
- 编译选项「应用」语义与 CB 略有差异：CB 是"改内存 + 保存工程"，本扩展无工程"已修改"状态，故直接落盘。

## 已知限制

- `Compile File (Without Project)` 走 VS Code 任务终端（固定 UTF-8），编译器若输出 GBK 中文仍会乱码（见使用说明 §16）；
- `.workspace` 被外部修改后不会提示重载（仅 `.cbp`）。
