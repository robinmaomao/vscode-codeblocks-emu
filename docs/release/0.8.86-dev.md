# 0.8.86-dev

> 第四轮编译链接对齐核查 · L1 修复：PCH 头文件 include 前置缺失（`-iquote`/`-I`/`-I.`）。

## 背景

第四轮核查发现 L1（高价值）：PCH 头文件虽被编译为 `.gch`，但编译其它源文件时 include 串缺少
`-iquote <对象目录> -I <对象目录> -I.` 前置，导致 gcc 在 `#include "header.h"` 时优先命中源目录的 `.h`
而非 `.gch` —— **PCH 实际从未生效**，与 Code::Blocks 同工程行为不一致。

## 修复内容（对齐 `compilerMINGWgenerator.cpp:34-95`）

- **`src/compiler/compiler.ts`**：`Compiler` 接口新增 `versionString` 字段（对齐 `Compiler::m_VersionString`）。
- **`src/compiler/commandGenerator.ts`**：`setupIncludeDirs` 新增 `pchIncludePrepend()`：
  - 仅 GCC 家族（`supportsPCH`）+ `pchMode === 1`（pchObjectDir 默认）+ 存在 `compile=true` 头文件时生效；
  - 逐目录去重后前置：gcc≥4 → `-iquote<目录> `，gcc<4 → `-I<目录> -I- `；
  - 第二循环对同批目录各补一条 `-I<目录> `；末尾固定 `-I. `；
  - `UseFlatObjects=true` 时目录取扁平对象目录（对齐 `fn.GetFullName()`）。
- **`src/extension.ts`**：`getCompiler` 在 `supportsPCH` 且无 `versionString` 时惰性执行
  `<C程序> --version` 取主版本号（对齐 `CompilerMINGW::SetVersionString`，compilerMINGW.cpp:240-318）。

## 验证

- 真实 MinGW g++ 8.1 实测：补上前置后 `gcc -H` 输出 `! obj/Debug/include/guard.h.gch`（PCH 生效）；
  修复前为 `. include/guard.h`（未用 PCH）。
- 新增 `tests/test-pch-quote.js`（16 断言：三模式 gating、gcc≥4/gcc<4、无版本默认、supportsPCH=false、
  UseFlatObjects、无 compile 头文件）。
- tsc 0 错；全量 82 测试仅 `test-writer.js` 预期失败；headless 真机构建 `EXIT 0`。
