# 0.8.140：构建性能归因告警改为可选（默认关闭）

> 发布日期：2026-11-05 ｜ 正式版（0.8.139 → 0.8.140）
> 测试结果见 [测试报告](../testing/test-report-0.8.140.md)（滚动更新）；
> 对齐依据见 [对齐对照.md](../guide/alignment.md)。

本版把构建结束的五类「性能归因告警」收进一个新设置 `codeblocks.build.performanceAdvisor`（**默认关闭**），
普通构建不再刷屏；诊断模式（`build.profile` / `build.sampleSystem`）下仍然自动输出。

## 1. 现象

0.8.135 引入的宿主卡顿判定在正常构建上也会触发，一次典型输出：

```text
⚠️ [Code::Blocks] The extension host was stalled for 59% of this build (longest single stall 975 ms). ...
⚠️ Suggestions: close memory-hungry applications / add RAM, ...
⚠️ CPU saturation is a cause too, not a symptom: 8 parallel compiler jobs on 8 logical CPUs (4 physical cores) ...
⚠️ Host stalls did not throttle this build: workers waited only 11 ms in total between units (57 units), ...
```

## 2. 根因

- 卡顿占比来自 `startHostLagSampler()` 的 **100 ms `setInterval` 实际漂移**：`lag = now - last - period`。
- 8 路编译器跑满 4 物理核 / 8 逻辑核时，扩展宿主**自己也被调度出去**，定时器回调被推迟几十~上百毫秒；
  累加后占比被显著放大（本例 59%），但同一轮 `dispatch wait` 只有 **11 ms**（57 个单元），
  说明构建几乎没有等待宿主——四行告警自相矛盾。
- 判定门槛只有三个数值（构建 ≥5 s、占比 ≥20%、单次 ≥500 ms），且**与任何设置无关**：
  `emitBuildProfile()` 在 `if (!prof) return;` 之前就无条件调用了五个 `report*` 方法。

## 3. 修复

新增设置 **`codeblocks.build.performanceAdvisor`**（boolean，默认 `false`），统一门控：

| 方法 | 输出内容 |
|------|----------|
| `reportHostStalls` | 宿主卡顿占比 + 建议 + `dispatch wait` 两分支判定 |
| `reportSecurityCpu` | 第三方实时防护 CPU 归因（≥10%） |
| `reportWatcherStorm` | VS Code 文件扫描器（`rg` + `conhost`，≥8%） |
| `reportMeasuredSaturation` | 整机 CPU 饱和归因（≥85%） |
| `reportSystemHeadroom` | 构建开始时的低内存检查（可用 <15%） |

开启条件的实现（`adviceEnabled()`）：

```ts
private adviceEnabled(): boolean {
  if (this.prof !== undefined) return true;          // build.profile 开启 = 诊断模式
  try {
    const cfg = this.scopeConfig();
    return cfg.get<boolean>('build.performanceAdvisor', false) === true
      || cfg.get<boolean>('build.sampleSystem', false) === true;
  } catch {
    return false;
  }
}
```

因此：默认安静；打开 `build.profile` 或 `build.sampleSystem` 无需额外设置即可看到全部归因；
也可以只开 `performanceAdvisor` 而不要计时块。

## 4. 兼容与边界

- **不改变**：`[profile]` 计时块、`build.traceProcesses` 的子进程统计行、`build.sampleSystem` 的
  系统 CPU 汇总块、`plainCb` 纯日志模式、并行编译与增量判定流程。
- 采样本身照旧执行（`startHostLagSampler` / `startSystemSampler`），只是告警输出被门控；
  `[profile]` 里的 `host stalled ratio` 等条目不受影响。
- **默认行为变化**：0.8.139 及更早版本在超阈值时必打印，本版默认不打印——这正是本版的目的。
- 设置作用域沿用同族 `build.*`（未声明 `scope`，可在文件夹级覆盖）；每次构建读取一次，修改即时生效。

## 5. 验证

| 层 | 结果 |
|----|------|
| 契约 | 3/3 脚本（契约 44 + 文档一致性 6 + 设置契约 665 断言）；设置项计数 82 → **83**，4 张设置表与双语 nls 全覆盖 |
| 单元 | `TOTAL=177 FAIL=0 SKIP=1`（新增 `test-build-performance-advisor.js` 31 断言） |
| E2E | 5/5 脚本，288 pass / 0 fail / 8 skip |
| 视觉 | 24/24（严格判定，基线未刷新） |
| 性能 | 13 项，13 pass / 0 warn / 0 fail |
| 打包 | 14 断言通过；VSIX 0.8.140（654.8 KB）打包 / 安装冒烟通过 |
| 宿主 | 24/24（真实 VS Code 1.85.0） |

人工确认项：

1. 默认（`performanceAdvisor=false`）构建不再出现上述四行 ⚠️；
2. `codeblocks.build.profile=true` 时四行恢复，且 `[profile]` 块正常；
3. 仅 `codeblocks.build.sampleSystem=true` 时归因告警与系统 CPU 汇总都出现。
