# 0.8.121-dev

> 无效编译器构建日志对齐（用户确认：P1 完整消息结构（文案扩展适配）+ P2-B 单遍结构记录 + P3-B 收尾行 + Run 分支 `Run aborted...`）。
> 依据：同一工程（编译器 ID 未注册）Rebuild 时，扩展日志比 Code::Blocks 少的逐行取证
> （`codeblocks-src` 引用为仓库内源码）。

## 背景：原日志比 CB 少的三处差异（取证结论）

1. **消息正文截断** —— CB `PrintInvalidCompiler`（`compilergcc.cpp:1756-1786`）输出完整 5 行 + 末尾空行；
   扩展此前只复刻 2 行，且把编译器 ID 拼进括号（CB 未注册时留空）。
2. **块次数** —— CB Rebuild 默认 `/rebuild_seperately=false`（`:2948-2958`）分两遍执行（clean 遍 + build 遍），
   每遍 `PreprocessJob` 各报一次 → 2 块；扩展单项目 Rebuild 为单遍执行 → 1 块。
3. **收尾** —— CB 任务列表为空 → `NotifyJobDone`（`:4123-4140`，第一遍被 `m_LastBuildStep` 抑制）第二遍输出
   `Nothing to be done (all items are up-to-date).`；扩展此前无该行（输出失败行/汇总）。

## P1：对齐 PrintInvalidCompiler 结构（文案扩展适配）

- 共享纯模块 `src/build/invalidCompiler.ts`（`isCompilerUsable` / `triedCompilerPaths` / `renderInvalidCompilerMessage` / `renderTriedCompilerPaths`），
  构建与运行入口共用；`buildEngine.reportInvalidCompiler` 三条独立错误条目（对齐 CB 三次 `LogError`）：
  - 主消息 5 行 + 末尾换行（与下一条之间空行）；`Skipping...` 为独立错误条目；
  - **文案扩展适配**（用户追加要求）：产品名 `Code::Blocks for VS Code`；修复指引改为扩展入口
    `Check "codeblocks.masterPath" / "codeblocks.compilerPrograms" settings, or run "Code::Blocks: Detect Compilers" to fix the compiler's setup.`
    （CB 原文指向其 Settings 对话框，VS Code 无对应 UI）；空名双空格修正为单空格；
  - 名称显示：已注册但 `IsValid` 失败 → `(名称)`；未注册 → 括号内显示其 ID（如 `(my-compiler)`）；
  - 已注册对象追加 `Tried to run compiler executable '…', but failed!` 尝试路径（对齐 `MakeInvalidCompilerMessages:234-259`；
    **保护性修正**：CB 原函数循环缺陷漏印 masterPath 根目录与最后一个 extra_path，扩展按 `IsValid` 检查顺序完整列出）。

## P2-B：单遍 Rebuild 仅报 1 次（保护性差异，已入对齐对照）

- CB Rebuild 两遍 = 报 2 次；扩展单项目 Rebuild 维持单遍执行（`cleanTarget` + 强制全编译）→ 只报 1 次。

## P3-B：收尾行 + 保留失败行（保护性差异）

- 全目标被无效编译器跳过后补输出 `Nothing to be done (all items are up-to-date).`（对齐 `NotifyJobDone`）；
- 随后照常输出扩展失败行/汇总（CB 日志无失败字样、内部同样按失败返回）——便于 VS Code 端明确失败原因。

## Run 分支：运行前编译器校验（对齐 Run aborted...）

- `run()` 解析目标后、启动程序前检查（对齐 `Run():1963-1986`）：非 CommandsOnly / 非 `null` 编译器目标需
  `resolveTargetCompiler` + `isCompilerUsable`；无效 → 完整消息（共享模块渲染，文案同款扩展适配）+ `Run aborted...`（:1981）并中止；
- 例外与顺序对齐 CB：CommandsOnly / `null` 不检查；编译器检查先于 exe 存在性检查；
- 保护性差异：输出通道自动 `show(true)`（确保报错可见）、无 toast（对齐 CB 日志行为）；
- 消息渲染与可用性检查从 BuildEngine 提取为纯模块 `src/build/invalidCompiler.ts`（构建与运行共用，行为不变）。
