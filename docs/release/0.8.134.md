# 0.8.134：构建并发/CPU 守卫 · clangd 与 ccache 缺陷修复

> 发布日期：2026-10-27 ｜ 正式版（0.8.133 → 0.8.134 里程碑汇总）
> 逐条对齐依据见 [对齐对照](../对齐对照.md)；clangd 配置约定见 [使用说明](../使用说明.md) §9。

## 概述

本版集中处理两类问题：

1. **构建期 CPU 打满** —— 并行编译默认值、逐行解析开销、构建期 clangd 重索引叠加；
2. **clangd / ccache 集成静默失效** —— 探测路径、引号参数、配置改写、扩展安装时机、原子写与诊断来源。

默认行为变化只有一处：`codeblocks.parallelJobs` 默认值 `0`（自动 = 逻辑核数 × 2）→ **`8`**；需要旧行为可显式设回 `0`。

## 一、构建并发与 CPU 守卫

- **并行编译默认 8**：`codeblocks.parallelJobs` 默认 `0` → `8`，新增 `scope: resource`（支持文件夹级覆盖）；`0` 仍保留「自动（逻辑核数 × 2，上限 32）」，`1` = 串行。默认值收敛到 8，给编辑器/其它扩展留出余量（并发越高全量构建越快，但 CPU 越接近 100%，且每条编译进程链常驻几十至几百 MB）。
- **取值容错**：数值字符串（如 `"12"`）按数字解析；`null` / 布尔 / 其它类型回退默认值（避免 `Number(null) = 0` 被误当成「自动」）。
- **构建期不重启 clangd**：构建进行中触发编译数据库重建（切换活动工程 / 改编译器）时只登记，构建结束 `finally` 再 `clangd.restart`，避免整库重索引与编译进程抢 CPU（`pendingClangdRestart` + 各构建入口统一 flush）。
- **每行输出只解析一次**：严重级别 / Diagnostic / 文件 URI / 结构化上报共用同一份 `parseLine` 结果（此前最多 4 次，正则是大量输出时宿主 CPU 的主要来源）；`OutputParser` 增加「无 `:` 行」快路径（命令行回显/进度行直接返回）。
- **子进程隐藏窗口**：编译 `cmd.exe` 派生统一 `windowsHide`，省去窗口创建/销毁开销。
- **设置快照按轮刷新**：整目标构建与单文件编译都在入口重置 `cfgSnapshot`，构建中改设置从下一轮生效（不再半途换值）。
- **ccache 前缀记忆化**：`$compiler` 展开点的编译缓存前缀按生成器实例缓存（千文件工程省约 2000 次配置查找）；解析缓存命中只做一次 `stat`，路径失效才重扫；仅在「未找到」时清空解析缓存（保住「运行中安装下一构建即生效」，又不再每构建全盘扫描）。

## 二、clangd 集成修复

- **不再改写用户配置**：清理失效片段时只合并**连续**的 `---`（删片段留下的空文档），用户自有的 `---` 分隔符保留 —— 旧实现「前一行是空行就删」会把两篇文档合并、丢失 `If` 条件，甚至因重复键让 clangd 丢弃整个 `config.yaml`。
- **编译命令逐字保留**：`compile_commands.json` 的 clang 兼容化改为「保留 token 原文」，`-DAPP_NAME="My App"` / `-DVERSION_STR="1.2.3"` / `-I"C:/Program Files/sdk"` 不再被拆成两个参数（此前宏值丢失，字符串还被当成输入文件）。
- **masterPath 参与探测**：裸程序名（`gcc.exe`）先解析为 `<masterPath>/bin/<program>`（兼容 masterPath 直接指向 bin）再查系统头 / `-dumpmachine`；宿主 PATH 未含工具链时 clangd 不再缺 `-isystem` / `--target`。`--query-driver` 建议值同步修正（此前 `dirname('gcc.exe')` = `.`，推荐 `./*` 无效）。
- **检测时效**：负结果 TTL 5 分钟 → 30 秒；手动「生成 compile_commands.json」先清探测缓存；监听 `vscode.extensions.onDidChange`，clangd 扩展安装/启用/卸载/禁用时重新探测并按需重建（`clangdDiagnosticsEnabled` 不再过期）。
- **安装目录覆盖**：clangd 扩展下载目录不再硬编码 `%APPDATA%\Code`，覆盖 Code / Code - Insiders / VSCodium / Cursor 与 `.vscode-server` 等远程 server 布局；`clangd.path` 必须是文件（配置成目录不再误判）。
- **重建收敛**：`buildLogDiagnostics` / `restartOnActiveProjectSwitch` / `queryDriver` 只影响展示与提示，不再触发全量重建；`clangd.enabled = false` 时不再生成（关闭已有 G4 提示）。
- **原子写**：用户级 `config.yaml` 与 `compile_commands.json` 改为「临时文件 + 重命名」，clangd 文件监听不会读到半截内容。
- **诊断来源**：Build Log 的 `clangd` 模式只取 `source` 为 `clang` / `clang-tidy` / `clangd` 的诊断（排除 cpptools、其它 linter 与本扩展的 `Code::Blocks` 构建诊断）；该文件没有 clangd 诊断时保留全部，避免面板变空。

## 三、编译缓存（ccache / sccache）修复

- **POSIX 可执行位**：非 Windows 上校验 `X_OK`，同名普通文件不再被当成工具（改为「未找到」并回退原编译器）。
- **`.cmd` / `.bat` 版本探测**：Scoop shim 等经 `cmd.exe` 执行（`execFile` 直接启动会 ENOENT/EINVAL），版本号不再显示「未知」。
- **提示标记**：修改编译缓存设置时一并重置「未检测到」标记（与注释/文档一致）。
- **解析缓存**：命中时校验路径仍存在（工具被卸载/移动自动重扫）。
