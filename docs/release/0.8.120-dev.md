## R1 并行度默认值：`min(逻辑核数 × 2, 64)`（全量 rebuild 实测 -45%）

- `buildEngine.maxJobs()`：`parallelJobs=0`（自动）由「核数」改为 `min(逻辑核数 × 2, 64)`；
- 依据：编译单元墙钟远大于其 CPU 占用（gcc→cc1→as 进程链 + Windows 杀软扫描停顿），
  按核数并行只能填满线程、大量停顿被浪费；2× 超额订阅把停顿重叠——
  实测全量 rebuild：8 并发 68.6–77.2s → 16 并发 38.5–43.4s，24 并发回退（~52s，开始争抢）；
- 显式设置值仍优先（含 1 = 串行），可一键回退；上限 64 与设置范围上限一致
  （注意：每个编译进程链常驻几十至几百 MB，内存敏感环境请显式降低）；
- 同步更新：`package.json` 描述、使用说明 §13.2 行、README 行、对齐对照新增
  「并行任务数默认值」保护性差异行（CB 依据：`cbthreadpool.cpp:32-39` 线程数 ≤0 → `wxThread::GetCPUCount()`）。

## R2 环境准备后台刷新（90–196ms → ~1ms）

- `src/tools/windowsPath.ts` 改为 stale-while-revalidate：首次调用同步读取（保持既有语义），
  其后立即返回缓存 + 过期（TTL 5s）**后台 `execFile` 异步刷新**；失败保留旧值、下周期重试；
- 效果：第二次构建起「环境准备」≈1ms（原每次构建 ~90–196ms 同步 `reg.exe` 阻塞）；
  增量构建约省 2–3%（rebuild 约 0.3%）。
