# 0.8.39-dev —— 命令模板回退与 Clean 无效编译器（第十七轮 E1-E3）

以 `Compiler::GetCommand`、`GetProjectFilesSortedByWeight`、`GetTargetCleanCommands`、
`CompileFileWithoutProject` 为基线取证，发现并修复 3 项。

## E1 命令模板选择三态对齐

- CB：`Compiler::GetCommand`（compiler.cpp:306-332）——`catchAll` 初值 **0**：扩展名为空
  （链接/打包命令）直接返回 `vec[0]`（首条，无论其是否声明扩展名）；扩展名精确匹配返回该条；
  不匹配返回**最后一条**空扩展名条目；无空扩展名条目时仍返回 `vec[0]`。
- 原状：catchAll 初值为空串，链接命令会错选最后一条通配模板、无通配时返回空。
- 实现：`getCommandTemplate` 重写为同三态逻辑。

## E2 文档补记

  compilergcc.cpp:3174-3191；扩展的 Build File 仅限项目内文件）。

## E3 Clean 对无效编译器目标

- CB：`GetTargetCleanCommands:965-978`——`GetCompiler(target id)` 为 null 时对象文件不清理，
  输出文件仍在 981-988 无条件删除；`PrintBanner:1788` CompilerValid 早退不打 Clean banner。
- 实现：`cleanTarget` 对目标编译器做 B4 同款有效性检查——无效则 debug 跳过对象清理、
  不打 Clean banner、输出文件（含 .exe 变体与 import 库）照删。
