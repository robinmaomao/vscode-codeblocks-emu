# 0.8.143-agent-control

> 发布日期：2026-11-06 ｜ 分支预发布版（`feat/agent-control` 专用，**不合并 main**）
> **主题**：Agent 全控制（LM Tools + MCP + CLI）+ 总闸 / 只读开关
> 测试结果见 [测试报告](../testing/test-report-0.8.143-agent-control.md)（滚动更新）；使用说明见 [Agent 控制](../guide/agent-control.md)。

版本号带 `-agent-control` 后缀：这是功能分支构建（上游正式版为 `0.8.142`），安装前请与正式版区分；
`cb-cli` 与扩展一起随包提供，但**不受扩展设置开关影响**。

## 概述

- **能力**：Copilot agent（Language Model Tools）/ 任意 MCP 客户端 / CI（`cb-cli`）可完整控制 Code::Blocks 工程：
  读取与增量修改 `.cbp`/`.workspace`、构建 / 重建 / 清理、运行、调试、导出、编译器探测，共 **11 个工具**，
  三端共用同一份实现（`src/api/toolRegistry.ts`）。
- **架构**：控制内核 `src/api/*`（无顶层 vscode 依赖）+ 构建内核 `src/build/buildProject.ts`（与 UI 同源）。
- **开关（本版新增）**：`codeblocks.agent.enabled`（默认开）、`codeblocks.agent.readOnly`（默认关），
  未受信任工作区强制关闭，切换即时生效。
- **规模**：设置项 83 → **85**（新增第 10 分区 `Agent`）；命令数不变（111）。

## ✨ 三条传输

| 传输 | 入口 | 说明 |
|---|---|---|
| Language Model Tools | `contributes.languageModelTools`（11） | 扩展进程内，Copilot 直接调用 |
| MCP server | `contributes.mcpServerDefinitionProviders` → `bundle/cb-mcp.js` | `process.execPath` 启动，stdio |
| CLI | `bundle/cb-cli.js` | 不启动 VS Code，`--json` 输出 + 稳定退出码 |

## 🔒 开关与安全

- `codeblocks.agent.enabled=false`：LM Tools 不注册（调用报未知工具）、内嵌 MCP 返回空定义，
  外部客户端直启的 server 也拒绝调用（`disabled`）；**未受信任工作区一律按关闭处理**。
- `codeblocks.agent.readOnly=true`：仅放行 `project_read` / `build_status` / `compiler list,info` /
  `workspace info,deps,list` / `debug state`，其余返回 `read-only`（工程文件字节不变）。
- 其他既有护栏：字段白名单、`dryRun`、`allowScripts` 门控、`build-busy`、写盘签名（`external-modified` + `force`）、
  每次工具调用一行审计日志。
- 已知表现：工具**调用**即时受控；VS Code 的工具**列表快照**（Configure Tools / `vscode.lm.tools`）可能滞后到下次窗口重载。

## 🐞 本版修复（reload 后的 clangd 噪音）

窗口重载（reload）后恢复多个工程时，clangd 相关输出会随工程数翻倍，并偶发
`command 'clangd.applyFix' already exists` → “couldn't create connection to server” 弹窗。

- **重复生成**：启动恢复 / 多选打开被 `withClangdBatch` 合并为一次 clangd 生成（编译数据库写入、`config.yaml`
  写入、重启各一次），不再每个工程跑一遍；`Project opened` 日志追加 `Project file: <路径>`，同名工程
  （例如两个 `app.cbp`）可直接区分。
- **弹窗根因**：启动恢复期间的生成会调用 `clangd.restart`，而 clangd 客户端刚随窗口启动、仍在 `initialize`；
  该命令实现为「dispose 未完成即新建 client」，于是命令重复注册、连接失败。
- **修复**：启动恢复期间若**编译数据库未变、仅 clangd 配置变化**则**跳过重启**（配置改动 clangd 即时生效），
  并在输出通道留一行「仍在启动中，跳过重启」的说明；数据库变化仍照常重启。判定抽成纯函数
  [`src/tools/clangdRestart.ts`](../../src/tools/clangdRestart.ts)，真值表见
  [`tests/test-clangd-restart-decision.js`](../../tests/test-clangd-restart-decision.js)（16 断言）。

## ⚠️ 行为变化与升级提示

- `engines.vscode` 为 `^1.102.0`：低于 1.102 无法安装本扩展（稳定版 LM Tools / MCP provider 的前提）。
- 默认行为与 `0.8.142` 一致（开关默认开启、只读默认关闭）。
- 关闭开关后若使用外部 MCP 客户端直连的 server，请重启该客户端。
- `cb-cli` 行为不受开关影响，CI 可继续直接使用。
