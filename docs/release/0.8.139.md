# 0.8.139：8.3 短路径拼接修复

> 发布日期：2026-11-05 ｜ 正式版（0.8.138 → 0.8.139）
> 测试结果见 [测试报告-0.8.139.md](../testing/test-report-0.8.141-agent-control.md) 与 [完整复核报告](../testing/test-report-0.8.139-full.md)；
> 对齐依据见 [对齐对照.md](../guide/alignment.md)。

本版修复 CI 在 0.8.138 上暴露的 **Windows 8.3 短路径拼接畸形**：资源文件（windres）、`Use83Paths`、`$TO_83_PATH` 等路径在部分环境下会得到 `E:\"C:\...\"` / `D:\"...\"` 这类非法路径。

## 1. 现象与根因

**现象**：GitHub Actions run `41836259345` 的 `core` 作业在 `tests/test-compiler-wrapper.js` 资源文件断言失败：

```text
windres.exe ... -i "D:\"C:\Users\RUNNER~1\...\?? ??\res.rc\"" ...
```

**根因**：`src/tools/pathCase.ts` 的 `shortPathWin` 用

```ts
spawnSync('cmd', ['/d', '/s', '/c', `for %I in ("${p}") do @echo %~sI`])
```

获取 8.3 短路径。Node 会对含空格的 `/c` 参数**再次加引号**，`cmd /s` 解析后把输出拼成「当前盘符 + `\"原路径\"`」：

- 本机复现：`E:\"C:\Users\...\res.rc\"`
- CI：`D:\"C:\Users\RUNNER~1\...\res.rc\"`

这不是测试环境的偶发问题：`shortPathWin` 同时用于资源文件编译、`Use83Paths`、`$TO_83_PATH` 与 `$file`，真实构建会拿到非法路径。

本地测试曾偶然通过，是因为畸形字符串里仍包含原始长路径；CI 上 `runneradmin` 被缩写为 `RUNNER~1`，长路径不再被包含，断言才暴露。

## 2. 修复

- **`shortPathWin`**：
  - 增加 `windowsVerbatimArguments: true`，阻止 Node 再次包装 `/c` 命令；
  - 改用 `cmd /u`，内部命令以 UTF-16LE 输出，避免非中文代码页把中文短路径写成 `??`；
  - 按 UTF-16LE 解码，并用 `fs.existsSync` 校验；无效时回退 `decodeText`（UTF-8/GBK）与原路径；缓存只保存有效结果。
- **回归测试**：
  - `tests/test-compiler-wrapper.js` 的资源断言改为校验 `-i` 参数是**存在的绝对路径**且 basename 为 `res.rc`，兼容 8.3 短路径（不再要求原始长路径）；
  - `tests/test-drive-case.js` 新增 4 条 `shortPathWin` 断言：中文+空格、畸形拼接、缓存稳定、特殊字符路径；
  - 新增 `tests/e2e/test-e2e-ccache.js`（21 断言）：中文工程路径 + 真实 ccache，覆盖相对源路径 + `-fno-working-directory`、`Cacheable calls` / `Hits`、ASCII 与 `cache=none` 对照（无 ccache 时 SKIP）。

## 3. 兼容与边界

- 仅 Windows 使用短路径逻辑；非 Windows 直接返回原路径。
- ASCII 路径行为不变；8.3 短路径仍按 Code::Blocks 语义使用，只是现在返回合法可用的路径。
- `cmd` 不可用、8.3 名称不可生成或输出仍不可解析时，回退原路径，不再产生畸形路径。
- 不新增设置项；不改变编译/链接流程、ccache 非 ASCII 规避或 `sccache` 行为。
