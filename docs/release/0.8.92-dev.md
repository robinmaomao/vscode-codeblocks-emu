## D1 Detach（分离调试器，进程继续运行）

- 对齐 CB：`debugger_menu.xrc:92-93` → `debuggermenu.cpp:141/724-728` → `debuggergdb.cpp:2486-2491`
  （`Detach()` + 放弃驱动）→ `gdb_commands.h:354-375`（CLI **`detach`**）；启用条件
  `debuggermenu.cpp:522-523` = **附加会话 + 暂停**。
- 适配器新增 `detach()`：发 MI `-target-detach` → 输出写 Debug Console → 发 `terminated` → 回收 GDB；
  新增 `isAttached()` / `isDetached()`（对齐 `IsAttachedToProcess` 语义）。
- `disconnect`：附加会话**先显式 `-target-detach`** 再结束（实验证明即使不分离被附加进程也存活，显式化更稳）。
- 新命令 `codeblocks.debug.detach`（Debug 菜单 Detach）：无会话/未暂停给出明确提示（对齐 CB 启用条件）；
  成功后状态栏「已从进程分离；被调试进程继续运行」。
- 实机实验（GDB 8.1）：attach 与 launch 两种会话 `-target-detach` 均 `^done` 且进程继续运行；
  launch 模式属**保护性扩展**（CB 仅附加模式提供）；attach 后 `-gdb-exit`/强杀 GDB 均不杀被附加进程
  （现有停止路径无隐性缺陷，实验 D/E），launch `-gdb-exit` 正常终止进程（实验 F，DAP 语义保持）。

## D2 Add symbol file…（运行时加载附加符号，可用版）

- CB 现状取证：菜单项存在（`debugger_menu.xrc:77-78`，启用 `debuggermenu.cpp:514-515` 仅暂停），
  但 `debuggergdb.cpp:1794` 为 `// TODO: should reimplement`，`:1807` 真正下发命令**被注释**；
  且原命令类 `gdb_commands.h:268-291` 发的 `add-symbol-file <file>` **缺地址参数**。
- 实测（GDB 8.1）：无地址必失败 `The address where <file> has been loaded is missing`（C3）；
  带地址成功 `add symbol table … .text_addr = 0x…` 且**主符号不受替换影响**（C2）；
  `-file-symbol-file` 是**替换主符号**语义（`main` 消失，C1）→ 不采用；
  扩展 `quote()`（反斜杠双写）路径形式实测同样可用（G，无需像 CB 转正斜杠）。
- 适配器新增：
  - `=library-loaded` / `=library-unloaded` 跟踪（`handleAsync`）→ `loadedLibraries()`
    （`ranges` 首段 = `.text` 加载地址，作地址预填数据源）；
  - `addSymbolFile(file, address)`：会话 + 暂停守卫、**地址必填**（空/非法格式明确报错）、
    `-interpreter-exec console add-symbol-file <quote(file)> <addr>`、输出写 Debug Console。
- 新命令 `codeblocks.debug.addSymbolFile`（Debug 菜单 Add Symbol File…）：QuickPick
  **已加载库列表（自动带 .text 地址）** + 「选择文件…」（exe/dll/so/elf/o）→ 地址输入框（预填、校验）。
- 保护性差异（记录）：CB 该项不可用且命令缺地址 → 扩展实现为可用版 + 地址必填 + 库地址预填。
