# 0.8.150

> 发布日期：2026-11-12 ｜ 功能版（0.8.148 → 0.8.150）
> **主题**：工程右键 `Build options…` / `Properties…` 完整移植 Code::Blocks

## 概述

本版把 Code::Blocks 工程右键里的两个核心对话框搬到 VS Code：

- **`Build options…`**（CB `CompilerOptionsDlg`）——工程/目标两级编译、链接、搜索目录、构建前后命令、自定义变量与 `"Make" commands`；
- **`Properties…`**（CB `ProjectOptionsDlg`）——工程设置、构建目标、脚本、备注、C/C++ 解析器选项与调试器页签。

两者共用同一套 Build options 视图（独立面板 + 属性面板内的覆盖层），因此交互与写回逻辑只有一份。数据来源仍是 `.cbp`：面板只收集数据，保存时由宿主统一写回并重载工程。

## 一、入口与共享视图

| 入口 | 行为 |
| --- | --- |
| 工程树工程节点右键 → `Build options…` | 打开独立面板（`codeblocks.compilerOptions` 命令，标题由「Compiler Options…」改为「Build options…」） |
| 工程节点右键 → `Properties…` | 打开工程属性面板（6 个页签），`Build options…` 按钮在面板内以居中对话框打开同一视图 |
| 目标节点右键 → `Build options…` | 打开独立面板并直接定位到该目标 |

- 左侧为工程/目标树（工程节点 + 各构建目标），右侧内容区首行是 **Selected compiler** 字段，其后是页签：编译器设置 / 链接器设置 / 搜索目录 / 构建前·后步骤 / 自定义变量 / `"Make" commands`。
- 编译器设置内再分「编译器标志 / 其它编译器选项 / 其它资源编译器选项 / `#定义`」子页签；标志列表按分类分组，右侧为复选框与参数列，底部保留 CB 的红色提示「注意，右键单击可设置或编辑编译器参数」。
- 链接器设置拆为「链接库 / 其它链接器选项」并排卡片，↑/↓ 按钮在列表左侧；搜索目录的 Policy 位于「编译器 / 链接器 / 资源编译器」子页签下方（对齐 CB 的布局顺序）。
- 底部按钮：`保存`、`保存并关闭`；保存失败时面板内回发错误并保持打开。

## 二、Compiler Flags 右键菜单与覆盖

标志列表右键菜单与 CB `compileroptionsdlg.cpp:3084-3096` 一致：

- `新建参数…` / `修改参数…` / `删除参数`
- `仅 C 参数…` / `仅 C++ 参数…`
- `展开所有分类` / `折叠所有分类`

落地方式：

| 设置项 | 作用 |
| --- | --- |
| `codeblocks.compiler.customFlags` | 新增参数（可编辑/删除），参与勾选列表 |
| `codeblocks.compiler.flagOverrides` | 覆盖（`modified`，以原始 `option` 为键）或隐藏（`removed`）**内置**参数；清空即恢复 XML 默认 |
| `codeblocks.compiler.languageFlags` | 「仅 C」`cOnly` / 「仅 C++」`cppOnly` 参数；设置后覆盖编译器 XML 的 `<Sort CFlags/CPPFlags>`，构建时按文件语言注入 |

- 覆盖/删除内置参数会弹出确认；删除后列表底部给出「恢复默认」提示，恢复即从 `flagOverrides.removed` 移除该项。
- 新增/修改会校验名称与参数非空、同参数重复，并在内置参数被覆盖时提示「编译器已内置该参数」。
- 只有当前选中的编译器受影响（按 `compilerId` 分组），切换编译器后目录即时刷新。

## 三、`"Make" commands`：Silent build 派生、Dist-clean 只读

CB 的 `compiler_options.xrc:1105/1130` 把 `Dist-clean project/target` 与 `Silent build` 的标签和输入框都标为 `<hidden>1</hidden>`，并且在保存时**不读取**输入框，而是派生：

```cpp
// compileroptionsdlg.cpp:1131-1132 / 1169-1170
SetMakeCommandFor(mcSilentBuild, txtMakeCmd_Build->GetValue() + " > $(CMD_NULL)");
```

本扩展按「方案 1」显示这两行，但保持派生/只读语义：

- **Silent build**：始终跟随 `Build` 命令派生（`<build> > $(CMD_NULL)`），输入框只读，编辑 `Build` 时同步刷新；
- **Dist-clean**：默认值 `$make -f $makefile distclean$target` 时不显示，工程里已有非默认值时才只读显示并给出说明；
- 保存时对工程与各目标统一重算派生值，避免写回过期内容；「更多命令」仅在存在派生值或自定义 Dist-clean 时出现。

## 四、Selected compiler 自动匹配工程声明的编译器

`.cbp` 里的 `<Option compiler="riscv32-v2" />` 现在会自动落到对应编译器（如 `RISCV32-V2`），不再固定显示扩展默认编译器：

- 匹配顺序：`id` 精确 → `id` 忽略大小写/连字符 → 名称忽略大小写/连字符；
- 编译器未注册时下拉追加一项并标注「(未找到)」，避免静默回退到别的工具链；
- 工程/目标未声明编译器时回退扩展设置 `codeblocks.compilerId`，并把结果写回作用域数据；
- 下拉只显示编译器名称，`id` 放在 `title` 里。

## 五、`Properties…` 与文件属性

- 页签：工程设置 / 构建目标 / 脚本 / 备注 / C/C++ 解析器选项 / 调试器；构建目标页签内可编辑目标类型、输出、编译器、依赖与目标文件列表。
- 文件属性改为模态：工程树文件右键 `Properties…` 直达该文件（选中行、滚入可视区、切换到对应目标），关闭时回写草稿。
- 脚本页签对 `<Script file>` 做存在性与 **Squirrel 语法**校验（只校验不执行），构建时仍按既有行为警告「暂不支持 Squirrel 构建脚本」并跳过。
- C/C++ 解析器页签读写 `<Extensions><code_completion><search_path add="…">`，保存后同步到 clangd 编译数据库。

## 六、解析与写回修复

| 问题 | 修复 |
| --- | --- |
| `<ExtraCommands>` 没有 `Add` 时解析器提前 `return`，`<MakeCommands>` 永不解析 | 仅跳过 `Add` 处理，继续解析 MakeCommands 与 legacy 节点 |
| 写回丢失未建模字段、legacy `<Build><Option>` 子节点 | 无模型值时回退原始 XML；legacy 子节点原样透传；模型显式空串视为用户清空 |
| `listCompilers` 把 `options_common_*.xml` 当编译器 | 以 `/^common(_|$)/i` 过滤 |
| 覆盖层重开后参数目录/语言参数丢失 | 保存时回写 `compilerCatalogs` / `compilerBaseCatalogs` / `compilerFlags` / `defaultCompilerId` |
| 目标被改名/删除后，过期快照按索引写到别的目标 | 先整体校验所有目标标题（`Target not found: {0}`），再落字段；工程重载时关闭面板 |

## 八、兼容与边界

- 不执行 Squirrel 构建脚本（仅语法校验 + 跳过警告），与既有行为一致。
- 参数覆盖/新增保存在**用户设置**（`application` 作用域，按编译器 ID 分组），不写入 `.cbp`；换机器或清空设置即回到编译器 XML 默认。
- 命令、视图、快捷键总数不变（113 / 6 / 34），仅 `codeblocks.compilerOptions` 标题改为 `Build options…`。
- 面板与属性面板共用视图与保存链路：任一处保存后都会写盘并重载工程，另一处打开时看到的是最新数据。
