## P3 Rename file…（`projectmanagerui.cpp:2852-2916`）

- 新命令 `codeblocks.renameFile`（文件节点右键，group `1_file@5`）——旧流程「移除 + 重新添加」会丢失
  compilerVar / compile / link / weight / virtualFolder / 自定义构建命令 / 目标归属；VS Code 原生 F2 改名
  会静默破坏 `.cbp`（源文件缺失警告），本命令修复该风险。
- 守卫（对齐 CB）：自动生成文件（`AutoGeneratedBy`）拒绝；构建进行中拒绝（扩展附加）；只读文件拒绝（扩展附加）。
- 输入新名（默认原名，禁 `\ / : * ? " < > |`）；大小写仅变体允许（对齐 CB `old.Lower()==new.Lower()`）。
- 编辑器占用：先确认 → 保存脏文档 → 按 Tab 精确关闭（`TabInputText` + `tabGroups.close`）。
- 磁盘改名：`fs.renameSync`；大小写变体或 `EPERM/EBUSY` 时回退**两段式改名**（临时名 `.old.cb-rename-<pid>`）。
- `.cbp` **最小文本手术**（新模块 `src/project/unitText.ts`）：仅改该 `<Unit filename>` 的属性值，
  子 `<Option>`、缩进、其它属性原样保留；未命中时明确提示手动修正。
- 其它已打开工程引用同一绝对路径 → **仅状态栏提示**（对齐 CB 只改当前工程，不自动改）。
- 重解析刷新 + 打开新文件。记录项：旧对象文件不迁移（CB 同），Clean 只删新对象名。

## P4 虚拟文件夹管理（`cbproject.cpp:1051-1097`）

- 新纯模块 `src/model/virtualFolders.ts`：
  - `addVirtualFolder`（多级 `a/b`、禁 `;`/`\`/空段/`.`/`..`、重复拒绝）；
  - `renameVirtualFolder`（列表与文件 `virtual_path` 前缀替换、保留子路径、改名后去重）；
  - `deleteVirtualFolder`（列表含子级移除 + 文件回根，**绝不删磁盘文件**）；
  - `assignFileToVirtualFolder`（拖拽归入，`''` = 回根）、`countFilesUnderVirtualFolder`、`isUnderVirtualFolder`、`remapVirtualFolder`。
- **保护性差异**：CB 用裸 `StartsWith` 前缀匹配（删除 `a` 会误伤 `ab`），本实现用**精确前缀**
  （等于自身或 `prefix + '/'`），已记录并在测试中固化为断言。
- 新命令：`codeblocks.newVirtualFolder` / `codeblocks.renameVirtualFolder` / `codeblocks.deleteVirtualFolder`
  （虚拟文件夹节点右键 group `5_vf@1..3`；工程节点可新建；Menu → Project → Project tree → Add New Virtual Folder…）。
  删除前模态确认并提示「N 个文件将移回工程根；磁盘文件不会被删除」（对齐 CB 的确认语义）。
- **拖拽入夹**（`ProjectDragAndDropController`）：拖拽载荷结构化（`project` / `files` 两类）——
  文件（支持多选）拖到**虚拟文件夹 / 物理目录 / 工程节点（=回根）**即修改 `file.virtualFolder`
  （仅模型，磁盘不动，对齐 `ProjectVirtualFolderDragged`）；文件分组节点不接受；跨工程拖拽忽略。
- 写回统一 `serializeProject` + `persistProjectAndReload`（空虚拟文件夹链在树中仍然显示）。
