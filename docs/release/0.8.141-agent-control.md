> 发布日期：2026-11-05 ｜ **预发布版**（`feat/agent-control` 专用，不合并 `main`）

> 使用说明见 [Agent 控制](../guide/agent-control.md) / [Agent control](../guide/agent-control.en.md)。

## 1. 本版能力

让 Copilot agent（VS Code Language Model Tools）、任意 MCP 客户端与 CI（CLI）**完整控制** Code::Blocks 工程：

| 能力 | 工具 / 命令 | 说明 |
|------|-------------|------|
| 读工程 | `codeblocks_project_read` | 四种视图（summary / targets / files / options）+ `schema` |
| 增量改 `.cbp` | `codeblocks_project_edit` | Edit DSL；`dryRun` 预览；`canonical` / `preserve` 两种写盘 |
| 文件 / 目标管理 | `codeblocks_project_file` / `codeblocks_project_target` | 增删改名 + 目标归属同步 |
| 构建 / 重建 / 清理 | `codeblocks_build` | 结构化诊断、`timeoutMs` 取消、`dryRun` |
| 构建状态 | `codeblocks_build_status` | 最近一次摘要（文件/行/列/严重级/命令/耗时） |
| 运行 | `codeblocks_run` | 捕获 stdout/stderr + 退出码 + 超时 |
| 调试 | `codeblocks_debug` | start/stop/breakpoints/stack/variables/evaluate/continue/step |
| 编译器 | `codeblocks_compiler` | list / detect / set / programs |
| 导出 | `codeblocks_export` | makefile / compile_commands / commands |
| 工作区 | `codeblocks_workspace` | 多工程与 `.workspace` 依赖 |

三条传输共用同一份 `src/api/toolRegistry.ts`，行为一致：

- **Language Model Tools**：`contributes.languageModelTools`（11 个，`engines.vscode` 需 ≥ 1.102）
- **MCP**：`contributes.mcpServerDefinitionProviders`（`bundle/cb-mcp.js`，`process.execPath` 启动）
- **CLI**：`bundle/cb-cli.js`（`show / edit / add-file / build --clean / run / debug / export / compiler / workspace`）

## 2. 架构

```
Copilot agent ──► LM Tools（扩展进程内）
MCP 客户端   ──► MCP server（子进程，stdio）
终端 / CI    ──► cb-cli（子进程）
                        │
                        ▼
              src/api 控制内核（无顶层 vscode 依赖）
                        │
                        ▼
        src/build/buildProject（与 UI 构建同一实现）
```

- `src/build/buildProject.ts` + `buildSummary.ts`：从 `extension.ts` 抽出的构建内核，UI / CLI / Agent 同源。
- `src/compiler/compilerFactory.ts`：编译器装配下沉，设置读取以接口注入。
- `src/cli/vscodeShim.ts`：用 `Module._load` 拦截 `vscode`，使构建链路可在无宿主下运行。
- 非交互构建：跳过 Rebuild 确认、自动停止调试器、跳过输出通道抢焦点；构建占用返回结构化 `build-busy`。

## 3. 安全与一致性

| 机制 | 行为 |
|------|------|
| 字段白名单 + 范围校验 | 未知字段报 `invalid-input`；`targetType 0..5`、`platforms 0..255`、`pchMode 0..2`、`weight 0..100` |
| `dryRun` | 只校验与预览，不写盘 |
| `allowScripts` | 脚本类字段（前后构建命令 / 自定义命令）必须显式放行 |
| 写盘签名 | 读盘**前**取签名，写盘前比对；并发外部修改 → `external-modified`（`force: true` 覆盖） |
| 扩展侧 tracker | `projectChangeTracker.hasChanged` 兜底，写入内存模型后重解析刷新树 |
| 原子写 + 编码保持 | 同目录临时文件 + `rename`；沿用原文件编码（UTF-8 / GBK / BOM） |

## 4. 兼容与边界

- **不新增命令、不新增设置**：既有 112 个命令、83 个设置项与全部 UI 行为不变（契约层逐项校验）。
- `engines.vscode` 抬到 `^1.102.0`：这是稳定版 LM Tools 与 MCP provider API 的前提，低于 1.102 无法安装本扩展。
- `preserve` 只支持文件级 `compile` / `link` 定点改写，其他编辑自动降级 `canonical` 并在 `warnings[]` 说明。
- `codeblocks_run` 无 stdin，交互式程序请用终端；GUI 程序与调试行为沿用现有 DAP。
- CLI/MCP 写盘会触发扩展的「外部修改」提示（文档已说明）；LM Tool 走内存模型不触发。
