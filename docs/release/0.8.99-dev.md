# 0.8.99-dev

> 响应文件（`*.respFile`）两项改进：**目录对齐**（不再散落工程根目录）+ **Clean 清理开关**（默认关，保持 CB 对齐）。

## 背景（响应文件是什么）

- 链接 / 编译命令行超过阈值时，扩展对齐 Code::Blocks `CheckForToLongCommandLine`（`directcommands.cpp:200-260`）
  把命令末尾参数（通常是对象列表）写入响应文件，命令改为 `@"<respFile>"`（gcc 从 `@file` 读参数）：
  - 生成位置：链接 / 打包 `<对象目录>/<目标名>_link.respFile`；编译 `<对象目录>/<源文件名>.respFile`
  - 阈值：`safe` 默认 **8000**（为 cmd.exe 8191 上限留余量）/ `cb` 模式 **32767**（对齐 CB）
- Code::Blocks 自身**从不删除**响应文件（全源码仅创建逻辑）；扩展此前同样保留、Clean 也不清理。

## 修复 A：目录对齐（`objectOutput` 为空 → `.objs`）

- **问题**：`.cbp` 未设置 `object_output` 时（parser 默认空串，`parser.ts:440`），对象文件会正确落到 `.objs/`，
  但链接 / 打包的响应文件此前直接用空目录字符串 → `path.join(工程根, '', 'Debug_link')` →
  **落到工程根目录** `Debug_link.respFile`（与 CB 不一致，也是"构建后工程里冒出一个不认识的文件"的常见来源）。
- **修复**：新增 `linkRespBase()`（`src/build/commandLine.ts`），空值 → `.objs`
  （对齐 `CompileTargetBase::GetObjectOutput` 的空值默认，`compiletargetbase.cpp:203-216`）；
  `buildEngine` 链接（`:1017`）与静态库打包（`:1115`）两处接入。

## 功能 B（新设置，默认关）：`codeblocks.build.cleanResponseFiles`

- Clean / Rebuild 时**递归删除目标对象目录下的 `*.respFile`**（含嵌套的编译响应文件），数量计入 Clean 汇总（详细模式逐条列出）；
- **默认 false**：Code::Blocks 不清理响应文件，默认关闭保持对齐；开启后避免旧响应文件永久遗留。
- 说明：响应文件是随时可安全删除的临时输入（需要时会自动重新生成）。
