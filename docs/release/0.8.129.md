## 概述

- **测试分层体系（L-1…L5 + CI）**：契约 / 无头单元 / 真实工程·调试·工具链·边界 E2E / VS Code 宿主 / 像素视觉 / 性能基准 / 打包安装七层统一运行器（`tests/run-all.js`）+ GitHub Actions；

- **post-build 脚本结束判定（本版新增）**：命令本体退出即继续构建，脚本里的后台进程不再拖住 post-build（详下）；
- **post-build 观感与阻塞治理（本版新增）**：脚本 stdout/stderr **实时流式**写入构建日志（不再等命令结束才回放，卡住期间不再「一片空白」）；长命令每 5s 输出「仍在运行 (x s)」心跳行（首条附排障提示）；新增可选超时 `codeblocks.build.scriptCommandTimeoutMs`（默认 `0` = 不超时，对齐 CB 无限等待；超时强杀进程树并记失败），用于脚本内网络盘（SMB）重连、上传服务（.NET 默认 100s 超时）等阻塞场景。杀树按「运行期采集进程树 PID + 超时后多轮收割」加固：`taskkill /T /F` 是瞬时快照式的，快照后才产生的子孙、以及「根已退出」时的空操作会让脚本继续启动 `start /b` 后台进程（实测杀树后 1~10s 仍出现且长期存活）。
- **构建关键路径开销**：项目级 pre/post 宏展开复用 `CommandGenerator`；扩展激活时异步预热 Windows 系统 PATH 缓存。
- **clangd 补全不再自动插入头文件（本版新增）**：生成的用户级 `config.yaml` 片段固定 `Completion.HeaderInsertion: Never` —— clangd 默认 `IWYU` 会在接受补全时自动插入符号所属 `#include`；如需恢复默认请自行覆盖该片段（下次生成会被重写）。

规模（0.8.129 时点）：命令 **103** 项、设置 **62** 项（7 分区 + 中英 nls）、视图 5 个；分层回归 `contract 2/2`、`unit 151 脚本 FAIL=0 SKIP=1`、`e2e 4/4`（构建矩阵 40 pass、调试 143 pass）、`perf 13 项 0 fail`、`pack 14 pass`。

## post-build 脚本结束判定（本版新增）

- **问题**：`.cbp` 工程 post-build 明显偏长——脚本本体早已结束，扩展仍要等很久才出汇总；脚本里启动后台程序时更甚（实测 `start "" /b ping -n 6 …`：命令本体 **47ms** 结束，引擎却等 **5113ms**）。
- **根因**：`scriptRunner.runScriptCommand` 以 Node `close` 事件判定脚本结束——`close` 要等**所有 stdio 管道关闭**，脚本启动的后台进程（`start` / GUI / 守护进程）继承 stdout/stderr 后会把构建拖到它们退出为止。Code::Blocks 同步等待**命令本体**（`wxExecute`），命令一结束就继续。
- **修复**：结束判定改用子进程 **`exit`** 事件 + 管道排空宽限；新增设置 `codeblocks.build.scriptExitGraceMs`（毫秒，默认 **1500**、可设 **0** 完全对齐 CB、上限 60000、非法/负值钳制 0）；宽限到期仍无 `close` 时在日志给出「后台进程仍在运行（不阻塞构建…）」说明行；单条脚本命令 >3s 追加 `耗时 x.xs（命令自身运行时）` 行（`plainCbLog` 模式两类提示均不输出）。
- **语义边界**：需要等后台程序结束的脚本请改用前台命令或 `start /wait`，或调大 `scriptExitGraceMs`。
- **实测**：同一条后台命令 `项目/post-build` **5117ms → 1557ms**；`scriptExitGraceMs=0` 时 **7ms**；6 条 `echo` 场景无回归。

## post-build 观感与阻塞治理（本版新增）

- **问题**：post-build 脚本卡在外部等待（网络盘 SMB 重连 `if not exist Z:\…`、上传服务 `.NET` 默认 100s 超时）时，构建日志**一片空白**直到脚本结束——用户无法判断是「脚本/网络慢」还是「扩展卡住」。
- **根因**：输出在命令结束后才整体回放；且引擎把脚本的全部等待时间都算作 post-build 时长，没有任何可观测信号或止损手段。
- **修复**：
  - **实时流式**：stdout/stderr 边运行边逐行写入日志（缩进两空格）；
  - **心跳行**：脚本命令运行 >5s 起每 5s 输出 `[script i-N] 仍在运行 (x s)…`（首条附「网络盘/服务等待 → 可在脚本内设置超时，或点『停止构建』终止」提示）；
  - **可选超时** `codeblocks.build.scriptCommandTimeoutMs`（默认 `0` = 不超时，对齐 CB 无限等待；上限 3600000）：超时强杀整棵进程树、日志给出超时行、构建记为失败；
  - **杀树加固**：`taskkill /T /F` 是**瞬时快照**式杀树 →（a）快照之后新生的子孙会逃逸；（b）taskkill 执行前命令本体已退出时整次杀树变成空操作（实测输出「没有找到进程」）。两种情况都会让脚本继续解释后续行并启动 `start /b` 后台进程（实测杀树后 **1s / 10s** 各出现一个，且长期存活）。因此在超时启用时**运行期多次采集命令的进程树 PID**（启动 150ms 后起、每 2.5s 一次、最多 4 次；枚举用 `wmic`≈0.4s，PowerShell `Get-CimInstance` 需 ≈2.7s——快照延迟直接决定能否在中间 cmd 退出前记下它的 PID；`wmic` 缺装时回退 CIM），超时后按「父 PID ∈ 已终止集合」多轮（6×800ms）收割，并排除自身 PID（防 PID 复用误杀）。
- **实测**：把超时点压在「前台等待结束」附近（最易出现 kill/start 竞态）——改造前（未收割）**15 轮中 14 轮**出现逃逸残留且 8s 后仍存活；加固后 **8 组超时点 × 3 轮 = 24/24 轮**零残留。
- **语义边界**：超时 = 终止整棵命令树，**脚本启动的后台程序会一并被终止**（这是超时的定义；不设超时则沿用「命令本体结束即继续」的 CB 语义）。单元回归 `tests/test-script-runner-exit.js` 覆盖流式实时性 / 心跳 / 超时 / 进程树快照 / 孤儿收割（51 断言），E2E S16 覆盖「标记行在构建返回前出现」。

## 构建关键路径开销

- 项目级 pre/post 命令的宏展开不再逐条 `new CommandGenerator`（1200 文件 / 6 目标工程构造 48.2ms/次，模板展开仅 0.7ms/次）→ 按编译器实例缓存复用；
- 扩展激活时 `warmWindowsSystemPath()` 异步预热注册表 PATH 缓存：首次构建「环境准备」不再同步付出 2×`reg.exe`（本机实测 184–209ms）。
