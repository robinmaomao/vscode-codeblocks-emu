# 0.8.96-dev

> 增量编译识别 `.ld` 等编译相关文件改动（保护性增强）：工程内 `.ld` / `.lds` / `.icf` / `.def` / `.xm` 等非编译文件改动后，自动重链接 / 重新打包。

## 背景（问题）

- 工程内 `.ld`（链接脚本）等文件不产生对象文件，不参与对象时间戳比对；此前只有目标属性 `external_deps` 能让它触发重链接。
- 实验复现（真实 gcc）：`main.c` + `start.S` + `ram.ld` 工程，二者均已编译且输出存在时：
  - 改 `.S` 自身 → 重编译 ✓（已有）
  - 改 `.S` 的 `#include` 头文件 → 重编译 ✓（已有）
  - **改 `ram.ld`（未配 external_deps）→ `Nothing to be done` ✗（本次修复）**
  - 改 `ram.ld`（已配 external_deps）→ 重链接 ✓（已有逃生通道）

## CB 取证

- CB 链接新鲜度只有两路：对象时间戳（`directcommands.cpp:819-833`：`objtime > outputtime → force`）与外部依赖（`AreExternalDepsOutdated` `directcommands.cpp:1007-1140`：库 `:1022-1084`、`external_deps`/`additional_output` `:1087-1140`）。
- "Nothing to be done (all items are up-to-date)." 由 `compilergcc.cpp:4131` 输出。
- CB 对工程内 `.ld` **同样不自动识别**；官方做法是填入目标属性 "External dependencies"（UI：`external_deps.xrc`；持久化：`projectloader.cpp:594-595 / 1635`）——即 `external_deps` 机制（扩展此前已完整支持）。

## 修复（保护性增强）

- 新设置 **`codeblocks.build.linkInputExtensions`**（数组，默认 `["ld","lds","icf","def","xm"]`；设 `[]` 关闭，恢复 CB 1:1 行为）：
  `.ld`/`.lds` = GCC/AVR 链接脚本、`.icf` = IAR 链接配置、`.def` = Windows 模块定义、`.xm` = AVR xmega 资源（工具链把 `.xm` 当资源编译时可从列表移除）。
- `buildEngine.linkInputsOutdated(target, output)`：遍历 `target.files`，仅取**非编译、非链接对象**且扩展名在白名单内的文件；mtime 比输出新（输出必须已存在）→ 返回该文件绝对路径。
- 接入 3 个判定点（对应“无编译单元早退 / 链接 / 静态库打包”）：
  1. 「Nothing to be done」早退分支：链接输入更新 → 继续进入链接阶段（不再提前返回）；
  2. 链接 `forceLink`；
  3. 静态库 `forceArchive`。
- 触发日志（仿 CB `directcommands.cpp:1052` 的 DebugLog 文案）：`Re-linking because 'ram.ld' is newer` / `Re-archiving because 'ram.ld' is newer`。
- 顺带修复：早退分支此前丢弃 `areExternalDepsOutdated` 的 `filesMissing`，缺失依赖无 WARNING；现与链接分支一致输出（对齐 `directcommands.cpp:707-720`）。

## 边界（不做的事）

- 不解析链接命令行的 `-T xxx` / `--script=`（宏展开、引号、响应文件场景复杂，易误判）；纯链接选项引用的文件仍请用 External dependencies。
- 工程外文件：用 External dependencies（CB 同款，目标属性面板可编辑）。
- 不做文件监视自动构建（保持 CB「构建时判定」语义）。
- 有自定义编译命令（custom buildCommand）的文件由编译单元链路负责，不在本增强范围。
- `.S`（汇编）与其 `#include` 头文件改动：本已支持（对象时间戳 + 依赖扫描），无变化。
