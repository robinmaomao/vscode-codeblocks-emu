# 0.8.148

> 发布日期：2026-11-11 ｜ 修复版（0.8.147 → 0.8.148）
> **主题**：Build Log（诊断来源 `build`）错误点击不跳转修复 + ANSI 颜色输出兼容

## 概述

0.8.141 / 0.8.142 修好了普通编译错误与部分链接期错误（`func_bt.c:(.text.f+0x2e)`），但仍有「有时候点了不跳」的残留场景：链接器输出 `<src>:(.text+0x9)` / `<obj>:(.text+0x9)` 时，诊断定位的「无改善」判断用错了比较对象，最终回退到带 `:(.text+0x9)` 的伪路径（永不存在）⇒ `openTextDocument` 失败 ⇒ 点击无反应；对象文件 `.o/.obj` 在链接阶段必然存在，还会被直接当成跳转目标。另有 `ld.exe` / `collect2.exe` 等无源码位置条目仍按可点击渲染，以及 `-fdiagnostics-color=always` 的颜色码导致整行解析失败。

本版修复三类跳转问题，并统一清理子进程输出中的 ANSI 颜色转义。

## 一、现象

- `codeblocks.clangd.buildLogDiagnostics = build` 时，Build Log 的 Errors 条目**有时**点击无反应，构建结束的「跳首个错误」与 F4 也静默跳过；
- 常见于链接期 `undefined reference`：`src/main.c:(.text+0x9)`、`obj/Debug/main.o:(.text+0x9)`；
- `ld.exe: cannot find -lfoo`、`collect2.exe: error: ld returned 1 exit status` 等条目点了完全没反应，也没有提示；
- 工程给编译器加 `-fdiagnostics-color=always` 时，Build Log / Problems 里**完全没有**错误条目。

## 二、根因

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 诊断定位 | `resolveDiagnosticLocation` 拿**剥掉 `:(section)` / `:line` 的 token** 拼 naïve 路径做 `unchanged` 比较；文件本来就对、行号推不出时判定「无改善」返回 `undefined` | 调用方回退到带 `:(.text+0x9)` 的原始路径 ⇒ 永不存在 |
| 对象文件 | `resolveExistingFile` 先判「路径存在」，`.o/.obj` 在链接阶段必然存在 | 对象文件（二进制）成为跳转目标，或行号探测失败后留下伪路径 |
| 无源码位置 | 伪工具名 / 构建产物仍按可点击渲染；`openFileAtLocation` 失败只写输出通道 | 点击无反应，没有任何可见反馈 |
| ANSI | 颜色转义插在 `file:line:col:` 之间，诊断正则整行匹配失败 | `-fdiagnostics-color=always` 时 Build Log / Problems 为空 |

## 三、修复

- `src/build/diagnosticPath.ts`
  - `unchanged` 改用**原始 `input.file`**（未剥离）比较：剥掉段名/行号后落到真实文件本身就是改善；
  - `.o/.obj` 只作为「找同名源码」的线索（工程文件索引 → 对象同目录的同名源码），**绝不返回对象文件**；
  - 新增 `isNavigableDiagnosticFile()`：排除工具伪名（`ld/collect2/windres/gcc/cc1/make/...`、`<stdin>` 等）、二进制/构建产物（`.o/.obj/.a/.dll/.exe/...`）与残留段名 `:(`。
- `src/tools/encoding.ts`
  - 新增 `stripAnsi()`（CSI / OSC / 单字符 ESC；无 ESC 行走 `includes` 快路径）；
  - 在 `decodeOutputLines` / `OutputLineDecoder` 的行解码阶段统一清理 ⇒ 构建、脚本、GDB 输出都不再带颜色转义。
- `src/extension.ts`
  - Build Log 结构化诊断与 Problems URI 统一做可导航校验（`statSync().isFile()` 按构建缓存）；不可导航时清空 `file/line/column`（消息保留），Problems 回退到工程根；
  - `codeblocks.openLocation` 失败时弹出可见警告（原来只写输出通道日志）。
- `src/ui/buildLogTreeProvider.ts`
  - 树节点命令以可导航判断为门；无源码位置条目显示「无源码位置（链接器/工具输出）」提示，不挂跳转命令；
  - F4 导航列表同步使用共享判断。

## 五、兼容与边界

- 正常 `file:line:col` 诊断行为不变（resolver 仍返回 `undefined`，走原逻辑）；
- 工程外对象且找不到同名源码时不猜测跳转目标（保留消息、不跳转）；
- 不新增设置项/命令；不涉及构建命令与产物；
- `make` 自定义工程仍不经构建引擎解析诊断（既有边界）。
