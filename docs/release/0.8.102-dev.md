# 0.8.102-dev

> 条目计数强制补全（else 分支）：源缺失的编译文件（仍在 `.cbp` 中、磁盘上已删除）的 WARNING 条目同样计入强制链接 / 重新打包。

## 背景

0.8.100/0.8.101 已复刻 CB `GetTargetCompileCommands:585` 的「ret 条目计数 → 强制链接」，但遗漏 else 分支（directcommands.cpp:562-566）：`IsObjectOutdated` 返回 false 且 `errorStr` 非空（源文件缺失）时，`ret.Add(COMPILER_WARNING_LOG + err)` —— **WARNING 条目同样计入计数 → 强制链接**。扩展此前输出同款 WARNING 后仍 `Nothing to be done`。

## 修复

- 编译循环收集 `missingSourceFiles`：compile 列表文件源缺失（且非 autoGeneratedBy、非 rebuild——rebuild 走 force 分支命令失败中止，对齐 CB）→ 计入强制；判定放在 compilerVar 检查之前（CB 的 else 分支先于 `GetCompileFileCommand` 的 compilerVar 判定，compilerVar 空者的 WARNING 同样计入）。
- 三处接入：链接 `forceLink`、静态库 `forceArchive`、「Nothing to be done」早退分支（与 `staleNoopFiles` 并列）。
- WARNING 文案仍由 `isUpToDate` 输出（与 CB 一致：`WARNING: Can't read file's timestamp: <路径>`）。

## 验证

- `tests/test-link-input-outdated.js` 22→**23 断言**：C22 源缺失（`gone.ld`，compile=1）→ WARNING + 无修改再构建仍重链接；C1-C21 回归不变。
- 探针 `.cb-tools/linkinput-missing.js`：修复前 `Nothing to be done`、修复后重链接。
- 全量 `TOTAL=110 FAIL=0 SKIP=1`；`tsc` 0 错误。
