### 3. 构建性能：post-build 脚本结束判定（后台进程不再阻塞构建）

| 项 | 内容 |
|---|------|
| 现象 | `.cbp` 工程 post-build 明显偏长：脚本本体输出早已结束，扩展仍要等很久才收尾；脚本里启动后台程序时更甚 |
| 根因 | `scriptRunner.runScriptCommand` 以 Node `close` 事件判定脚本结束——`close` 要等**所有 stdio 管道关闭**，脚本启动的后台进程（`start` / GUI / 守护进程）继承 stdout/stderr 后会把 post-build 拖到它们退出为止（实测 `start "" /b ping -n 6 …`：命令本体 47ms 结束，引擎却等 **5113ms**）。Code::Blocks 同步等待**命令本体**（`wxExecute`），命令一结束就继续 |
| 修复 | 结束判定改用子进程 **`exit`** 事件 + 管道排空宽限（新设置 `codeblocks.build.scriptExitGraceMs`：默认 1500ms、可设 `0` 完全对齐 CB、上限 60000、负值/NaN 钳制为 0）；宽限到期仍无 `close` 时置 `ScriptResult.trailingBackground` 并输出「后台进程仍在运行（不阻塞构建…）」说明行；单条脚本命令 >3s 追加 `耗时 x.xs（命令自身运行时）` 行（`plainCbLog` 模式两类提示均不输出） |
| 次级开销 | 项目级 pre/post 宏展开不再逐条 `new CommandGenerator`（1200 文件 / 6 目标工程：48.2ms/次 → 复用实例 0.7ms/次）；扩展激活时**异步预热** Windows 系统 PATH 缓存，首次构建「环境准备」不再同步付出 2×reg.exe（本机实测 184–209ms） |
| 验证 | `tests/test-script-runner-exit.js` **25 pass**；E2E S15（后台进程 25s 自终止）：脚本命令后 **≤3s** 收口、总时长 <10s；性能基准 B11 **min 1865.92ms ≤ 预算 3500ms**（修复前 ≈5.1s） |
