## 覆盖补齐（阶段 2）

- **DAP 能力 26/30 → 30/30**：新增 `modules`（目标+已加载库，含 .text 基址）与 `loadedSources`
  （`-file-list-exec-source-files`）实现并声明 `supportsModulesRequest`/`supportsLoadedSourcesRequest`；
  调试 E2E 新增 S9（`setFunctionBreakpoints` 真实命中、`modules`/`loadedSources` 内容、`pause` 能力探测），70 → 81 断言。
- **D-07（新发现并修复）**：Windows 原生 GDB 下 `pause` 会下发 `-exec-interrupt`，该命令既不产生 `*stopped`
  还会让 GDB 永久失去响应（实测：之后 `-thread-info`/`-break-list` 全部无回执）⇒ 改为能力探测 + 优雅降级
  （回「不支持」并保持会话可用；远程/其它平台不变）。文档限制见 [使用说明 §8](./../使用说明.md)。
- **D-08 / D-09（覆盖补齐期间发现并修复）**：
  `cleanFile` 无对象文件时只写 debug 级日志、叠加先清空输出 ⇒ 面板空白零反馈（改为 **info 级**，用户可见）；
  `toggleCompile/toggleLink` 重新启用时写默认值字面量 `="1"`（与 writer「默认值不写」不一致）⇒ 改为
  **启用＝删除该选项**、**禁用＝写 `="0"`**，并在子节点清空后收回 `<Unit … />` 自闭合写法。
- **D-10 / D-11（宿主层用例期间发现并修复）**：clangd **二进制**存在即让出 Problems ⇒ 改为需 clangd **扩展**已安装
  （未装/被禁用时构建诊断回到 Problems，宿主层实测 0 → 1 条）；`codeblocks.openProject` 忽略参数 ⇒ 支持
  `Uri|string` 带参直开（无参保持对话框）。
- **调试深化（阶段 3）**：**多线程切帧语义修复**（`stackTrace` 忽略 `threadId`、帧 id 仅按 level 跨线程冲突、
  `evaluate` 忽略 `frameId`）；新增**运行中请求防护**（`targetRunning` 状态 + 统一快速失败与中文说明）——
  修复前后差分：`threads` 30014ms → **1ms**、`evaluate` 30000ms → 0ms、`stackTrace` 30016ms → 0ms、
  `setBreakpoints` 30005ms → 1ms（原先全部 DAP 超时）；E2E 新增 attach / Detach（目标进程仍存活）/ 多线程切帧 /
  运行中防护断言，**81 → 114 断言**。`stopOnEntry` 未消费登记为能力缺口（用例 SKIP）。
- **覆盖矩阵**：设置 44/60 → **60/60（100%）**（新增 `tests/test-settings-coverage.js`：读点位置 + 已接线 + 行为断言）；
  语言/语法 3/6 → **6/6（100%）**（新增 `tests/test-grammar-smoke.js`：tmLanguage 结构 + 正则编译 + 样例命中）；
  命令 75/103 → **101/103（98%）**、快捷键 28/33 → **33/33（100%）**（新增可激活扩展的测试基建
  `tests/_harness/extensionActivation.js` 与三个命令处理器测试：编辑类 9 项 / 工程类 8 项 / 文件与快捷键 11 项）；
  DAP 26/30 → **30/30（100%）**。
  余 2 个命令为**已登记的可解释缺项**（不计入自动化）：`detectCompilers`（真实并行探测外部编译器 + QuickPick
  异步握手，跨机不稳定；已有 detector 模块级与静态接线断言覆盖）与 `openIncludeFile`（需活动工程 + 真实
  include 落盘；其纯解析链路已由 `test-include-resolver.js` 覆盖）。

## 收口（阶段 4 / 阶段 5）

- **阶段 4 工具链链接级**：AVR / RISC-V 由「对象级」升级为**链接级**断言（全量构建 → `.elf`：`e_machine`、
  入口地址语义、入口落在 `.text` 区间、`.text` 非空、`objcopy -O ihex` 可转 Intel HEX）；**TCC 0.9.27 接入**
  （构建 + 运行；其 `-o` 不补 `.exe`，测例按显式输出名断言）；MSP430 / SDCC 保持 SKIP + 精准指引
  （SDCC 稳定版仅安装器、快照为 nightly）。矩阵 **22 pass / 5 skip → 38 pass / 4 skip**（`TOTAL=42`）。
- **阶段 5 稳定性与 CI**：两处负载敏感用例（`test-debug-detach-symbol`、`test-makefile-export`）改为
  「轮询替代固定 sleep + 清理半成品 + 失败重试 1 次 + 显式超时 + 异常路径清理长驻进程」，
  `--group unit` 连续 3 次 **TOTAL=145 FAIL=0 SKIP=1**；
  同时把 `tests/test-settings-coverage.js` 的「绝对行号 ±40」读点断言换成
  「读点是一次真实配置取值（`.get(...)`）」——绝对行号断言在无关代码增删后会误报
  （实测 `gdbDebugAdapter.ts` 增行 44 行即误判，曾使 main CI 变红），新断言对插入/删除不敏感、
  且仍能拦截「键被删/改名/挪走/退化为普通字符串」（已用突变测试验证会失败）。
- **阶段 5 CI 加固**（`.github/workflows/ci.yml`）：npm 与 `.vscode-test` 缓存；覆盖矩阵汇总写入 job summary
  且生成器漂移**仅告警不失败**（矩阵已重新生成同步）；新增**每周定时巡检**（`schedule` + 桌面三层
  `continue-on-error` + 结果摘要），PR 仍只跑必跑作业。
- **未修候选（已登记，见 [遗留问题决策清单 §7](../遗留问题决策清单.md)）**：D-12 keybindings reset 去抖回写窗口、
  D-13 无扩展名产物在 Windows 下的 Run/Debug、C-01 `stopOnEntry` 未被适配器消费（E2E SKIP）。
- **视觉基线跨机可移植**：新增渲染指纹（OS/浏览器主版本/DPI/**字体度量哈希**）+ 入库基线元数据
  `tests/visual/baselines/.fingerprint.json`；同环境仍**严格判定**（本机 24 pass / 0px），跨环境自动降级为容差并
  逐条标注 `OK(P)`、明确提示「非静默放宽」；`--update` 在指纹不匹配时写 `.cb-tools/visual/<指纹>/` 不再覆盖入库基线。
  假失败来源已量化（DPI 1.25 → 10.1–12.2%、字体集不同 → 8.7–14.3%、关 LCD 文本渲染 0.43–0.62%）。
- **性能趋势**：每次运行追加 `.cb-tools/perf-history.jsonl`（本机历史），`--trend` 输出「较上次 / 较最近 N 次中位数 /
  较基线」并打印 `⚠️ 趋势告警`（仅告警，硬门禁仍是 `min ≤ 预算`）；`docs/性能基准.md` 新增「趋势」小节。
- **运行器修正**：`run-all.js --filter` 未命中任何脚本时**报错退出**（原先 `--group visual --filter props` 会
  `TOTAL=1 FAIL=0` 静默全绿）；visual 层 `--filter` 透传为脚本内 `--only`（按面 id 筛选，文档推荐用法现已可用）。
- **偶发用例复跑证据**：`test-debug-detach-symbol` 22/0、`test-makefile-export` 17/0、宿主层 23/0/0
  （含 4×CPU 满载 + PATH 注入 Git `sh.exe` 的加压复跑）。
