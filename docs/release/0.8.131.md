# 0.8.131

> 发布日期：2026-10-15 ｜ 正式版（0.8.130 → 0.8.131 里程碑汇总）

## 概述

0.8.130 发布后的迭代（**工作区检测开销治理** + **clangd 设置改动立即生效** + **设置即时生效收口**）汇入 main，并以本正式版收束。产品行为变更三处：**工程检测改为增量登记 + 单次合并扫描（含两项新设置与 1 条诊断命令）**、**clangd 用户配置在设置变更后自动重新生成（含字符串数组取值容错）**、**编译器设置变更立即生效（状态栏刷新 + 重生成 + 重启 clangd）与两项设置变更提醒（`persistLog` 需重载、`clangd.enabled` 关闭遗留片段）**；其余为测试断言与文档同步。

- **工作区检测开销治理（本版新增，对齐“构建期进程暴增 + CPU 冲 100%”修复简报）**：`.cbp` 新增/删除改为**增量登记**（不再触发全工作区 `findFiles`，历史上每次事件固定起 2 个 ripgrep 进程）；工作区工程扫描合并为**一次** `findFiles('**/*.{cbp,workspace}')` 并排除重目录，加 30s 结果缓存 + 单飞；新增设置 `codeblocks.detect.autoOpen` / `codeblocks.detect.autoOpenThreshold` 与命令 `Code::Blocks: Workspace Scan Report`；兜底符号索引加 mtime + size 单文件缓存。
- **clangd 设置改动立即生效（本版新增）**：改任意 `codeblocks.clangd.*` 后**自动重新生成**用户级 `config.yaml` 片段（不再需要重开工程 / 手动生成），生成中到达的请求改为「跑完再补一次」；`suppressedWarnings` / `forcedIncludes` / `excludeDirs` 增加**取值容错**（字符串按分隔符拆分、非数组回退默认值并提示；数组值 trim/去空/去重），片段层再加非数组防御。
- **设置即时生效收口（本版新增）**：`compilerId` / `masterPath` / `compilerPrograms` 变更 → 状态栏 `Compiler:` 刷新 + 按新编译器重生成编译数据库 + DB 变化且已打开源文件时**重启 clangd**（不提供关闭项）；`build.persistLog` 变更 → 弹提醒 + 一键重载窗口；`clangd.enabled` 关闭 → 提醒既有片段仍会被 clangd 读取（可打开配置）。

规模（0.8.131 时点）：命令 105 → **106** 项、设置 74 → **76** 项（7 分区 + 中英 nls）、视图 5 个；分层回归 `contract 2/2`、`unit 155 脚本 FAIL=0 SKIP=1`、`e2e 4/4`、`visual 24 pass`、`perf 13 项 0 fail`、`pack 14 pass`。

> 上一版（0.8.130）的 post-build 输出实时化/心跳/可选超时、宽限改「安静期 + 上限」、并行上限 64 → 32、Problems 诊断批量发布、clangd 补全与配置治理见 [0.8.130 发布说明](./0.8.130.md)。

## 工作区检测开销治理（本版新增）

- **问题**（用户反馈）：编译期出现进程暴增、CPU 冲 100%，两三个文件的工程也明显比 Code::Blocks 慢；工作区越大越明显。
- **根因**：`.cbp` 文件事件（新增/删除）每次都触发**工作区级全量扫描**——每次事件固定起 2 个 ripgrep 进程，成本与工作区文件数成正比；扫描未排除 `Output`/`obj`/`bin`/`node_modules`/`.git` 等重目录，也没有缓存与单飞，窗口激活/会话恢复时可能叠加多次。
- **修复**：

| 项 | 现状 | 修复 |
| --- | --- | --- |
| `.cbp` 事件 | 每次新增/删除都触发全工作区扫描（2 个 ripgrep 进程） | 改为**增量登记**：只维护已登记工程文件集合，不再扫描 |
| 全量扫描 | 无 exclude、无缓存、无单飞 | 合并为**一次** `findFiles('**/*.{cbp,workspace}')`，显式 exclude 重目录（`Output`/`obj`/`bin`/`node_modules`/`.git`，并把 `files.exclude` 默认项写回），加 **30s 结果缓存 + 单飞**；宿主实测（36 工程 / 36,829 文件）激活期扫描 **211ms → 89ms** |
| 大工作区自动打开 | 检测到多少就多选多少（默认全选） | 新设置 `codeblocks.detect.autoOpen`（`all`/`single`/`off`，默认 `all`）与 `codeblocks.detect.autoOpenThreshold`（默认 `20`）：未打开工程数超阈值不再自动弹多选（仅状态栏入口 + 输出通道提示），并限制会话恢复的工程数；多选**默认只勾选最近使用/活动工程** |
| 兜底符号索引 | 多工程每次都全量重解析 | `SymbolIndex` 增加「mtime + size」单文件缓存：只重解析变化文件（`stats()` 可读 parsed/reused） |
| 排查手段 | — | 新命令 `Code::Blocks: Workspace Scan Report`：输出扫描耗时、工程数、工程目录数、当前 ripgrep 并发与「单工程工作区」建议 |

- 文档：使用说明 §5 新增「检测与自动打开可配置」与「排查工作区扫描开销」小节，§13.5 设置表新增两行。
- 回归：新增 `tests/test-project-detect-scan.js`（增量登记不再触发 `findFiles`、单次合并扫描与 exclude、阈值与 `autoOpen=single/off` 行为、多选不全选、扫描报告输出；每个配置场景单起子进程）。

## clangd 设置改动立即生效（本版新增）

用户反馈：在设置 `codeblocks.clangd.suppressedWarnings` 里加了 `-Wempty-body`，`%LocalAppData%\clangd\config.yaml` 里却没有这一项。排查确认**写入链路本身没问题**（设置值原样进 `Diagnostics.Suppress`），问题出在触发与取值：

| 项 | 根因 | 修复 |
| --- | --- | --- |
| 改设置不生效 | `activate()` 只监听 `clangd.path` / 少数 `codeblocks.*` 键，**没有任何 `codeblocks.clangd.*` 监听** ⇒ 只有打开工程 / 切换活动工程 / 手动 `Generate compile_commands.json` 才重写 `config.yaml`（改完设置看文件仍是旧内容） | 监听 `codeblocks.clangd` 设置变化 → 复用既有去抖 + 单飞重新生成（clangd 自动重载配置，无需重启/重载窗口），输出通道留痕；未打开工程时跳过（作用域未知），下次打开工程按新设置生成 |
| 生成中的改动被丢弃 | `runClangdGeneration` 单飞时**直接丢弃**后来的请求（恰逢生成中改设置会静默失效） | 改为「待重跑」合并：生成结束若期间有请求则补跑一次（交互式标记一并保留） |
| 值写成字符串 ⇒ 压制项全废 | `for (const w of s.suppressedWarnings)` 对字符串**按字符**迭代 ⇒ 片段写出 `- -`、`- W`… 单字符项（`-Wempty-body` 永不出现） | 入口容错：字符串按逗号/分号/空白拆分、非数组回退设置默认值，并在输出通道提示 `取值类型不正确`；数组值 trim/去空/去重；`clangd.ts` 片段层再加非数组防御（不写该键、绝不按字符迭代） |

- 覆盖：新增 `tests/test-clangd-settings-sync.js`（31 断言：设置变更后自动重新生成、字符串/非数组容错与提示、去重与 trim、连续变更最终值必达、无工程时跳过、重开工程按新设置生成；G1 编译器设置变更 → 状态栏刷新 + 按新编译器重生成数据库 + 无条件重启 clangd；G3/G4 提醒弹窗文案与按钮动作、值未变化与无片段时静默）；`tests/_harness/vscodeMock.js` 增加 `emitConfigChange` 派发设置变更事件；`tests/test-clangd-config.js` 101 → **112 断言**（含片段层非数组防御与接线静态断言）。
- 文档：[使用说明 §9](../使用说明.md) 写明自动重新生成、取值容错与「改编译器立即生效」，§13.1/§13.4 设置表标注生效时机，FAQ 新增 4 条（压制项没生效 / 改编译器没生效 / 关闭 clangd 后片段仍在 / persistLog 需重载）；手工验收清单 +5 条。

## 设置即时生效收口（本版新增）

用户要求排查"还有哪些扩展配置改了不会立即生效"，逐项审计 76 个设置读点（15 个键已监听、其余靠调用时读取天然即时、激活期读点仅 2 处），确认 3 处真实缺口并按确认范围修复（`asmUsesCompilerV1` / `responseFile` 对编译数据库的微影响评估为收益低，**不做**）：

| 项 | 现状 | 修复 |
| --- | --- | --- |
| **G1** 改编译器不生效 | 改 `codeblocks.compilerId` / `masterPath` / `compilerPrograms` 后：编译数据库（含编译命令、`--target`、系统头 `-isystem`）与用户配置片段**都不重新生成**，状态栏 `Compiler:` 也不刷新（`updateCompilerStatusBar()` 只在工程事件/探测命令里调用）；`Detect Compilers` 连写 3 个设置同样只更新状态栏 | 新增监听这三项设置 → `updateCompilerStatusBar()` + 有工程时输出通道留痕并按新设置重新生成（复用既有去抖 + 单飞 + pending 合并）；生成后若编译数据库**实际变化**且已打开 C/C++ 文件则**重启 clangd**。重启原因区分「切换活动工程」（受 `clangd.restartOnActiveProjectSwitch` 控制）与「编译器设置变化」（**无条件**，不提供关闭项）；未打开工程时只刷新状态栏 |
| **G3** `build.persistLog` 需重载窗口 | 输出通道类型（普通输出通道 ⇄ 日志通道）在激活期创建，中途切换需重建通道且会清空当前输出 ⇒ 只能重载窗口生效（原先只有设置表里一行文字说明，改了没反应容易以为功能坏了） | 变更时弹提醒（含当前为「开启/关闭」的描述）+ 按钮「重载窗口 / 稍后」，选前者执行 `workbench.action.reloadWindow` |
| **G4** 关闭 clangd 集成后旧片段仍生效 | `clangd.enabled=false` 只让扩展停止生成/更新用户级 `config.yaml`，**已写入的片段仍会被 clangd 读取**（继续指向旧编译数据库），且片段属于用户级配置（优先级高于项目 `.clangd`）⇒ 关掉后旧工程的红波浪线/补全配置照旧 | 由「开 → 关」时弹提醒（说明片段仍生效 + 按钮「打开 clangd 配置 / 稍后」打开 `%LocalAppData%\clangd\config.yaml`）；用模块级记录的上次取值判断方向，值未变化不重复弹窗；从未写过片段（无遗留）时静默。不自动清理：片段是用户级配置，且当前工程的片段会被「清理失效片段」命令判为有效而保留 |

- 覆盖：`tests/test-clangd-settings-sync.js` 18 → **31 断言**（新增 13 条：G1 全链路 + G3/G4 弹窗与静默场景）；`tests/test-clangd-config.js` 108 → **112 断言**（新增 G1/G3/G4 的 dist 接线静态断言）。
