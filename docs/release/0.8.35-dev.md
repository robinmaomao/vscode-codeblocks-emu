# 0.8.35-dev —— 每目标编译器（混合编译器工程对齐）

第十三轮 X1：`CompilerFactory::GetCompiler(target->GetCompilerID())` 对齐。

## 背景

Code::Blocks 在构建链路的多个环节都按**目标声明的编译器**工作，而扩展此前把
`BuildEngine` 绑定在单个编译器实例上（取项目默认编译器）。对于「一个工程里
Debug 用 GCC、Release 用 Clang」这类混合编译器工程，模板、开关、程序路径、
错误/警告正则都会用错。

## 改动

- `src/build/buildEngine.ts`
  - 构造函数新增可选参数 `resolveCompiler?: (id: string) => Compiler`；
  - 新增 `switchCompiler(target)`：解析 `target.compilerId || project.compilerId`，
    命中且不同于当前实例时切换 `this.compiler`，并同步重建 `OutputParser`
    （错误/警告正则随编译器切换）；resolver 未命中时保持当前编译器不崩溃；
  - 六处切换点（对齐 CB 的 593/634/722/965/1011/1167）：
    1. `build()` 项目级 pre-build 前（首目标上下文）；
    2. `build()` 每目标 Banner 打印前（compiler 显示名按目标）；
    3. `build()` 项目级 post-build 前（末目标上下文）；
    4. `buildTarget()` 开头（生成 CommandGenerator 前）；
    5. `compileFile()` / `cleanFile()` / `cleanTarget()`（单文件编译/Clean 路径）；
    6. `collectCompileCommands()` 逐目标循环内（`compile_commands.json` 每目标用对编译器）。
- `src/extension.ts`：4 处 `new BuildEngine(...)` 追加 `(id) => getCompiler(id)` 解析器。
- `test-project/headless-build-check.js`：2 处构造追加同一解析器。
- `test-mixed-compiler.js`（新增）：临时 .cbp 双目标（ccA/ccB）+ 两个伪造编译器，
  断言 Debug 命令含 `gccA.exe`、Release 命令含 `gccB.exe`、遍历后引擎停在末目标
  编译器、resolver 未命中不崩溃 —— 5 pass。
