# 0.8.132：中英文界面语言切换（i18n 设施 + 静态贡献全量本地化 + 运行时文案全覆盖）

> 发布日期：2026-10-22 ｜ 正式版（0.8.131 → 0.8.132 里程碑汇总）
> 约定与批次台账见 [国际化](../国际化.md)。

## 概述

扩展此前是「中英混杂」：命令标题是硬编码英文、设置描述/视图欢迎语/全部运行时文案（弹窗、QuickPick、状态栏、WebView 面板）是硬编码中文，仅 7 个设置分区标题走 nls。本批次引入完整的双语机制：

- **静态贡献**（命令标题、设置描述与枚举说明、视图名、容器名、欢迎语、调试器片段描述、`displayName`/`description`）全量改 `%key%` 占位符，英文放 `package.nls.json`（默认）、中文放 `package.nls.zh-cn.json` —— 跟随 VS Code 显示语言，重载窗口生效；
- **运行时文案**由新设置 `codeblocks.ui.language`（`auto` / `en` / `zh-cn`，默认 `auto`）控制，**即时生效**，不依赖窗口重载；
- 新命令 `Code::Blocks: Switch UI Language…`（`codeblocks.ui.switchLanguage`）提供三态切换与「重载窗口」入口。

规模：命令 106 → **107** 项、设置 76 → **77** 项（7 分区 + 中英 nls）、nls 键 **212** 个（英文/中文各一份）、
运行时迁移点 **1123** 处 / 词条 **1072** 条（含批次 2 的运行时文案全覆盖；批次 1 时为 290 / 239）。

## 一、i18n 设施（本版新增）

| 新增 | 说明 |
| --- | --- |
| `src/i18n/core.ts` | 纯逻辑：`resolveLanguage(setting, envLanguage)`（`auto` + 显示语言 → `zh-cn`/`en`，非法值按 `auto`）、`formatSource`（`{0}`/`{1}` 占位符；缺参保留占位符原样）、`lookupTemplate`、`translate` |
| `src/i18n/index.ts` | 扩展入口：`t(source, ...args)`、`uiLanguage()`、`refreshUiLanguage()`、`translationsTable()`；语言进程内缓存（热路径不读配置），设置变更/激活时刷新 |
| `src/i18n/strings.zh-cn.json` | 词条表（**英文源串为键** → 中文译义），随 `resolveJsonModule` 内联进 dist / bundle，无运行时文件 IO |
| `tsconfig.json` | 新增 `resolveJsonModule`（导入 JSON 词条） |

设计取舍：**不使用** `vscode.l10n.t()` —— 标准机制只能跟随显示语言，无法满足「设置级强制切换」；
字典仍按 l10n bundle 的「源串为键」风格组织，后续可平滑对接标准流程。命名空间调用 `i18n.t(...)`
（文件内已有多个名为 `t` 的局部变量），消息模板禁止内插 `${}`（守卫拦截）。

  5 视图名、2 容器标题、1 条视图欢迎语、2 条调试器片段描述、`displayName` / `description` 全部改 `%key%`；
- 键命名与约定见 [国际化 §3](../国际化.md)；
- 中文原文逐条保留为中文 nls 值（`markdownDescription` 的锚点、`command:` 链接、`%APPDATA%` 等字面量原样）；
  英文为**新写**（68 条设置描述此前只有中文）；
- 覆盖矩阵命令/视图标题按中文解析后写入（文档面向中文读者）。

> 二级占位符（nls 值本身是 `%key%`）会导致原样显示 `%key%` —— 本版修掉了新设置引入的这一处
> （`codeblocks.ui.language` 一度被包成 `configuration.codeblocks.ui.language.*`），并加入守卫。

## 三、`ui.language` 设置与切换命令

- **设置** `codeblocks.ui.language`：`enum: [auto, en, zh-cn]`，默认 `auto`，`scope: window`，描述与枚举说明走 nls；
- **命令** `codeblocks.ui.switchLanguage`：QuickPick 三态（标签用原生语言名 `English` / `中文（简体）`，附当前项「当前 / Current」标记）→ 写全局设置 → 按**新语言**提示结果并给出「重载窗口」按钮（说明命令标题/设置界面需重载才跟随显示语言）；
- **即时生效**：监听 `codeblocks.ui.language` → `refreshUiLanguage()` + 刷新状态栏 + 刷新已打开面板**标题**（面板正文在下次打开时按新语言渲染；有意不重渲染 HTML，避免丢弃工程属性面板未保存的编辑）。

### 2E 的关键设计：`logT()` 统一构建日志

此前构建日志用 `msg(zh, en)` 双写，`codeblocks.log.english` 决定取哪一侧。批次 2 引入
`logT('英文源串', ...args)`：

```
log.english = true   → 恒英文（对齐 Code::Blocks 原文，忽略 ui.language）
log.english = false  → 跟随 codeblocks.ui.language（中文走词条表，英文回退源串）
```

`src/build/**` 的 81 处日志、`extension.ts` 中带 `[Code::Blocks]` 前缀的 90+ 处输出通道行全部改走 `logT`，
并新增守卫：`src/build/**` 不得再直接调用 `msg()`（`tests/test-i18n-dict.js` S8b）。`msg()` 仅保留给
「英文侧是 CB 原文、中文侧是通知文案」的 3 处构建结果 toast。

### 2A 的关键设计：WebView 面板「源级插桩」而非「渲染后替换」

第一版实现对渲染后的 HTML 整段做中英替换，结果**误伤工程数据**（fixture 备注被半翻译成「5 个Build targets」）。
改为在**源码模板**上把中文文本包成 `i18n.tr('中文原文')`（含内联 `<style>`/`<script>` 文本，跳过 HTML/CSS/JS 注释），
中文即键、`strings.zh-cn.webview.json` 做中文→英文反查：不碰数据，也不需要 WebView 内判语言。

### 2F 的三类手工处理（codemod 不能自动覆盖）

1. **模板内插里的条件分支**：`` `${cond ? '中文A' : '中文B'}` `` → `cond ? i18n.t('A') : i18n.t('B')`（每个分支独立词条）；
2. **对象字面量键**：`filters: { '源文件': [...] }` → `filters: { [i18n.t('Source files')]: [...] }`（计算键）；
3. **占位符语序**：英文可按英文语序重排 `{N}`（如 `Remove file "{1}" from project "{0}"?`），词条集合一致即可。

## 七、已知限制

1. 命令标题与设置界面**无法运行时切换**（VS Code 只按显示语言解析 `%key%`）→ `ui.language` 与显示语言不一致时混语言，切换命令提示中已说明；
2. 已打开面板的正文/标签在重开后才按新语言渲染（只刷新标题，避免丢弃未保存编辑）；
3. `zh-tw` / `zh-hk` 在 `auto` 下按 `zh-cn` 处理；
4. **一键一值**：同一英文源串只能有一个中文译义；需要两种中文表述时用不同英文源串区分
   （如快捷键面板的 `Clean` → `Clean（清理）` vs 清理确认按钮的 `Clean now` → `清理`）；
5. **构建日志双开关**：`codeblocks.log.english=true` 时构建日志恒英文（对齐 CB 原文，忽略 `ui.language`），
   其余界面文案仍跟随 `ui.language` —— 两者语义不同，属有意设计（设置说明已写清）。
