# 0.8.104-dev

> 绝对路径 Unit 规范化（对齐 `cbProject::AddFile`）：同盘绝对路径相对化、跨盘/UNC 保留——修复绝对路径文件被误判「源缺失」的伪 WARNING 与强制重链（F5b；F5a 的判定修正由其自然覆盖）。

## 背景

- 扩展 parser 此前 `absolutePath = unixJoin(basePath, rel)` 对绝对 `rel` 拼接错误（`<项目目录>/C:/...`），导致绝对路径 Unit 的 `existsSync` 恒 false → F4/F4a 引入的缺失源判定将其误判为「源缺失」，每次构建输出伪 `WARNING: Can't read file's timestamp` + 强制重链（该文件此前也因 `isUpToDate` 恒"最新"而从不编译）。
- CB 的做法（cbproject.cpp:880-904）：同盘绝对路径 `MakeRelativeTo(projectBasePath)` 相对化（`..` 前缀），跨盘/UNC 保留绝对（`pf->file` 原样）。

## 修复（F5b）

- `parseUnits` 对齐 CB：`path.isAbsolute(rel)` 时比较卷根——同盘（含无卷信息）→ `path.relative` 相对化（盘符比较大小写不敏感）；跨盘/UNC → 保留绝对。
- `absolutePath`：绝对 `rel` 直接取原路径（不再 base+绝对 拼接）；其余仍 `unixJoin`。
- 下游消费者（对象路径 `objectPathRelative` 的 isAbsolute 分支、`relativeToCommonTopLevelPath` 重算、writer）均随之正确。
- **F5a**：绝对路径文件从此 `absolutePath` 正确 → `missingSourceFiles`/F4a 的 `existsSync` 与 `isUpToDate` 均判定正确，伪 WARNING 消除——F5a 的判定修正由 F5b 自然覆盖。

## 验证

- 新增 `tests/test-abs-unit-path.js`（**9 断言**）：A 同盘绝对路径 → 相对化 + 首次构建成功（编译 absmain.c + 链接）+ 二次构建 `Nothing to be done`（无伪 WARNING）；B 跨盘（Z: 模拟）→ 保留绝对、absolutePath 无 base 拼接；C UNC → 保留绝对。
- 探针 `.cb-tools/linkinput-abs.js` 修复前后对照（修复前 `absolutePath exists=false` + 伪 WARNING；修复后相对化 + 正常）。
