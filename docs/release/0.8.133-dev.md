# 0.8.133-dev：构建日志补齐 Code::Blocks 产物体积行

> 开发版记录（`package.json` 版本仍为 0.8.132，发布时统一升版与刷新版本标记）。
> 逐条对齐依据见 [对齐对照](../对齐对照.md)；日志约定见 [国际化](../国际化.md) §2「三种运行时 API」。

## 概述

Code::Blocks 在**链接成功后**会打印产物体积行：

```
Output file is Output\bin\app.rv32 with size 478.53 KB
```

扩展此前只打印自己设计的完成式摘要行（`✔️ [Linked] Output\bin\app.rv32 (1.2s)`），**纯 CB 日志模式（`codeblocks.build.plainCbLog`）下更是完全没有成功提示** ——
从 Code::Blocks 迁过来、习惯用该行确认产物路径与体积的用户会以为链接没有执行。本版把这一行补齐。

## 一、实现（对齐 CB `CompilerGCC::OnJobEnd`）

CB 的实现（`plugins/compilergcc/compilergcc.cpp:3956-4001`）：链接进程（`cmd->isLink`，由 `GetTargetLinkCommands`
插入的 `COMPILER_WAIT_LINK` 标记）退出码为 0 时，打开 `target->GetOutputFilename()`（宏已替换、分隔符保持原生）取长度并按档位格式化：

| 文件大小 | 单位 | 显示 |
| --- | --- | --- |
| `< 1024` | `bytes`（小写） | `512.00 bytes` |
| `< 1048576` | `KB` | `478.53 KB` |
| `≥ 1048576` | `MB` | `1.50 MB` |

要点：**没有 GB 档**（≥1 MiB 一律 MB）、**一律两位小数**（不足 1 KB 也是 `512.00 bytes`）、**判档用 `<`**（1024 字节 ⇒ `1.00 KB`）；
产物打不开时 CB 什么都不打印。

扩展侧新增纯逻辑模块 `src/build/outputFileInfo.ts`：`formatCbFileSize(bytes)`、`outputFileSizeText(absPath)`（缺失/非普通文件 → `undefined`），
由 `BuildEngine.reportOutputFile()` 在**链接成功**与**静态库打包成功**后各调用一次：

- 位置与 CB 一致：链接/打包命令输出之后、`✔️ [Linked]` / `✔️ [Archived]` 摘要行之前，**post-build 脚本之前**（脚本若改产物，行内体积仍是链接当时的体积）；
- 路径用 `expandedOutputFilename(target)`（对齐 CB 打印的配置值，含平台扩展名）/ `computeStaticOutput(...)`（静态库真实 `.a` 路径）；
- **两种日志模式都输出**：plain 模式本就是 CB 原文基线（此前缺这一行），enhanced 模式保留带耗时与 Emoji 的摘要行；
- 文案走 `logT()`，`codeblocks.log.english=true` 时恒英文、否则跟随 `codeblocks.ui.language`（中文为「输出文件为 {0}，大小 {1}」）。
