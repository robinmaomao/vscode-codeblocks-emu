## 编译/链接全链路对齐（D1-D12）

对扩展与 Code::Blocks（directcommands.cpp / compilergcc.cpp 状态机 / compilercommandgenerator.cpp / projectloader.cpp）逐项复核后实施的 12 项对齐：

| 项 | 内容 |
|---|---|
| D1 | 外部依赖 `external_deps`/`additional_output` 解析 + 过期检查：链接库/外部依赖比输出新 → 强制重链接；缺失依赖输出 WARNING（含「目标已最新」路径，对齐 CB 先查外部依赖再跳过的顺序） |
| D2 | 项目级 pre/post build **每次构建各执行一次**（pre 用第一个目标上下文、post 用最后一个）；目标级脚本按目标执行；虚拟目标单引擎构建 |
| D3 | 读取 default.conf 编译器全局搜索目录（include_dirs/library_dirs/res_include_dirs/link_libs），追加在项目/目标目录之后 |
| D4 | Clean 时动态库额外删除 import 库；CommandsOnly 目标不删输出 |
| D5/D11 | 链接对象收集按文件编译器程序检查，缺失时跳过并输出 "Skipping file (no compiler program set)"；无链接器程序输出 "Skipping linking" |
| D6 | 输出文件名宏展开（$(VAR) 生效于时间戳判断/Clean/静态库命名） |
| D7 | 项目自定义变量（`codeblocks_project_custom_variables`）解析 + 迭代替换展开，作用于脚本/deps 扫描目录/命令目录 |
| D8 | 零可链接对象文件时 "Linking stage skipped"，不执行空链接 |
| D9 | 源文件时间戳读取失败回退编译（对齐 IsObjectOutdated fall-back） |
| D10 | 响应文件命名对齐 CB：`对象目录/源文件名.respFile`、`对象输出目录/<目标>_link.respFile` |
| D12 | windres 空格 bug 修复：资源文件短路径（GetShortPath）；Use83Paths 目录短路径 |

## 增量构建行为对齐（F1-F3，实测发现）

| 项 | 内容 |
|---|---|
| F1 | **post-build 门控**：项目 post-build 仅在最后一个目标实际产生命令（编译/链接/打包）或 `alwaysRunPostBuildSteps` 时执行 —— Rebuild 后增量构建不再误跑 postbuild 脚本 |
| F2 | Banner 移到项目 pre-build 之后、每目标构建前（对齐 bsTargetPreBuild）；文案对齐 CB `-------------- Build: ... --------------`；编译器显示名取 default.conf NAME |
| F3 | 路径宏（`$(PROJECT_DIR)` 等）Windows 下原生反斜杠 + 大写盘符，消除 `e:/...\output` 混合形态 |
