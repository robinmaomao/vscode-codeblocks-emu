# 0.8.100-dev

> 编译条目计数强制重链：对齐 Code::Blocks `GetTargetCompileCommands:585`——`compile=1` 但对象永不产生的文件（自定义空命令 / 工具未匹配）**每次构建**都强制重链接 / 重新打包。

## 背景（用户实测反馈）

- 用户 RISC-V 工程中 `custom.ld` 配置为：
  ```xml
  <Unit filename="custom.ld">
      <Option compile="1" />
      <Option compiler="riscv32-elf" use="1" buildCommand=" " />
      <Option compiler="riscv32-none-elf" use="1" buildCommand=" " />
  </Unit>
  ```
- 实测 Code::Blocks 修改 `custom.ld` 后增量编译**会重链接**；扩展此前输出 `Nothing to be done`（编译链将空白命令判为 no-command 跳过、链接输入白名单又跳过带自定义命令的文件 → 双重落空）。

## CB 机制取证（directcommands.cpp 逐行）

1. `compile="1"` → `custom.ld` 进入编译文件列表（`GetProjectFilesSortedByWeight(target, true, false)`，:545）；
2. `IsObjectOutdated`（:1148）：对象 `Output/obj/custom.o` 永不产生 → `if (!timeObj) return true`（:1175）→ **每次构建都判定过期**；
3. `GetCompileFileCommand`（:263）：`useCustomBuildCommand` → 命令 = `" "`（空白≠空，未触发 :349 的空命令跳过）→ 默认「完整命令行」日志 → `ret.Add(COMPILER_SIMPLE_LOG + " ")` → **至少产生 1 个条目**；无自定义命令时同样产生 "Skipping file (no compiler program set)" 条目（:350）；
4. `GetTargetCompileCommands` 末尾（:585）：`GetLinkCommands(target, ret.GetCount() != counter)` → **编译阶段产生过任何条目即 force=true**；
5. `GetTargetLinkCommands(target, force=true)` 跳过全部时间戳检查 → 生成链接命令 → 重链接；
6. `compilergcc.cpp:2627-2633`：`hasCommands = cmds.GetCount()`（含日志行）→ 不输出 "Target is up to date."，post-build 照跑。

即 CB 在该类工程下**每次增量构建都重链接**（条目计数把日志行也计入的实现副作用，`logging=clogNone` 时不触发）。

## 修复（对齐，非保护性差异）

- `buildEngine` 编译循环新增 `staleNoopFiles`：`compile=true` 且 `makeCompileUnit` 返回 `no-command` / `not-compilable` 的文件，按 CB `IsObjectOutdated` 语义判定过期（对象缺失即过期；`rebuild` 恒真；`autoGeneratedBy` 与 `compilerVar` 空不产生条目，对齐 CB 不强制）。
- 三处接入：链接 `forceLink`、静态库 `forceArchive`、「Nothing to be done」早退分支（条目存在则不再早退）。
- 触发日志：`目标 "Debug" 含 N 个过期且无可执行命令的编译文件（custom.ld），强制链接（对齐 CB 条目计数）`（重新打包同款）。
- `linkInputsOutdated`（0.8.96-dev 的 mtime 保护性增强）保持不变：仅覆盖 compile=false 的普通链接输入；带自定义命令（use=1）文件改由条目计数规则负责，注释已同步更正。

## 验证

- `tests/test-link-input-outdated.js` 11→**16 断言**：新增用户工程原样场景（compile=1 + 自定义空命令）——C11 首次构建、C12 **无修改也重链接**（CB 条目计数）、C13 改动仍重链、C14 无自定义命令（Skipping 条目）仍强制、C15 静态库无修改也重新打包；既有 C4/C10（compile=false 无改动 → Nothing to be done）回归不变。
- 全量 `TOTAL=110 FAIL=0 SKIP=1`；`tsc` 0 错误。

## 文档

- `使用说明.md`：§构建行为新增「编译条目计数强制重链」条目、§13.2 `linkInputExtensions` 行补充适用范围、FAQ `.ld` 分两种情形重写；`对齐对照.md`「链接输入（.ld 等）新鲜度」行更正为 CB 双路机制与扩展复刻；版本串更新。

# 0.8.101-dev

> 0.8.100-dev 条目计数强制的补全与设置健壮性：真实自定义命令的编译单元同样强制重链/重新打包；`linkInputExtensions` 设置容错；compile=false 的自定义命令文件恢复 mtime 触发。

## 背景（上轮遗留 + 核查）

0.8.100-dev 已复刻 CB「编译条目计数」强制（`GetTargetCompileCommands:585`），但仅覆盖「无可执行命令」的编译文件（自定义空命令 / 工具未匹配）；真实自定义命令文件（如 `buildCommand="cmd /c ..."`）在 CB 中命令本身也是条目 → 每次构建都重链，扩展此前仍 `链接已是最新`。同时设置误配（字符串 / `*.ld` / 非数组值）会静默失效，compile=false + 自定义命令的链接输入不触发 mtime 增强。

## 修复

- **F1 条目计数补全**：链接/静态库打包的 force 增加 `totalUnits > 0`（编译阶段产生过任何单元即强制，对齐 CB「ret 条目计数」；普通工程零影响——对象已更新本就强制）。真实自定义命令文件（对象永不产生）由此每次构建都重链接/重新打包，与 CB 一致。
- **F2 设置容错**（`linkInputExtensions()`）：字符串（`'ld, lds'` / `'.ld'` / `'*.ld'`）按 `;`/`,`/空白拆分；`true`/数字/对象/空串等误配回退默认列表（避免静默关闭）；规范化兼容 `*.` 前缀与去重；仅显式空数组 `[]` 关闭（文档约定）。`package.json` 描述同步（格式说明 + 作用域）。
- **F3a 边界一致性**：`linkInputsOutdated` 的自定义命令跳过条件改为 `use && file.compile`——compile=1 的仍由条目计数规则负责（避免双重计入/双日志），compile=false 的即使带自定义命令也按 mtime 触发（命令不执行、CB 亦无动作，属保护性增强）。

## 验证

- `tests/test-link-input-outdated.js` 16→**22 断言**：C16 字符串 `"ld, lds"`、C17 `["*.ld"]`、C18 误配 `true` 回退默认、C19 compile=false+自定义命令 mtime 触发（F3a）、C20/C21 compile=1+真实自定义命令无修改也重链/重新打包（F1）；既有 C1-C15 回归不变。
- 探针 `.cb-tools/linkinput-probe.js` P1-P9 + P3b 全部符合预期。
- 全量 `TOTAL=110 FAIL=0 SKIP=1`；`tsc` 0 错误。

## 文档

- `使用说明.md`：§构建行为条目（真实命令 + 空命令全覆盖）、§13.2 行（格式/作用域）、FAQ（含带自定义命令者）；`对齐对照.md` 行扩展为「staleNoopFiles + totalUnits>0」双复刻；`README.md`/版本串更新。

# 0.8.109-dev

> UI 核查 N2（方案 C）：`Run` / 自定义工具的集成终端改为**同名先弃后建**——同一名称始终只有一个终端标签，每次运行输出全新。

# 0.8.125-dev

> A2 惰性命令生成（用户确认执行）：先判过期、仅对过期/强制单元生成编译命令 —— 对齐
> `GetTargetCompileCommands`「force || IsObjectOutdated → GetCompileFileCommand」（directcommands.cpp:558），
> 消除 up-to-date 文件「先生成后丢弃」的浪费。**R4（ccache/sccache 前缀）未选（暂缓）**。

## 背景（报告 §7.2）

- CB 基线：`GetTargetCompileCommands`（directcommands.cpp:536-589）逐个文件**先判 `IsObjectOutdated`**，
  只有过期文件才调用 `GetCompileFileCommand` 生成命令；up-to-date 文件仅在有错误时补 WARNING。
- 扩展现状（改动前）：收集循环先 `makeCompileUnit`（完整 `renderTemplate`：宏展开/目录合并/引号/反引号）
  再 `isUpToDate` —— up-to-date 文件的命令生成完即被丢弃（只打 `[Skipping]`），属**既有语义偏差 + 纯浪费**。
- 实测（0.8.120 M0，大型 RISC-V 工程 487 文件/248 单元）：noop 热构建 1.13s 中命令生成浪费 ≈0.25s；
  增量改 1 文件 6.46s 中 ≈0.31s；预计 noop -22%、增量 -5%、rebuild 无变化。

## 变更（`src/build/buildEngine.ts`）

- 新增私有 `isCompileCandidate(target, file)`：文件是否可能产生编译命令（自定义命令 / 可编译类型 /
  PCH 头文件 / 生成器文件）——`makeCompileUnit` 与收集循环**共用同一分类条件**（防漂移）。
- 收集循环（1b）重排为：**候选分类 → 过期判定 → 仅过期/强制生成命令**：
  - 非候选文件：保持原「条目计数」路径（过期 → `staleNoopFiles` 强制重链），不触发命令生成；
  - up-to-date 候选：直接跳过（保留 `[Skipping] ... (up to date)` 日志与 `skippedCount`），**不再生成命令**；
  - 过期/强制候选：生成命令（对齐 `GetCompileFileCommand`）；`not-compilable`/`no-command` 分支
    此时必然过期/强制 → 条目计数条件等价简化为 `!autoGeneratedBy`（原 `rebuild || !isUpToDate` 已由外层保证）。
- 语义保留清单（逐项核对）：`staleNoopFiles` 强制重链、`missingSourceFiles` WARNING、
  `no-command` debug 日志（仅过期/强制分支，CB 同）、PCH `.gch` 对象路径、deferredUnits 延后、
  verbose 日志顺序、条目计数强制链接（编译产生条目 → 链接命令生成）。
- **已知微差（有意）**：up-to-date 且命令本为空的候选文件（如自定义空命令 `buildCommand=" "`、
  缺 WINDRES 的资源文件）——由原「debug: no compiler program set」改为「`[Skipping] … (up to date)`」

  既不生成命令也不打印，扩展此变更方向与 CB 一致。

# 0.8.128-dev

> 汇编注释标记可配置：默认 `//`（预处理的 `.S` 安全）；
> 新设置 `codeblocks.editor.asmHashComment` 开启后动态还原 GAS 原生 `#`（即时生效）。

## 变更

- **默认值**：`language-configurations/asm.json` 行注释标记 `#` → `//`（块注释保持 C 风格）。
- **新设置** `codeblocks.editor.asmHashComment`（boolean，默认 `false`）：
  开启后经 `vscode.languages.setLanguageConfiguration('asm', …)` **动态注册**行注释 `#`
  （VS Code 中扩展动态注册优先级 100 > 静态文件配置 50；仅覆盖 `comments`，括号/自动闭合等仍沿用静态配置）；
  关闭即释放 Disposable 自动回退静态 `//`；**修改即时生效**（无需重载窗口，`Ctrl+/`、`Ctrl+K Ctrl+C/U`、命令面板等全部注释路径一致）。
- 新纯模块 `src/tools/asmCommentConfig.ts`（`ASM_LANGUAGE_ID` / `ASM_HASH_COMMENT_SETTING` / `asmCommentsRule()`）；
  `src/extension.ts` 接线：激活时应用 + `onDidChangeConfiguration` 监听 + `context.subscriptions` 释放。
- **实测依据**（本机工具链）：原生 `.s` 经 GAS 直接汇编时 `//` 在 RISC-V（binutils 2.28 / 2.43）整行报 junk、行尾报 illegal operands，x86 行尾报 invalid char；`.S` 经 cpp 预处理则 `//` / `#` 均安全——故默认 `//` + 可切回 `#` 并存。
