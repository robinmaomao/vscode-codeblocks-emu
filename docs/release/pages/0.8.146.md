# Code::Blocks for VS Code 0.8.146

> 发布日期：2026-11-10 ｜ 修复版（0.8.145 → 0.8.146）

## 概述

🩹 本版修复 **clangd `#ifdef` 关闭区域不再变暗**（inactive regions 装饰失效）。

- 🐞 **现象**：`config.h` 里 `#define FUNC_BTHID_EN 0` 等宏关闭的功能代码（`config.c` 中的 `#if FUNC_BTHID_EN` 块）**不变暗**，保存头文件也不刷新；关闭/重开文件或重载窗口才恢复。
- 🔍 **根因**：clangd 服务端一直在正常发送 `textDocument/inactiveRegions`；失效点在 vscode-clangd 的装饰生命周期——语言客户端「原地重启」时 Feature 被复用，`clear()` 只 `dispose()` 装饰类型却不清空字段，之后的重建条件 `if (!this.decorationType)` 永远为假 ⇒ 装饰永不重建。
- 🧭 **为何才出现**：0.8.144 为修复 `clangd.applyFix` 重复注册，把自动重启从「`clangd.restart` 命令（重建全新客户端）」改为「`LanguageClient.restart()`（复用同一客户端与 Feature）」，第一次踩中该缺陷；0.8.143 及更早版本不受影响。
- 🛠️ **修复**：本扩展监听 clangd 客户端状态，停止/启动过渡时清空装饰类型，进入 Running 后立即重建并重新应用已收到的区域；不改 clangd 扩展本体、不改任何用户设置。

规模（0.8.146 时点）：命令 **113**、设置 **85**、视图 **6**、快捷键 **34**。

## 🐞 修复细节

- 客户端 `Stopped` / `Starting`：`dispose()` 旧装饰类型并**置空**，同时清空已缓存的区域，避免把上一轮宏状态画到新代码上。
- 客户端 `Running`：装饰类型缺失（被清空或从未创建）时重建一次，并重新应用到当前可见的 C/C++ 编辑器。
- 本扩展每次重启 clangd（打开工程 / 切换活动工程 / 改编译器）后立刻触发一次修复；用户手动执行 clangd 的 Restart 命令时通过低频轮询发现新客户端。
- 兼容性：按运行时形状探测 clangd 扩展的内部 Feature，探测失败只输出一条提示并保留 clangd 原行为。

## ⚠️ 行为变化与升级提示

- 只修复装饰显示，**不改变**诊断、补全、编译数据库、构建/调试行为；
- 不写入任何 `clangd.*` 设置，也不修改 clangd 扩展本体；
- 版本号 `0.8.146`；VSIX 文件名 `codeblocks-vscode-0.8.146.vsix`。

## 📦 安装

- 下载本页附件 **`codeblocks-vscode-0.8.146.vsix`**，或：

  ```powershell
  code --install-extension codeblocks-vscode-0.8.146.vsix --force
  ```

- 要求 VS Code **1.85.0+**；安装后请 **Reload Window**（装饰状态在扩展激活时重建）。
