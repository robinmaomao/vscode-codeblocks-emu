# Code::Blocks for VS Code 0.8.134

> 发布日期：2026-10-27 ｜ 正式版（0.8.133 → 0.8.134 里程碑汇总）

## 概述

🎯 本版围绕「大工程构建时的 CPU / 进程开销」做收口，并修掉一批 clangd 与 ccache 的真实缺陷。

- 🧵 **并行编译默认 8**：`codeblocks.parallelJobs` 默认从 `0`（自动 = 逻辑核数 × 2）改为 **8**，并改为 `resource` 作用域（支持文件夹级覆盖）；`0` 仍为自动、`1` = 串行；
- 🛑 **构建期不再重启 clangd**：构建进行中触发的编译数据库重建只登记，构建结束再重启，避免整库重索引与编译抢 CPU；
- ⚡ **逐行解析开销收敛**：构建输出每行只解析一次（此前最多 4 次），`OutputParser` 增加「无 `:` 行」快路径；编译子进程统一 `windowsHide`；设置快照按轮刷新；
- 🧩 **clangd 配置不再被改写**：清理失效片段只合并连续 `---`，用户自有的 `---` 保留（旧实现会合并片段、丢 `If` 条件，甚至让 clangd 丢弃整个 `config.yaml`）；
- 🔤 **`compile_commands.json` 逐字保留参数**：`-DNAME="My App"`、`-I"C:/Program Files/..."` 不再被拆成两个参数；
- 📦 **ccache 修复**：`$compiler` 前缀按生成器实例记忆化、解析缓存命中只 `stat` 一次、修正 POSIX 可执行位校验与 `.cmd` / `.bat` 版本探测。

同时包含：裸程序名先按 `masterPath/bin` 解析再探测系统头 / `--target`、clangd 检测时效（负结果 TTL 30 秒 + 扩展安装状态监听）、原子写 `config.yaml` / `compile_commands.json`、Build Log 只取 clangd 来源诊断。

## 🧵 构建并发与 CPU 守卫

- `codeblocks.parallelJobs` 默认 **8**；`0` = 自动（逻辑核数 × 2）、`1` = 串行；数值字符串按数字解析，`null` / 布尔等类型回退默认值；
- 构建期 clangd 重启（切换活动工程 / 改编译器触发）推迟到构建结束；
- 构建输出每行只解析一次，`OutputParser` 对「无 `:` 行」走快路径；编译子进程统一 `windowsHide`；设置快照按轮刷新。

## 🧩 clangd 集成修复

- 用户 `config.yaml` 不再被改写：只合并被删片段留下的连续 `---`，用户自有分隔符与 `If` 条件保留；
- `compile_commands.json` 逐字保留带引号的参数，宏不再被拆成两个参数；
- 裸程序名（`gcc.exe`）先按 `masterPath/bin` 解析，再探测系统头 / `--target`；`--query-driver` 建议值不再是 `./*`；
- 检测：负结果缓存 30 秒、手动生成清缓存、监听扩展安装状态；下载目录覆盖 Insiders / VSCodium / Cursor / 远程 server；`clangd.path` 必须是文件；
- 只影响展示的设置（`buildLogDiagnostics` / `restartOnActiveProjectSwitch` / `queryDriver`）不再触发全量重建；`clangd.enabled=false` 时不生成；
- 原子写 `config.yaml` / `compile_commands.json`；Build Log 的 clangd 模式只取 clangd 来源诊断。

## ⚡ 编译缓存（ccache / sccache）修复

- `$compiler` 前缀按生成器实例记忆化；解析缓存命中只 `stat` 一次、失效才重扫，仅「未找到」时清缓存；
- 修 POSIX 可执行位校验、`.cmd` / `.bat` 版本探测、提示标记重置。

## ⚠️ 行为变化与升级提示

- **并行编译默认值 0 → 8**：默认不再吃满「逻辑核数 × 2」；需要旧的自动行为请显式设 `codeblocks.parallelJobs = 0`；
- 构建期间 clangd 重启被推迟到构建结束（切换活动工程 / 改开编译器不再即时重索引）；
- 用户 `config.yaml` 与 `compile_commands.json` 的写入更保守（原子写、参数逐字保留）——用户自有分隔符不会再被改写；
- 无新增设置项。
