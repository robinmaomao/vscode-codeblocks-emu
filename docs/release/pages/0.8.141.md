# Code::Blocks for VS Code 0.8.141

> 发布日期：2026-11-06 ｜ 正式版（0.8.140 → 0.8.141 里程碑汇总）

## 概述

🎯 本版修复两个现场反馈的问题：**打开工程后 clangd 不分析**、**编译错误不自动跳转到源码**。

- 🔄 **clangd 打开工程即重启**：打开工程（含从状态栏「Code::Blocks projects」打开检测到的工程）时，只要编译数据库**或**配置片段有变化、且 clangd 扩展已激活，就重启语言服务器；新增重启原因 `'open'`，**不受** `codeblocks.clangd.restartOnActiveProjectSwitch` 限制；
- 🎯 **错误跳转真正定位**：`executeCommand('vscode.open', uri, { selection: Range })` 经命令参数 JSON 序列化后 `Range.toJSON()` 变成 `[start, end]`，主进程不再认作 `IRange` ⇒ **只打开文件、丢弃定位**；改为 `openTextDocument` + `showTextDocument({ selection })` + `revealRange`；
- 🧭 **导航更可靠**：跳过链接期伪文件（`ld` / `ld64` / `lld` / `collect2` / `link` / `cl`）与打不开的文件，逐条回退到下一条；
- 🧰 **新增排障命令**：`Code::Blocks: Restart clangd Language Server`（菜单 `Code::Blocks → Settings`）。

同时包含：`codeblocks.openLocation` 内部命令（树节点用纯标量参数跳转）、`finishBuildSummary` 先 `await` 面板聚焦再跳转（消除焦点竞争）、输出通道留痕「已跳转到首个错误：`file:line:col`」。

## 🔄 打开工程后 clangd 不分析（根因与修复）

**根因**：生成链路本身正常（`openProject()` → `compile_commands.json` + 用户级 `config.yaml` 片段），缺的是「让已启动的 clangd 重新加载」：

| # | 缺陷 | 位置（修复前） |
|---|------|----------------|
| A | 打开工程**从不**设置重启原因：`restartClangdReason` 只可能是 `'project'` / `'compiler'` ⇒ 重启判定整段短路 | `openProject()` 末尾 |
| B | 唯一的「切换活动工程」触发点受 `codeblocks.clangd.restartOnActiveProjectSwitch` 控制（现场为 `false`） | 重启判定 |
| C | 门槛 `hasOpenSourceFile()`：从状态栏打开工程时通常没有可见的 `.c/.h` 编辑器 ⇒ 即使 A/B 都满足也不重启 | `hasOpenSourceFile()` |

**修复**：

- 新增重启原因 **`'open'`**（新打开与「已打开再刷新」两条路径都置位），与 `'compiler'` 一样**不受** `restartOnActiveProjectSwitch` 限制；
- 触发条件从「数据库变化」扩展为「**数据库或配置片段**有变化」（`updateClangdUserConfig()` 的 `written` 参与判定）；两者都没变时仍不重启（避免无谓整库重索引）；
- 门槛改为 **`clangdExtensionActive() || hasOpenSourceFile()`**：语言服务器已在跑才重启；没跑时无需唤醒，下次打开源文件会自然读到新配置；
- 输出通道留痕「已打开工程，重启 clangd 以套用新的编译数据库 / 配置」；新增命令 `Code::Blocks: Restart clangd Language Server` 便于一键验证。

## 🎯 编译错误不自动跳转（根因与修复）

**根因**：`vscode.Range` 在扩展宿主里 `toJSON()` 返回 **`[start, end]`**（`Position` → `{ line, character }`），命令参数跨进程走 JSON 序列化 ⇒ 主进程收到的 `options.selection` **不是 `IRange`** ⇒ 文件被打开、**定位被丢弃**；目标文件本来就打开时表现为「构建失败但没跳」。同类写法还有 Build Log 树节点与 Symbols 视图节点。

**修复**：

- 新增 `src/ui/openLocation.ts`：`openFileAtLocation()` = `openTextDocument` → `showTextDocument({ preview, selection })` → `revealRange(InCenter)`（与仓库内 `bookmarkGoto` / `locateInCbp` 同一套已验证做法；行 / 列越界自动钳制）；
- 新增内部命令 `codeblocks.openLocation`（参数为纯标量 `{ file, line, column }`，不进命令面板），Build Log 诊断节点与 Symbols 节点改用它；
- `gotoFirstError` / `gotoNextError` / `gotoPreviousError` 改为 `async`，失败时**继续找下一条**，全失败才返回 `undefined`；
- `finishBuildSummary()` 改 `async`：先 `await` 面板聚焦（`codeblocks.buildLog.focus` 现在返回内部命令的 Promise），再跳转，并留痕「已跳转到首个错误」/「首个错误没有可跳转的源码位置」；
- 导航列表过滤链接期伪文件（树视图仍照常显示这些错误，只是不作为跳转目标）。

## ⚠️ 行为变化与升级提示

- 打开工程时若数据库 / 配置有变化且 clangd 正在运行 → 会多一次 `clangd.restart`（整库重索引的 CPU 峰值出现在打开工程后）；构建进行中仍走「推迟到构建结束」路径；
- `codeblocks.clangd.restartOnActiveProjectSwitch` 语义不变（仍只作用于「切换活动工程」）；
- 链接期错误（`cannot find -lxxx`）不再占用「首个错误」名额，输出通道会提示「首个错误没有可跳转的源码位置」；
- 无新增设置项。

## 📦 安装

- 下载本页附件 **`codeblocks-vscode-0.8.141.vsix`**，或：

  ```powershell
  code --install-extension codeblocks-vscode-0.8.141.vsix --force
  ```

- 要求 VS Code **1.85.0+**；安装后请 **Reload Window**。
