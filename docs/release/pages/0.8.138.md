# Code::Blocks for VS Code 0.8.138

> 发布日期：2026-11-04 ｜ 正式版（0.8.134 → 0.8.138 里程碑汇总）

## 概述

🎯 本版修复**中文 / 非 ASCII 工程路径下 ccache 永不命中**的缺陷：`-g` 让 GCC 隐式 `-fworking-directory`，预处理输出首部的绝对路径按系统 ANSI（GBK）写出，ccache 判定编码非法后直接跳过缓存。

- 🔍 **根因已实测**：`ccache -s` 显示 `Cacheable calls: 0` / `Uncacheable 100%`，日志记 `unsupported_source_encoding`；
- 🔧 **修复只在必要条件下生效**：`compilerCache = ccache` + 工具已探测 + GCC/Clang + 工程根路径含非 ASCII，才追加 `-fno-working-directory` 并改用工程相对源路径；
- 📈 **实测效果**：中文路径工程 `Cacheable calls` **0% → 100%**、二次构建 **4 次 Direct HIT**、Release 单文件 **2.5 s → 0.1 s**；
- 🧭 **零影响边界**：ASCII 路径的编译命令与 0.8.137 **逐字节一致**；资源文件（windres）、`sccache`、`cache = none` 行为不变；**无新增设置项**。

同时包含：构建开始的一条说明行、源文件 / 包含目录自身含非 ASCII 时的告警与出路提示（该情形无法自动修复）。

## 🔍 现象与根因

**根因（实测：ccache 4.14.1 + MinGW GCC 8.1，中文 Windows 代码页）**

- `-g` 让 GCC 隐含 `-fworking-directory`，预处理输出以 `# 1 "<绝对 cwd>//"` 开头；源文件 / 头文件路径含非 ASCII 时同样出现在 `# 1 "<文件>"` 标记里；
- 中文 Windows 上这些路径字节按系统 **ANSI 代码页（GBK）** 写出，不是合法 UTF-8；
- ccache 以 UTF-8 校验预处理输出 ⇒ 记 `unsupported_source_encoding` ⇒ **直接跑真编译器、不写缓存**。用户侧表现就是「ccache 没生效」；
- 纯 ASCII 的「特殊符号」路径（空格、`&`、`()`、`#`、`%`、`!`、`'`）**不受影响**，已实测可缓存并可命中。

## 🔧 修复

仅在 `codeblocks.build.compilerCache = ccache`、工具已探测到、编译器为 GCC/Clang、且工程根路径含非 ASCII 时：

- 标准编译命令追加 `-fno-working-directory`（抑制 cwd linemarker）；
- 编译单元改用**工程相对源路径**（绝对路径会把 GBK 字节带进 `# 1 "<文件>"`）；
- 构建开始输出一条说明；源文件 / 包含目录自身含非 ASCII 时告警并给出出路（这类情形无法自动修复）。

## 🧭 兼容与边界

- ASCII 路径：命令与 0.8.137 **逐字节一致**（不加 flag、仍用绝对源路径）；
- 资源文件（windres）、`sccache`、`cache = none`：行为不变；
- 产物：`.text` 一致；`DW_AT_name` / `DW_AT_comp_dir` 正常，仅 `.debug_info` 有细微差异（`-fno-working-directory` 的预期结果）；
- 无新增设置项。

## ⚠️ 行为变化与升级提示

- 中文 / 非 ASCII 工程路径下，启用 ccache 后的编译命令会多出 `-fno-working-directory` 并使用工程相对源路径（仅该组合）；
- 纯 ASCII 路径工程的命令**完全不变**，无需迁移；
- 源文件或包含目录**自身**含非 ASCII 时仍无法缓存，输出通道会给出明确告警（建议改名或移到 ASCII 路径）；
- 无新增设置项。
