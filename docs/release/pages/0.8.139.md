# Code::Blocks for VS Code 0.8.139

> 发布日期：2026-11-05 ｜ 正式版（0.8.138 → 0.8.139 里程碑汇总）

## 概述

🎯 本版修复 CI 在 0.8.138 上暴露的 **Windows 8.3 短路径拼接畸形**：资源文件（windres）、`Use83Paths`、`$TO_83_PATH` 等路径在部分环境下会得到 `E:\"C:\...\"` / `D:\"...\"` 这类非法串。

- 🐞 **根因**：`shortPathWin` 用 `spawnSync('cmd', ['/d','/s','/c', 'for %I …'])` 取 8.3 短路径；含空格的 `/c` 参数被 Node 再次加引号，`cmd /s` 于是输出 `E:\"C:\...\"`；
- 🧪 **为何本地没暴露**：畸形串仍包含原始长路径，本地断言偶然通过；CI 上 `runneradmin` 被缩写为 `RUNNER~1` 才暴露；
- 🔧 **修复**：改用 `windowsVerbatimArguments: true` + `cmd /u`，按 UTF-16LE 解码并用 `fs.existsSync` 校验，失败回退 UTF-8 / GBK 与原路径；
- 🧷 **回归补齐**：`test-drive-case.js` 新增 4 条 `shortPathWin` 断言；新增 `tests/e2e/test-e2e-ccache.js`（21 断言，真实 ccache + 中文路径）。

同时包含：资源文件断言兼容 8.3 短路径形态（不再依赖长路径字面量）。

## 🐞 现象与根因

**现象**：GitHub Actions run `41836259345` 的 `core` 作业在 `tests/test-compiler-wrapper.js` 的资源文件断言失败。

**根因**：

- `shortPathWin` 通过 `spawnSync('cmd', ['/d', '/s', '/c', 'for %I in ("<path>") do @echo %~sI'])` 取短路径；
- Node 对含空格的 `/c` 参数**再加一层引号**，而 `cmd /s` 又会剥掉首尾引号 ⇒ 输出变成 `E:\"C:\Program Files\..."` 这类畸形串；
- 资源文件（windres）、`Use83Paths`、`$TO_83_PATH`、`$file` 都会受影响；
- 本地测试因畸形串仍包含原始长路径而偶然通过；CI 上 `runneradmin` 被缩写为 `RUNNER~1`，路径不再包含长用户名才暴露。

## 🔧 修复

- `spawnSync` 增加 `windowsVerbatimArguments: true`，避免 Node 二次加引号；
- `cmd /u` 以 UTF-16LE 输出，按 UTF-16LE 解码，消除中文路径的代码页问题；
- 结果用 `fs.existsSync` **校验**：不存在即回退 UTF-8 / GBK 解码结果，再回退原路径（绝不把畸形串传下去）；
- 资源文件断言兼容 8.3 短路径形态。

## 🧭 兼容与边界

- 仅影响 Windows 下 `Use83Paths` / 资源文件 / `$TO_83_PATH` 等**短路径**取值路径；
- 非 Windows 平台与未启用 8.3 短路径的工程：命令不变；
- 短路径不可得（卷禁用 8.3）时回退原长路径，行为与 0.8.138 一致；
- 无新增设置项。
