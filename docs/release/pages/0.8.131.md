# Code::Blocks for VS Code 0.8.131

> 发布日期：2026-10-15 ｜ 正式版（0.8.130 → 0.8.131 里程碑汇总）

## 概述

🎯 本版两条主线：

- 🧵 **工作区检测开销治理**：`.cbp` 文件事件改**增量登记**（不再触发全工作区 `findFiles`，历史上每次事件固定起 2 个 ripgrep 进程）、工作区工程扫描合并为**一次**并排除重目录（30s 缓存 + 单飞）、大工作区不再自动弹多选；宿主实测（36 工程 / 36,829 文件）激活期扫描 **211ms → 89ms**；
- ⚙️ **设置改动立即生效**：改任意 `codeblocks.clangd.*` 或**编译器设置**（`compilerId` / `masterPath` / `compilerPrograms`）后自动重新生成 clangd 用户配置与编译数据库（编译器变化还会重启 clangd 刷新已打开文件），并补齐字符串数组**取值容错**；两处「改了没反应」改为一键提醒（`build.persistLog` 需重载、`clangd.enabled` 关闭后片段仍生效）。

同时包含：新增命令 `Workspace Scan Report`、兜底符号索引单文件缓存、覆盖矩阵与文档同步（产品行为此外零变化）。

## 🧵 工作区检测开销治理（0.8.130 后合入）

- **起因**：用户反馈编译期进程暴增、CPU 冲 100%，两三个文件的工程也明显比 Code::Blocks 慢，工作区越大越明显。
- **`.cbp` 事件改增量登记**：新增 / 删除 `.cbp` 只维护已登记工程集合，不再触发工作区级全量扫描（历史上每次事件固定起 2 个 ripgrep 进程，成本 ∝ 工作区文件数）。
- **扫描合并为一次**：`findFiles('**/*.{cbp,workspace}')` 单次调用，显式 exclude `Output` / `obj` / `bin` / `node_modules` / `.git` 等重目录（并把 `files.exclude` 默认项写回），加 **30s 结果缓存 + 单飞**。
- **大工作区不再自动弹多选**：新设置 `codeblocks.detect.autoOpen`（`all` / `single` / `off`，默认 `all`）与 `codeblocks.detect.autoOpenThreshold`（默认 `20`）——未打开工程数超阈值时仅保留状态栏入口 + 输出通道提示，并限制会话恢复的工程数；多选**默认只勾选最近使用 / 活动工程**。
- **兜底符号索引按文件缓存**：`SymbolIndex` 增加「mtime + size」判定，多工程重建只重解析变化文件。
- **新增排查命令** `Code::Blocks: Workspace Scan Report`：输出扫描耗时、工程数、工程目录数、当前 ripgrep 并发与「单工程工作区」建议。

## ⚙️ clangd 设置改动立即生效（0.8.130 后合入）

起因：在 `codeblocks.clangd.suppressedWarnings` 里加了 `-Wempty-body`，`%LocalAppData%\clangd\config.yaml` 里却没有这一项。排查确认**写入链路本身正常**，问题出在**触发**与**取值**：

- **触发**：此前 `activate()` 里没有任何 `codeblocks.clangd.*` 监听，只有打开工程 / 切换活动工程 / 手动执行 `Generate compile_commands.json` 才重写配置 ⇒ 现在改任意项即**自动重新生成**（约 **150ms 去抖合并**；clangd 自身会重载 `config.yaml`，无需重启或重载窗口），生成 / 跳过都在输出通道留痕；未打开工程时跳过（作用域未知），下次打开工程按新设置生成。
- **生成中的请求不再丢弃**：单飞期改设置原先被**静默丢弃** ⇒ 改为「跑完再补一次」（交互式标记一并保留）。
- **取值容错**：`suppressedWarnings` / `forcedIncludes` / `excludeDirs` 手改成字符串（如 `"-Wunused-function, -Wempty-body"`）时按逗号 / 分号 / 空白**拆分**，写成其它类型则**回退设置默认值**并在输出通道提示取值类型问题；数组值顺带 trim / 去空 / 去重；片段层再加**非数组防御**——历史上字符串会**按字符**迭代，写出 `- -`、`- W`… 单字符压制项（等于该设置彻底失效）。

## 🔧 设置即时生效收口（G1 / G3 / G4）

逐项审计 76 个设置读点后确认的 3 处真实缺口：

- **G1 改编译器立即生效**：修改 `codeblocks.compilerId` / `masterPath` / `compilerPrograms` → 底部状态栏 `Compiler:` 立即刷新 + 按新编译器重新生成 `compile_commands.json`（编译命令 / `--target` / 系统头 `-isystem` 全部按新编译器推导）；编译数据库**实际变化**且已打开 C/C++ 文件时**重启 clangd**，免去「换了编译器、红波浪线 / 补全还是旧的」。重启原因区分「切换活动工程」（受 `codeblocks.clangd.restartOnActiveProjectSwitch` 控制）与「编译器设置变化」（**无条件**，不提供关闭项——不重启等于设置没生效）。
- **G3 `build.persistLog` 变更提醒**：输出通道类型（普通通道 ⇄ 日志通道）在激活期创建、不可热切换（重建会清空当前输出）⇒ 改动时**弹提醒**（含「开启 / 关闭」描述）并提供「重载窗口 / 稍后」，点前者执行 `workbench.action.reloadWindow`。
- **G4 关闭 clangd 集成提醒**：`codeblocks.clangd.enabled` 置 `false` 只让扩展停止生成 / 更新用户级 `config.yaml`，**已写入的片段仍会被 clangd 读取**（继续指向旧编译数据库）⇒ 由「开 → 关」时**弹提醒**并提供「打开 clangd 配置 / 稍后」（打开 `%LocalAppData%\clangd\config.yaml`）；值未变化（其它来源重复派发事件）或无既存片段时**静默**，不重复打扰。不自动清理：片段是用户级配置，且当前工程的片段会被「清理失效片段」命令判为有效而保留。
- **G5 不做**（用户确认）：`asmUsesCompilerV1` / `responseFile` 对编译数据库仅有微影响，评估为收益低。

## ⚠️ 行为变化与升级提示

- **大工作区（未打开工程数 > 20）激活时不再自动弹多选**：改为状态栏入口 + 输出通道提示；需要旧行为可把 `codeblocks.detect.autoOpen` 设为 `all`、`autoOpenThreshold` 调大；
- **工程多选默认只勾选最近使用 / 活动工程**（不再全选）；
- **clangd 用户配置与编译数据库会在设置变更后自动重新生成**；改编译器设置时若编译数据库**实际变化**会**重启 clangd**（触发一次重新索引）；
- `codeblocks.build.persistLog` 仍需重载窗口生效（现在会弹提醒 + 一键重载）；
- 关闭 `codeblocks.clangd.enabled` 后**既有片段仍会被 clangd 读取**（现在会提醒并可打开配置清理）；
- 既有工程的构建命令、增量语义与其它默认行为**零变化**。

## 📦 安装

- 下载本页附件 **`codeblocks-vscode-0.8.131.vsix`**，或：

  ```powershell
  code --install-extension codeblocks-vscode-0.8.131.vsix --force
  ```

- 要求 VS Code **1.85.0+**；安装后请 **Reload Window**。工程内 `test-project/`（3 个 `.cbp` + 1 个 `.workspace`）可直接用于验收。
