# Code::Blocks for VS Code 0.8.142

> 发布日期：2026-11-06 ｜ 正式版（0.8.141 → 0.8.142 里程碑汇总）

## 概述

🎯 本版修复**链接期错误（`undefined reference`）点不动、也不自动跳**：Build Log 的 Errors 条目点击无反应，同一份日志里的 Warnings 却正常。

- 🧭 **根因**：GNU ld 的 `obj\...\x.o:x.c:(.text+0x9): undefined reference to '…'`（或 `x.c:(.text.函数+0x2e)`）被解析器整串当成文件名、且没有行号；相对路径再按链接命令的 cwd 拼接，得到的路径根本不存在 ⇒ `openTextDocument` 失败；
- 🔧 **修复**：新增纯逻辑模块 `src/build/diagnosticPath.ts`，在构建引擎的 `resolveFile` 钩子里把文件**按 basename 落回工程源码**（`x.o` → `x.c` 回退），并从段名 / 未定义符号名补出**行号**；
- 🎯 **效果**：Errors 条目显示 `func_bt.c:6`，点击与「构建结束自动跳首个错误」都能把光标放到出错行；Problems 面板条目同样指向真实源码；
- 🧪 **验证**：新增 `test-diagnostic-path.js`（18 断言）+ 真实 gcc 的 `test-e2e-linker-diagnostic.js`（7 断言）。

同时包含：`BuildOptions.resolveFile` 钩子（Problems 与结构化诊断共用一次修正）、诊断文本按文件缓存。

## 🧭 现象与根因

| 环节 | 修复前 | 后果 |
| --- | --- | --- |
| 输出解析 | `obj:src:(section+0xNN)` 整串被当作文件名，行号缺失 | 树里显示伪路径；无行号可跳 |
| 路径解析 | 相对路径按**链接命令的 cwd**（工程执行目录）拼接 | `cwd\link_err.c` 不存在 |
| 打开文件 | `openTextDocument` 抛错 → `openFileAtLocation` 返回 false | 点击无反应；自动跳转静默跳过 |

需要同时处理 GNU ld 的两种形态：`<obj>:<src>:(<section>)` 与 `<src>:(<section>)`。

## 🔧 修复

- `splitDiagnosticFileToken()`：拆 `file:(section)` / `obj:src:(section)` / `file:line`；
- `resolveExistingFile()`：绝对 → `cwd` → 工程根 → basename 索引（`.o/.obj` 回退同名源文件；同名多份取「路径后缀匹配」的那个）；
- `findIdentifierLine(text, id, 'any' | 'call')`：段名带函数名 → 定位到该函数；只有 `.text` 时用消息里的未定义符号 → 定位到**调用处**（跳过 `extern` 声明）；
- 构建引擎新增 `resolveFile` 钩子，Problems 与 Build Log 诊断共用同一份修正（含行号重算 range）；
- 扩展按工程文件表构造索引并注入（整次构建复用，文本读取带缓存，仅在链接期诊断需要时发生）。

## ✅ 验证

| 层 | 结果 |
| --- | --- |
| 单元（新增） | `test-diagnostic-path.js` **18 断言**：token 拆解 / 文件定位 / 行号启发式 / 缓存 / 与真实 OutputParser 串联 |
| E2E（新增，真实 gcc） | `test-e2e-linker-diagnostic.js` **7 断言**：真实链接失败 → 诊断指向真实源文件、行号 = 调用行、Problems URI 一致、伪路径消失 |
| 全量 | `unit 179 脚本 FAIL=0 SKIP=1`、`contract 3/3`、`e2e 6/6` |

## ⚠️ 行为变化与升级提示

- 只在「解析出的文件按原逻辑打不开」时改造：绝对路径 + 行号已正确的诊断**原样透传**；
- 工程外文件（系统头 / 第三方库）不做猜测，保持原行为；
- `.o/.obj` 仅在工程文件表里能找到同名源文件时回退；
- 无新增设置项、无新增命令；构建命令与产物零变化。
