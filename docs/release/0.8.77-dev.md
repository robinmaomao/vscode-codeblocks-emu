# 0.8.77-dev

> 调试 P2 三项改进：指令断点 / 线程名解析修复 / 多调试会话路由。

## E1 指令断点（反汇编视图）

- 声明 DAP 能力 `supportsInstructionBreakpoints` 并实现 `setInstructionBreakpoints`：反汇编视图 gutter 对**任意指令**下断（对齐 Code::Blocks 反汇编窗口断点）
- 地址形式 `-break-insert *ADDR`（GDB 8.1 / 7.6.1 双实测可用）；条件 / 命中次数 / 日志消息与文件断点一致（条件为客户端求值，规避 GDB 8.1 条件命中崩溃）
- 新纯函数 `parseInstructionReference`（`0x`/十进制引用 + 偏移，非法防护）+ 4 断言

## E2 线程名解析修复

- `onThreads` 弃用旧惰性可选组正则（与第五十轮 D3 栈帧同款缺陷：`name` 永不捕获），改用逐 tuple `parseThreadTuples`
- 实测：GDB 实报的线程名（如源码文件名）现可在线程视图显示；缺失时兜底「线程 N」

## E3 多调试会话路由

- `debugRegistry`：单指针 → 「会话 id → 适配器」映射 + 最近会话兜底
- 适配器携带 `session.id`（工厂传入），注册/注销随会话生命周期；新增 `onDidChangeActiveDebugSession` 刷新
- 多会话时寄存器视图 / 调试辅助命令跟随 **VS Code 聚焦会话**；任一会话结束不再误清指针

## 验证

- e2e（真实 GDB 8.1）**14/14**：指令断点全链路（能力/非法地址/反汇编取址/下断/命中存活/清除跑完）、线程名捕获、双会话聚焦优先 / 兜底 / 注销不误清
- 全量 61 测试 + headless 通过
