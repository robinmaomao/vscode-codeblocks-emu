# 0.8.135：构建期进程/CPU 收口 · 产物排除写入用户设置

> 发布日期：2026-11-03 ｜ 正式版（0.8.134 → 0.8.135 里程碑汇总）
> 逐条对齐依据见 [对齐对照](../guide/alignment.md)；设置项见 [使用说明](../guide/usage.md) §13；dev 迭代过程见 [0.8.135-dev](./0.8.135-dev.md)。

## 概述

本版把「构建期 CPU 被吃满」这条链路完整收口，分三层：

1. **少派生进程**：编译/链接命令去掉 `cmd.exe` 中转；PCH 旧产物不再拼 `cmd /c if exist … del …`；
2. **少让编辑器做无谓工作**：产物目录排除项改为写入**用户设置**（不进仓库），并补齐默认 `.objs` / `.deps`
   与全部构建入口；
3. **能自证**：新增系统 CPU 归属采样，把 `rg.exe` / `conhost.exe` 单列为「VS Code 文件扫描器」，
   满载时直接指出是谁在吃 CPU。

默认行为变化两处：

- `codeblocks.build.autoExcludeOutputs` 仍默认开启，但写入目标由工作区改为**用户设置**，并自动清理
  旧版本写进 `.vscode/settings.json` 的同名条目；
- `codeblocks.build.lowerCompilerPriority` 默认由「开」改为**关**（实测编译器只吃 16~31 ms CPU，
  降优先级只会在被抢 CPU 时更饿）。

## 一、进程收口

| 项 | 0.8.134 | 0.8.135 |
| --- | --- | --- |
| 编译/链接派生 | `spawn(cmd, { shell: true })`，Windows 上每条命令先起 `cmd.exe /d /s /c` | 能安全拆分时直接 `spawn(program, args)`，**每单元少一个 `cmd.exe`**；含 cmd 元字符 / cmd 内建命令 / 引号不可靠时回退 `shell: true` |
| PCH 旧产物删除 | 命令前缀拼 `cmd /c if exist "…" del "…"` | 宿主内 `fs.rmSync(…, { force: true })`，且**只在真正派发该单元前**执行（命令收集 / Makefile 导出 / compile_commands 生成无副作用），命令保持单行 |
| pre/post-build 脚本 | `spawn(..., { shell: true })` 未设 `windowsHide` | 补 `windowsHide: true` |
| 并发上限 | 只按任务数限流（0 = 逻辑核 × 2，最多 32） | 新增进程预算：实际并发 = `min(请求值, 32, max(8, 逻辑核数))`，被收敛时打印说明；默认仍为 8 |
| 可观测性 | 只有 `[profile] spawn count` | `spawn peak (live child processes)`、`spawn without shell`；`codeblocks.build.traceProcesses`（默认关）打印一行汇总 |

## 二、产物排除：写入用户设置

`files.watcherExclude` / `search.exclude` 的产物排除项**不再写到工作区 `.vscode/settings.json`**：

- 写入 `ConfigurationTarget.Global`（用户设置），同一台机器上所有工作区生效，且不会被提交到仓库；
- 旧版本写进工作区的同名条目（值必须为 `true`）自动删除；用户自己添加的其它条目原样保留；
  工作区对象被清空时直接删除该设置键（不留下 `{}`）；
- 产物目录推导补齐 Code::Blocks 默认值：`object_output` 为空 → `.objs`、`deps_output` 为空 → `.deps`，
  并先展开 `$(…)` 宏（避免生成 `**/$(TARGET_OBJECT_DIR)/**` 这类无效 glob）；
- 排除动作覆盖全部会写/删产物的入口：Build / Build Workspace / Clean / Clean Workspace /
  右键单工程 Build·Rebuild / 单文件编译 / Rebuild All；
- 工程扫描（`findProjectFiles`、项目快速选择）同样跳过 `.objs` / `.deps`。

## 三、扩展宿主 CPU 收口

- **收集阶段分片让出**：增量判定 + 命令生成是同步文件系统扫描，每 32 个文件 `await setImmediate`。
- **include 解析缓存**：键 = 搜索目录签名 + 引用方式 + 源目录 + include 名；每轮构建清空（负结果只在同一轮复用）。
- **构建期不生成编译数据库**：`generateClangdForWorkspace` 在构建中只登记，构建结束再生成
  （生成链路要同步派生交叉编译器取系统头，构建期间跑会与编译抢 CPU 并阻塞宿主）。
- **探测缓存随工具链失效**：`queryCompilerIncludes` / `queryCompilerTarget` 的缓存键加入编译器 `mtime`。

## 四、系统 CPU 归属采样

`codeblocks.build.sampleSystem`（默认关，Windows）：

- 每 ~1 s 输出「整机 % + 编辑器 + 已知安全软件 + VS Code 文件扫描器（`rg` + `conhost`）+ 其余」；
- 采样器自身 CPU 从「其余」中扣除（`__self`），避免观测者污染观测；
- 扫描器 ≥ 8% → 点名提示启用 `autoExcludeOutputs` 并重载窗口；
- 安全软件 ≥ 10% → 点名提示把工程目录 / 对象目录 / 工具链目录加入实时扫描白名单；
- 总占用 ≥ 85% 且编辑器 + 安全软件 ≤ 40% → 明确告知「满载来自编译器工具链」，并给出 `parallelJobs` 取舍建议。

## 六、实测数据（VS Code 1.144.0，隔离 Profile，801 文件 / 8 并发）

| 指标 | 数值 |
| --- | --- |
| 构建墙钟 | 11.6 s |
| 收集阶段 | 292 ms |
| 宿主输出解析 | 10 ms |
| 派发空档（dispatch wait） | 3 ms |
| 事件循环最大滞后 | 17 ms |
| 宿主卡顿占比 | 3% |
| VS Code 文件扫描器（rg + conhost）CPU | **0%** |
| 编辑器 + 子进程 CPU | 12% |
| 工具链 + 其它程序 + 系统 CPU | 80% |

结论：扩展自身没有空转；同工程在 Code::Blocks 里 CPU 只有几个百分点，差别在于 Code::Blocks
没有文件监视器与搜索索引，而 VS Code 会把构建写入的每个目标文件当成一次工作区变更。
本版把这条放大链的入口（产物目录）从「默认不排除」改为「默认排除且写用户设置」。
