## 汇编注释（0.8.128-dev）

- 默认值：`language-configurations/asm.json` 行注释标记 `#` → `//`（预处理的 `.S` 安全；块注释保持 C 风格）；
- 新设置 `codeblocks.editor.asmHashComment`（boolean，默认 false）：开启后经 `vscode.languages.setLanguageConfiguration('asm', …)` **动态注册** GAS 原生 `#`（扩展动态注册优先级高于静态文件配置；仅覆盖 comments，括号等仍沿用静态配置）；关闭即释放、自动回退静态 `//`；**修改即时生效**（`Ctrl+/`、`Ctrl+K Ctrl+C/U`、命令面板等全部注释路径一致）；
- 实测依据：原生 `.s`（GAS 直接汇编）在 RISC-V（binutils 2.28 / 2.43）与 x86 上均拒绝 `//`（整行 junk / 行尾 illegal operands / invalid char），`#` 才是 GAS 原生注释（行首 / 行尾均安全）；`.S` 经 cpp 预处理则两者均可——默认 `//` + 可切回 `#` 并存。

## F5 调试接入（本版新增）

- **背景**：VS Code 在「无 `launch.json` → F5」时走 `createSession → guessDebugger → resolveConfigurationByProviders`，**只询问扩展注册的 `DebugConfigurationProvider`**；此前扩展只注册了 DAP 适配器工厂，导致 F5 两条分支**都静默失败**（有活动 C 文件时语言唯一命中本调试器 → 不弹框、也不启动；无活动文件时弹 `Select debugger`、选中后仍无会话、无报错、不创建 `launch.json`）。
- **实现**：新增 `src/debug/debugConfigProvider.ts`，注册两组 `DebugConfigurationProvider`——
  - **Initial**：`resolveDebugConfiguration`（F5 空配置 → 按活动工程推导并回填 `type`）+ `resolveDebugConfigurationWithSubstitutedVariables`（`program` 变量替换后不存在 → 回退到活动目标输出并在输出通道记录）+ `provideDebugConfigurations`（创建 / 添加配置时给出真实目标输出，而不是占位 `${workspaceFolder}/bin/Debug/app`）；
  - **Dynamic**：`provideDebugConfigurations`（`Select and Start Debugging` / 「More Code::Blocks GDB options...」）。
- **复用**：`debug()` 与两个 provider 共用 `deriveDebugLaunchConfig()`（活动目标 → 输出文件 / 宿主程序 → GDB → 运行目录 / 参数 / 环境 / 源搜索目录 / 远程目标），F8 路径的行为与文案逐字不变。
- **激活事件**：新增 `onDebug`、`onDebugResolve:codeblocks`、`onDebugInitialConfigurations`、`onDebugDynamicConfigurations:codeblocks`（VS Code 的隐式激活事件生成**不覆盖**调试贡献，必须显式声明）。
- **实测**（VS Code 1.141.0 开发宿主 + `test-project` 副本）：① F5 无 `launch.json` 且有活动 C 文件 → 直接启动、命中断点、程序输出 `hello-cb: 2 + 3 = 5`；② F5 无活动文件 → 选择框新增「More Code::Blocks GDB options...」，选中 `Code::Blocks GDB` 后正常启动；③ `Code::Blocks: Debug`（F8）回归正常；④ `launch.json` 的 `program` 失效时回退到活动目标输出并成功运行。

- 汇编（`.s` / `.S`）行注释默认由 `#` 变为 **`//`**；原生 `.s` 直接汇编（未经 cpp 预处理）请开启 `codeblocks.editor.asmHashComment` 使用 `#`；

- 既有工程的构建命令、增量语义与其余默认行为**零变化**。
