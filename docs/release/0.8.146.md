# 0.8.146 — 2026-11-10

> 修复版：clangd `#ifdef` 关闭区域（inactive regions）不再变暗。

## 问题

打开工程后，`config.c` 里被 `#if` / `#ifdef` 关掉的代码（如 `#if FUNC_BTHID_EN` 且 `config.h` 中该宏为 `0`）**不变暗**；关掉宏再保存头文件也不会刷新。关闭并重开文件、或重载窗口后恢复正常，随后又复发。

## 根因

1. clangd 服务端一直在发送 `textDocument/inactiveRegions`（clangd 22.1.6 日志可见），因此问题不在宏解析、也不在编译数据库。
2. vscode-clangd 的 `InactiveRegionsFeature` 在语言客户端**原地重启**时被复用：停止阶段 languageclient 调用 `clear()`，它只 `decorationType?.dispose()`，**不清空字段**；重启后重建装饰的条件是 `if (!this.decorationType)`，字段仍是（已释放的）对象 ⇒ 永不重建，`applyHighlights` 拿着已释放的装饰类型去 `setDecorations` ⇒ 页面不变暗。
3. 0.8.144 为修复 `command 'clangd.applyFix' already exists`，把自动重启从「`clangd.restart` 命令（销毁旧客户端、重建全新客户端）」改成「`LanguageClient.restart()`（复用同一客户端与 Feature）」——正好踩中该缺陷。0.8.143 及更早版本从未复用 Feature，所以从没出现过这个现象。

## 修复

- 新增 `src/tools/clangdInactiveRegions.ts`：通过 clangd 扩展 v1 API 暴露的 `LanguageClient` 找到 `InactiveRegionsFeature`（按运行时形状探测，找不到就静默降级）。
  - 状态进入 `Stopped` / `Starting`：释放并**清空**装饰类型、清空已缓存的区域（避免把上一轮宏状态画上去）。
  - 状态进入 `Running`：装饰类型缺失时重建，并把已收到的区域重新应用到可见编辑器。
- `src/extension.ts`：注册该 watcher，并在本扩展每次重启 clangd 后立即触发一次修复；`deactivate` 时释放。
- 不改 clangd 扩展本体、不改用户设置、不改 clangd 的解析/渲染逻辑；仅在 `Running` 且装饰类型缺失时才重建（不会重复 dispose/新建）。
