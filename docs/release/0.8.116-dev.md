# 0.8.116-dev

> 复核修复：0.8.114/0.8.115 实施批次自检发现并修复两处小缺陷（G1 逐行读配置 / P2 单飞期间置脏被吞）。

## G1 复核修复：输出时间戳改为「缓存值 + 配置监听」

- **问题**：`timestamp` getter 内联 `vscode.workspace.getConfiguration(...)`——`cbChannel` 普通通道**每输出一行**都会调用一次 getter（构建输出数千行时逐行读配置），与性能批次目标相悖；
- **修复**：`extension.ts` 激活时读取一次到 `buildOutputTimestamp`；`onDidChangeConfiguration('codeblocks.build.outputTimestamp')` 刷新该变量；getter 改读变量。仍**即时生效（免重载）**，与 `buildLogPrefs` 的「缓存 + 失效」模式一致；
- **断言**：`test-clear-output` 40→**41**（D11 监听接线）。

## P2 复核修复：单飞收尾追加重建 + 构建异常保留脏标记

- **问题**：多工程连续打开（Symbols 视图可见）时，索引构建期间的 `markFallbackIndexDirty` 只置标志、不追加构建；单飞完成后若无新触发，索引停留在旧快照（缺后打开的工程）；
- **修复**：`requestFallbackIndexBuild` 收尾（finally）若 `fallbackIndexDirty && symbolsViewVisible` → 追加重建一次；构建异常（catch）时保留脏标记供下次重试；
- **断言**：`test-fallback-index-lazy` 17→**19**（C7 追加重建 / C8 异常保留脏标记）。

- P1/P3/P4/P5/P6/P7/P8/G2 复查未见新问题；
