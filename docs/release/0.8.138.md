# 0.8.138

> 发布日期：2026-11-04 ｜ 正式版（0.8.137 → 0.8.138 里程碑汇总）
> **主题**：ccache 非 ASCII 路径修复
> 设置项见 [使用说明](../guide/usage.md) §13 / §15 常见问题；测试结果见 [测试报告-0.8.138.md](../testing/test-report-0.8.142-archive.md)；
> 对齐依据见 [对齐对照.md](../guide/alignment.md)。

本版修一个用户可感知的「开关打开了但完全没效果」：**工程路径带中文（或任意非 ASCII 字符）时，ccache 永远不命中**。

## 1. 现象与根因

**现象**：`codeblocks.build.compilerCache = ccache` 已启用、构建日志里也确实前置了 `ccache.exe`，但 `ccache -s` 永远是
`Cacheable calls: 0` / `Uncacheable calls: 100%` —— 缓存从不写入、也从不命中。工程路径全 ASCII 时一切正常。

**根因（实测取证，ccache 4.14.1 / 中文 Windows CP936 / MinGW GCC 8.1）**：

1. `-g`（Debug 目标默认）让 GCC 隐式启用 `-fworking-directory`，预处理输出首部写出 `# 1 "<绝对工作目录>//"`；
   源文件、头文件、`-I` 目录含非 ASCII 时，同样出现在 `# 1 "<文件>"` linemarker 里；
2. 中文 Windows 上这些路径字节是**系统 ANSI 代码页（GBK）**，不是 UTF-8；
3. ccache 按 UTF-8 严格解码预处理输出，失败即记 `unsupported_source_encoding`（日志 `Failed; falling back to running the real compiler`），
   **直接执行真编译器、不写缓存** —— 用户侧看到的就是「ccache 不生效」。

对照实测（同一份 `main.c`，只改路径）：

| 工程路径 | 参数 | Cacheable | 结论 |
|---|---|---|---|
| `...\ascii-proj` | `-g -Wall -c main.c -o obj\Debug\main.o` | 1/1 | 正常，二次构建 HIT |
| `...\中文工程` | 同上 | **0/1** | 永远 Uncacheable |
| `...\中文工程`（无 `-g`） | `-Wall -c ...` | 1/1 | 正常 |
| `a&b(c)` / `p#1` / `p%20x` / `p!x` / `p'q` | `-g -Wall ...` | 1/1 | 正常（**纯 ASCII 特殊符号不受影响**） |
| ASCII 目录 + 源文件 `中文.c` | `-g ... -c 中文.c` | **0/1** | 文件名非 ASCII 同样不可缓存 |
| `LC_ALL=zh_CN.UTF-8` / `CCACHE_SLOPPINESS` / `-fdebug-prefix-map` / 8.3 短路径 cwd | `-g ...` | 0/1 | 均无效 |

## 2. 实现

**自动规避（仅 `ccache` + 工具已探测到 + GCC/Clang + 工程根路径含非 ASCII）**，两件事一起做才有效（缺一即 0% 可缓存）：

- **命令生成侧**：标准编译命令（含 PCH 头文件，`CommandType.CompileObjectCmd`）末尾追加 `-fno-working-directory`，
  抑制 cwd linemarker；链接 / 资源编译 / 脚本 / `compile_commands.json` 不注入（`noCompilerCache` 语义不变）。
- **编译单元侧**：源文件参数由绝对路径改为**工程相对路径**（`UseFullSourcePaths` 的绝对路径会把中文目录的 GBK 字节带进 linemarker）。
  源文件相对名本身非 ASCII 时相对化无效，保持原绝对路径并告警。

两者都是纯 ASCII 后，ccache 恢复正常写入/命中（本机实测：4/4 可缓存、二次构建 4 次 Direct HIT、Release 单文件 2.5 s → 0.1 s）。

**提示与告警**（构建开始各一次，跨引擎 10 s 去抖，不额外增加设置读取）：

- 已规避 → 输出通道 info 说明「改用相对源路径 + 追加开关」；
- 源文件 / 头文件 / 包含目录仍含非 ASCII → warn 并给出示例文件名与出路（改名或迁到 ASCII 路径）；
- `sccache` 无该限制；`cache=none` 时不做任何路径判断（零影响、不多读设置）。

## 3. 兼容与边界

- 只影响「`ccache` 已启用 + 工程路径含非 ASCII」的构建；**ASCII 路径命令与 0.8.137 逐字节一致**（仍用绝对源路径、不加开关）。
- 产物：`.text` 一致，`DW_AT_name` / `DW_AT_comp_dir` 均正常（实测 `objdump` 核对），仅 `.debug_info` 有细微字节差异。
- 资源文件（windres）不前置缓存程序、也不加开关，保持 CB 的绝对路径 + 8.3 短路径语义。
- 非 ASCII **文件名 / 包含目录**无法自动修复：只能告警 + 文档指引（不做 8.3 短路径改写，避免改 DWARF 文件名且卷可能未生成 8.3 名）。
- 新增设置项：**无**（沿用 `compilerCache` / `compilerCachePath`）；`sccache` 行为不变。
