# 0.8.126-dev

> R4 编译缓存（用户确认执行）：`codeblocks.build.compilerCache`（none/ccache/sccache，默认 none 零影响）
> + `compilerCachePath` 显式路径 + 新命令 `installCompilerCache` 引导安装；检测提示矩阵与构建回退告警。
> 延续 0.8.125-dev 的 Y3（A2 惰性命令生成）之后的最后一根「残留问题核查」尾巴。

## 背景（报告 §7.2 R4）

- 需求来源：构建性能建议清单——重复构建（切分支 / Clean 后 rebuild / 多工程共享）是典型
  用户痛点，ccache/sccache 可显著摊薄成本；但**不能改变对齐语义**：CB 无此功能，
  故按「保护性增强、默认关闭、零影响」处理（与 `parallelJobs` / `linkInputExtensions` 同档）。
- 用户确认的实施方案（四项决策）：
  1. 枚举 `build.compilerCache`（none/ccache/sccache，默认 none）+ 路径二级项 `compilerCachePath`；
  2. 自动检测 + 提示矩阵（未装→安装提示；装了未启用→启用询问；启用未找到→失效提示；
     均一次 + 「不再提示」，修改设置自动重置）；
  3. 引导安装命令（winget 复制/执行 或 打开官方下载页；**不做**静默自动安装，
     不做扩展内下载安装的二期方案）；
  4. ①②③ 三项一次做完。

## 变更

### 新增 `src/build/compilerCache.ts`（纯模块，无 vscode 依赖）

- `normalizeCompilerCacheKind`：未知/空/大小写变体 → none（误配安全回退）；
- `resolveCompilerCachePath` / `resolveCompilerCachePathCached`：
  显式路径（优先且唯一，无效即未找到——不静默回退 PATH）→ PATH 扫描（Windows 含
  `.exe/.cmd/.bat` 变体）→ 常见安装目录（WinGet Links / Scoop shims / `%USERPROFILE%\.cargo\bin` /
  Chocolatey / Program Files）→ **WinGet Packages 便携包兜底**（新式 winget 不建 Links、包目录被
  直写用户 PATH；扩展宿主 PATH 为启动快照时按包名段匹配 + 有界递归定位 exe）；
  会话级缓存按 `kind|显式路径|PATH` 键控，设置变化/安装动作调用方主动失效；
- `decideCompilerCachePrompt`：四态提示矩阵（含 manual 绕过标记，供「重新检测」）；
- `parseToolVersion` / `COMPILER_CACHE_INSTALL` / `buildInstallGuideItems`：
  winget id（Ccache.Ccache / Mozilla.sccache）、下载页、许可与引导项构造。

### `src/compiler/commandGenerator.ts`

- `GenerateParams` 新增 `noCompilerCache?: boolean`；
- `$compiler` 展开点注入前缀（`renderTemplate` 第 1 步）：`"<wrapper>" `（含尾随空格，
  路径含空格自动加引号），仅此处注入——链接（`$linker`）/资源（`$rescomp`）/库（`$lib_linker`）
  自然不受影响；
- 惰性 `require('vscode')` 读取两项设置（headless 单测无宿主时回退空串，与 `asmUsesCompilerVar` 同款）。

### `src/build/buildEngine.ts`

- 四处非标准编译路径显式排除：`collectCompileCommands`（clangd 编译数据库）、
  两处 pre/post 脚本宏展开、`expandCustomCommand`（工程内自定义 `buildCommand` 逐字展开不变）；
- `build()` 开头新增 `warnCompilerCacheMissing()`：已启用但未解析到工具 → 输出通道告警一次
  （区分「显式路径无效」与「PATH/常见目录未命中」两态），构建回退原编译器、不失败；
  每次构建先清解析缓存重探（运行中安装工具 → 下一个构建即生效），跨引擎 10s 去抖
  （工作区构建逐项目建引擎，同一配置不重复刷屏）。

### `src/extension.ts`

- 启动预热（4000ms，与编译器探测并行）→ `checkCompilerCachePrompt()`；
- 提示矩阵落 globalState 标记（`codeblocks.compilerCache.*Prompted` / `dontAsk`）；
  「如何安装」直达引导命令；「重新指定路径」打开设置页；「不再提示」落位；
- 设置变化监听：清解析/检测缓存、重置提示标记并立即重新检测（免重载窗口）；
- 新命令 `codeblocks.installCompilerCache`：QuickPick 选工具 → 引导项
  （复制 winget 命令 / 终端执行（需确认，可能 UAC 弹窗）/ 打开官方下载页 / 重新检测并启用）；
  **扩展不做任何静默安装**；安装动作收尾附一次「重新检测」。

### `package.json`

- 版本 0.8.126-dev；新命令条目；
- 新设置两项（均 `machine-overridable`：不进 Settings Sync，可按工作区覆盖）：
  - `codeblocks.build.compilerCache`：枚举三值 + `enumDescriptions` + 描述含安装引导
    `command:` 链接（设置界面可直接跳转引导命令）；
  - `codeblocks.build.compilerCachePath`：默认空串（自动探测）。
