# 0.8.109-dev

> UI 核查 N2（方案 C）：`Run` / 自定义工具的集成终端改为**同名先弃后建**——同一名称始终只有一个终端标签，每次运行输出全新。

## 背景

原实现每次 `vscode.window.createTerminal` 都新建终端实例（VS Code 不合并同名终端），连续运行 N 次会在面板堆积 N 个同名标签（每个还附带一个 shell 进程），旧输出散落在旧标签里。用户确认方案 C 修复：同名终端先 `dispose()` 再新建。

## 改动

- 新模块 `src/ui/runTerminal.ts`：`createRunTerminal(name, options, api?)`——先 dispose 全部同名现有终端，再创建新终端；`cwd`/`env` 与 `vscode.window.createTerminal` 同语义；`api` 可注入便于单测。
- `src/extension.ts` 四处接线（不再直接 `createTerminal`）：
  1. `run()` 普通可执行分支 — `Run: <目标名>`；
  2. `run()` 库/CommandsOnly 宿主程序分支 — `Run: <目标名>`；
  3. 自定义工具 terminal 模式 — `CB Tool: <工具名>`；
  4. 无工程编译成功后运行 — `Run (no project)`。
- 名称精确匹配（前缀/子串同名不误杀）；不同目标各自一个标签；Debug 走 DAP 不受影响。

## 验证

- 新增 `tests/test-run-terminal.js`（16 断言：先弃后建顺序 / 同名全弃 / 不同名不弃 / 前缀不误杀 / name-cwd-env 透传 / dist 接线静态断言）。
- `tsc` 0 错误；全量回归 `TOTAL=112 FAIL=0 SKIP=1`；headless 构建检查 EXIT 0（跑完自动还原 hello.exe）。
