# 0.8.101-dev

> 0.8.100-dev 条目计数强制的补全与设置健壮性：真实自定义命令的编译单元同样强制重链/重新打包；`linkInputExtensions` 设置容错；compile=false 的自定义命令文件恢复 mtime 触发。

## 背景（上轮遗留 + 核查）

0.8.100-dev 已复刻 CB「编译条目计数」强制（`GetTargetCompileCommands:585`），但仅覆盖「无可执行命令」的编译文件（自定义空命令 / 工具未匹配）；真实自定义命令文件（如 `buildCommand="cmd /c ..."`）在 CB 中命令本身也是条目 → 每次构建都重链，扩展此前仍 `链接已是最新`。同时设置误配（字符串 / `*.ld` / 非数组值）会静默失效，compile=false + 自定义命令的链接输入不触发 mtime 增强。

## 修复

- **F1 条目计数补全**：链接/静态库打包的 force 增加 `totalUnits > 0`（编译阶段产生过任何单元即强制，对齐 CB「ret 条目计数」；普通工程零影响——对象已更新本就强制）。真实自定义命令文件（对象永不产生）由此每次构建都重链接/重新打包，与 CB 一致。
- **F2 设置容错**（`linkInputExtensions()`）：字符串（`'ld, lds'` / `'.ld'` / `'*.ld'`）按 `;`/`,`/空白拆分；`true`/数字/对象/空串等误配回退默认列表（避免静默关闭）；规范化兼容 `*.` 前缀与去重；仅显式空数组 `[]` 关闭（文档约定）。`package.json` 描述同步（格式说明 + 作用域）。
- **F3a 边界一致性**：`linkInputsOutdated` 的自定义命令跳过条件改为 `use && file.compile`——compile=1 的仍由条目计数规则负责（避免双重计入/双日志），compile=false 的即使带自定义命令也按 mtime 触发（命令不执行、CB 亦无动作，属保护性增强）。
