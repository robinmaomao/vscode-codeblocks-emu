# 0.8.113-dev

> UI 核查 N2 增强（方案 A + 方案 B1，用户确认）：Run/自定义工具终端的「同名先弃后建」改为精确识别 + 跨重载回收。

0.8.109-dev 方案 C 的同名匹配会无差别 `dispose()` 所有同名终端——用户手工创建（或其它扩展创建）的同名终端会被误杀。两阶段增强：

## 方案 A（本会话精确识别）

- `src/ui/runTerminal.ts` 增加模块级 `WeakSet`（弱引用）记录 `createRunTerminal` 创建的终端；
- dispose 判定改为「同名 && 本扩展创建」，用户同名终端不误杀。

## 方案 B1（跨窗口重载回收）

- 复查发现：WeakSet 为内存态、窗口重载即失效——VS Code 持久会话会连名恢复旧终端，重载后首跑无法识别旧标签 → 每重载一次 +1 个陈旧同名标签（方案 C 的「单一标签」保证被削弱）；
- 新增 `RunTerminalRegistry`（`createWorkspaceRunTerminalRegistry`：`workspaceState` 键 `codeblocks.runTerminalNames` 持久化「本扩展用过的终端名」）；
- dispose 判定改为「同名 &&（WeakSet 命中 ‖ 注册表命中）」；`createRunTerminal` 创建后登记名称；
- `extension.ts` 激活时 `setRunTerminalRegistry(createWorkspaceRunTerminalRegistry(context.workspaceState))` 接线；
- 效果：重载后旧同名标签仍被回收——**「单一标签」保证跨重载成立**；从未用过的名称不受影响。
