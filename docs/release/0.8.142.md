# 0.8.142

> 发布日期：2026-11-06 ｜ 正式版（0.8.141 → 0.8.142 里程碑汇总）
> **主题**：链接期错误（undefined reference）定位与跳转修复

## 概述

0.8.141 修好了「编译错误不跳转」，但**链接期错误**（`undefined reference`）仍然点不动：Build Log 的 Errors 条目点击无反应，构建结束后也不自动跳；同一份日志里的 Warnings 却能正常跳。

根因是链接期诊断的「文件」不是普通路径：GNU ld 输出 `obj\...\link_err.o:link_err.c:(.text+0x9): undefined reference to '...'`（或 `func_bt.c:(.text.func_bt_warning_discon+0x2e)`）——解析器把 `obj:src:(section)` 整串当成文件名、且没有行号；相对路径再按**链接命令的 cwd**（工程执行目录）拼接，得到的路径并不存在 ⇒ `openTextDocument` 失败 ⇒ 既不跳转也不报错。

本版新增一个**纯逻辑的诊断定位模块**（`src/build/diagnosticPath.ts`），在构建引擎新增的 `resolveFile` 钩子里做两件事：

- **定位文件**：绝对路径 / `cwd` / 工程根依次尝试，再按 basename 落回工程源码（`a.o` → `a.c` 回退）；同名多份时优先「绝对路径以原始相对路径结尾」的那个；
- **补出行号**：段名带函数名（`.text.<函数>+0xNN`）→ 定位到该函数；段名只有 `.text` 时，用消息里的未定义符号名定位到**调用处**（跳过 `extern` 声明）。

修复后：Errors 条目显示 `func_bt.c:6`，点击与「构建结束自动跳首个错误」都会把光标放到出错行；Problems 面板的条目同样指向真实源码。

规模（0.8.142 时点）：无新增设置项、无新增命令（命令 111 / 设置 83 不变）；新增 `tests/test-diagnostic-path.js`（18 断言）与 `tests/e2e/test-e2e-linker-diagnostic.js`（7 断言，真实 gcc 链接失败）。

## 一、现象

- Build Log → **Errors (1)** 条目 `func_bt.c:(.text.func_bt_warning_discon+0x2e)` 无法点击跳转，构建结束也不自动跳；
- 同一份日志的 **Warnings** 条目（`func_bt.c:50:17: implicit declaration of ...`）点击可正常跳转；
- Problems 面板里这条错误的文件点击同样无反应（指向不存在的路径）。

## 二、根因

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 输出解析 | `'Undefined reference (plain)'` 把 `obj:src:(section+0xNN)` 整串当作文件名，行号缺失 | 树里显示伪路径；无行号 |
| 路径解析 | 相对路径按**产生该输出的命令的 cwd**（链接命令 = 工程执行目录）拼接 | `cwd\link_err.c` 不存在 |
| 打开文件 | `openTextDocument` 对不存在的路径抛错，`openFileAtLocation` 返回 false | 点击无反应；自动跳转静默跳过 |

> 注：MinGW/GNU ld 的两种常见形态都要处理——`<obj>:<src>:(<section>)` 与 `<src>:(<section>)`。

## 三、修复

- 新增 `src/build/diagnosticPath.ts`（纯模块、无 vscode 依赖，IO 注入便于单测）：
  - `splitDiagnosticFileToken()`：拆 `file:(section)` / `obj:src:(section)` / `file:line`；
  - `resolveExistingFile()`：绝对 → `cwd` → 工程根 → basename 索引（`.o/.obj` 回退同名源文件；同名多份取后缀匹配）；
  - `findIdentifierLine(text, id, 'any' | 'call')`：`any` 取首次出现（段名函数名 → 定义），`call` 跳过 `extern`/类型前缀那行（未定义符号 → 调用语句）；
  - `createDiagnosticResolver()`：按文件缓存文本，整次构建复用。
- `src/build/buildEngine.ts`：`BuildOptions.resolveFile` 钩子；Problems 诊断与结构化诊断共用同一份修正结果（含行号），`toDiagnosticFrom` 用修正后的行号重算 range。
- `src/extension.ts`：按工程文件表构造索引并注入解析器（一次构建一次），无额外磁盘开销（仅在链接期诊断需要时读文件，且有缓存）。

## 五、兼容与边界

- 只在「解析出的文件按原逻辑打不开」时改造：绝对路径 + 行号已经正确的诊断**原样透传**（resolver 返回 `undefined`）；
- 工程外文件（系统头、第三方库）不做猜测（返回 `undefined`，保持原行为）；
- `.o/.obj` 仅在工程文件表里能找到同名源文件时回退；
- 无新增设置项、无新增命令，构建命令与产物零变化。
