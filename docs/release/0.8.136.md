# 0.8.136

> 发布日期：2026-11-04 ｜ 正式版（0.8.135 → 0.8.136 里程碑汇总）
> **主题**：工作区路径守卫（`codeblocks.workspace.pathGuard`）
> 根因取证与方案见 [archive/2026-11-04-rg-storm-root-cause.md](../archive/2026-11-04-rg-storm-root-cause.md)；
> 设置项见 [使用说明](../guide/usage.md) §13；测试结果见 [测试报告-0.8.137.md](../testing/test-report-0.8.142.md)（滚动更新）。

## 概述

同一份 `.cbp` 在某个路径下构建时 `rg.exe` / `conhost.exe` 暴增、CPU 打满，换到另一个路径就正常。经调试器取证，根因是**工作区路径里含成对的 `[ ]`**：

1. VS Code 的 AI 指令定位器（`PromptFilesLocator`）把 `.github/instructions`、`.claude/rules` 拼成绝对路径后，用 `Eao()` 按**路径段是否含 glob 元字符**做拆分（`xgn()`：`*`/`?` 任意命中，`[ ]`/`{ }` 需成对）；
2. 遇到 `[内部]5756C_lvd_reset` 这样的目录名，**搜索根被截断到祖先目录**（实测 `E:\Work_Share\2026\10`），其余部分变成 glob；
3. glob 在 JS 侧匹配，ripgrep 拿不到任何 `-g` 参数 ⇒ 每次文件变更都把该祖先目录**整棵枚举**一遍（构建写几十个对象文件就叠出上百次），`Code.exe` 分组里出现成百上千个 `rg.exe` + `conhost.exe`，CPU 100%。

路径干净时 `Eao()` 直接返回整条指令路径、不带 `filePattern`，调用方走 `FileStat` 分支，**不会启动 rg** —— 这就是"换个路径就正常"的原因。

## 新增能力

### 设置 `codeblocks.workspace.pathGuard`

| 值 | 行为 |
|---|---|
| `off` | 不自动检查（手动命令仍可用） |
| `prompt`（默认） | 发现问题时在 Code::Blocks 输出通道与通知里报告；用户点「关闭这两处扫描」后才写设置 |
| `auto` | 发现问题时直接写设置并提示 |

检查内容（全部离线、纯计算）：

- 逐段判定 glob 元字符（含未闭合、转义等边界，与上游 `xgn()` 一致）；
- 用 `Eao()` 的同一规则算出 **VS Code 实际会用的搜索根**，并统计该根下文件数（上限 5000；盘符根直接短路）；
- 报告命中段、`searchRoot`、`filePattern`、影响与两条修复路径（改名 / 关扫描），并给出恢复方法。

修复动作：把 `chat.instructionsFilesLocations` 的 `.github/instructions`、`.claude/rules` 写成 `false`，
经 `ConfigurationTarget.Global` 写入**用户设置**（幂等、保留其它键、立即生效）。**绝不**写工作区 `.vscode/settings.json`。

### 命令 `Code::Blocks: 检查工作区路径`

手动触发同一套检查与报告（不受 `off` 影响），并提供「复制诊断」。

## 兼容性 / 行为边界

- **不改**编译、链接、清理、调试流程，不改 `.cbp`，不动 `files.watcherExclude` / `search.exclude`，**不禁用** Copilot Chat；
- 写入的是**用户级**设置，会影响所有工作区；只关这两处指令目录的自动发现，其它 AI 定制项不受影响；
- 若目标 VS Code 版本没有该设置键，写入不生效（输出里同时给出"改目录名"这条恒定有效的路径）；
- 两处扫描已关闭后**不再重复提示**（按有效配置判断，重载窗口/重新打开都安静；手动命令仍可复检）；
- 每个窗口对同一路径只提示一次，「不再提示」记入 `globalState`；`auto` 模式忽略该记录（显式选择优先）。

- `npm test`：**TOTAL=171 FAIL=0 SKIP=1**；`npm run test:contract`：**2/2**；`npm run compile` / `npm run bundle`：无错误、无告警；
