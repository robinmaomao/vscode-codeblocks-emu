# 0.8.98-dev

> 修复 clangd 跨界 typedef 冲突误报：嵌入式 SDK 头文件与工具链系统头对 `__int32_t` 等类型的定义不一致时，
> clangd 报 `redefinition_different_typedef`（GCC 能编过）——现**默认压制**。

## 问题

- **现象**（clangd 诊断）：
  `In included file: typedef redefinition with different types ('__int32_t' (aka 'int') vs 'long')`，
  代码 `clang(redefinition_different_typedef)`；`_stdint.h(44,19)` 报错处、`typedef.h(11,26)` 为先前定义。
- **根因**：嵌入式 SDK 头文件（`typedef.h`）与工具链系统头（`_stdint.h`）对 `__int32_t` 的类型定义不同
  （`long` vs `int`）；GCC 因预处理宏/包含顺序不触发，clang（clangd 内置前端）按字面判定为不同 typedef 重定义。
  属**跨工具链解析差异导致的误报**，与用户代码无关。

## 修复

- clangd 用户配置生成（`src/tools/clangd.ts` → `Diagnostics.Suppress`）默认新增压制项 **`redefinition_different_typedef`**：
  `codeblocks.clangd.suppressedWarnings` 默认值 → `["-Wunused-function", "redefinition_different_typedef"]`
  （`package.json` 与 `src/extension.ts` 两处同步）。
  - **语义核实**（clangd 官方文档 + 源码 `Diagnostics.cpp`）：`Suppress` 匹配前会对 `err_`/`-W` 前缀做规范化，
    因此写诊断名（`redefinition_different_typedef`）或 clang 内部名（`err_redefinition_different_typedef`）等价；
    **错误级诊断同样生效**（在 `HandleDiagnostic` 阶段置为 Ignored，不再发布）。
  - **恢复显示**：从设置 `codeblocks.clangd.suppressedWarnings` 移除 `redefinition_different_typedef` 后重新执行
    `Code::Blocks: Generate compile_commands.json…`（clangd 会自动重载配置，无需重启）。
- **顺带健壮性**：`updateClangdUserConfig([])`（空作用域调用）不再留下悬空 `---` 分隔符。
- **打包修复**：`.vscodeignore` 增 `.cb-tools/**`——临时/审计脚本移入子目录后，裸模式 `.cb-*.js` 不再匹配嵌套路径（vsce 行为），此前会被误打进 VSIX（本次实装 16 文件已排除）。
