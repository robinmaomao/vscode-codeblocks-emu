## 0. 结论概要

本轮共发现 **2 项文档认知错误 + 14 项新功能缺口 + 1 组插件评估结论**：

| 类别 | 数量 | 代表项 |
|---|---|---|
| 文档修正（无代码或少量代码） | 2 | 书签“原生承担”不成立；项目自定义变量语义与 CB 不符 |
| 环境变量体系对齐 | 2 | `<Environment>` 编辑 UI；`$(VAR)` 宏展开未接入 |

| 编辑器辅助 | 3 | 书签、Open include file、Add TODO item |
| 模板 | 2 | From template / Save as template；更多工程模板 |
| 插件评估 | 1 组 | Source Exporter / CppCheck / Profiler / DoxyBlocks / lib_finder 等 |

**总体判断**：第二轮把“对话框级”大项基本清完；本轮缺口集中在三类——
① **数据已解析/未接线**（`<Environment>` 变量进宏表、调试 search_path）；
② **对齐 CB 对话框但无编辑 UI**（Custom variables 页、目标/工程高级字段、远程调试）；
③ **CB 特色工具/插件**（书签、Open include、模板、导出类）。

> 影响面：全部候选**不触碰现有编译/链接命令生成与执行链路**（唯一例外 R2：宏展开结果可能变化——属预期对齐，需回归）。
> 其中 R4（远程调试）是唯一“新增调试工作流”的项，对嵌入式（GDB remote target，如 OpenOCD/串口）价值最高。

## 1. 文档认知修正（先取证，零/低成本）

### M1. “Bookmarks 由 VS Code 原生书签承担”不成立

- **CB 依据**：`main_menu.xrc:192-210`（Edit → Bookmarks：Toggle bookmark / Goto previous / Goto next / Clear all bookmarks）；
  contrib 插件 `BrowseTracker`（浏览标记历史，另一套机制）。
- **核验**：VS Code 本体 `resources/app/out/**` 全量检索 `bookmark` 仅命中 codicon 图标名与扩展徽章样式
  （`M.bookmark.id`、`extension-bookmark`），**不存在书签功能/命令**；扩展源码全库无 bookmark 引用。
- **结论**：`docs/对齐对照.md` §5 Edit 行“Bookmarks 由 VS Code 原生书签承担”为错误表述。
  → 修正为“VS Code 无内置书签；CB 书签为未对齐项（可选实施 R10）”。

### M2. “项目自定义变量”的 CB 依据不成立（语义修正）

- **核验（CB 25.03 全树检索）**：
  - 字符串 `codeblocks_project_custom_variables` 在 `codeblocks-src/` **0 命中**；公开代码搜索（grep.app）**全局 0 命中**；
    `cbProject` 无 `SetVariable/GetVariable`（全树仅 `uservarmanager.h` 的同名 API，属**全局**编译器变量）；
    `SaveExtendedData`（扩展注释所引）在 CB 源码中不存在。
  - CB 实际机制一：`<Environment><Variable name value/>`（项目级在 `<Build>` 下、目标级在 `<Target>` 下）
    → `projectloader.cpp:900-915 DoEnvironment` → `CompileOptionsBase::SetVar`
    → `macrosmanager.cpp:217-243 ReadMacros/RecalcVars` 并入宏表（**键名大写**；目标覆盖项目；上一个目标变量在重算时移除）
    → `$(VAR)` 在构建命令（`compilercommandgenerator.cpp:579`）、运行命令（`compilergcc.cpp:2127`）展开。
  - CB 实际机制二：Build options 对话框「Custom variables」页 = 编辑上述 `<Environment>` 变量
    （`compileroptionsdlg.cpp:587 DoFillVars`、`:1206-1240 DoSaveVars`，作用域随对话框树选中「项目/目标」）；
    页面保存写回即 `SaveEnvironment`（`projectloader.cpp:1423-1440`，按 name 排序输出）。
- **扩展现状**：
  - `<Environment>`：已解析（`src/model/parser.ts:478-522`）、已写回（`src/model/projectWriter.ts:114-122/211/311`）、
    Run/Debug 已注入进程环境（`src/extension.ts:4991-4993`、`:5083-5093`，对齐 CB 的“仅 Run/Debug”表述）；**无编辑 UI**。
  - 「项目设置」tab 的 `customVariables` 写入的是 `Extensions/codeblocks_project_custom_variables`
    （`src/model/customVariables.ts`）——CB 25.03 核心**无消费点**（脚本可经 `FindExtensionElement` 自行读取，属社区约定）。
  - `$(VAR)` 宏展开：`replaceCbMacros` 只查内置宏 → `process.env` 回退（`src/compiler/cbMacros.ts:238-239`），
    **不包含** `<Environment>` 变量 → 与 CB 不一致（见 R2）。
- **结论**：修正 C3 项文档语义；新增 R1（编辑 UI）与 R2（宏展开）完成对齐。原「项目自定义变量」tab 可保留并
  标注为“扩展增强（脚本约定节点）”，或改名避免与 CB「Custom variables」混淆。

### R1 环境变量编辑 UI（CB Build options → Custom variables 页）

### R2 `<Environment>` 变量接入 `$(VAR)` 宏展开（语义对齐）
- **CB 依据**：`macrosmanager.cpp:217-243`（ReadMacros 大写键；target 覆盖 project；`RecalcVars:246-260` 目标切换清理）、
  `compilercommandgenerator.cpp:579`（最终命令统一 ReplaceMacros）、`compilergcc.cpp:2127`（Run 命令行）、`:2486`（构建循环按目标重算）。
- **现状**：`replaceCbMacros` 未注入 `<Environment>`（`cbMacros.ts:238-239` 仅 `process.env` 兜底）；
  构建命令生成调用点（`commandGenerator.ts:266/797`、`buildEngine.ts:159/749/1297...`）均未传 env 变量。
  → 使用 `$(VAR)` 的工程在 CB 可用、在扩展**展开为空**。
- **实现方式**：`replaceCbMacros` 增加 envVars 来源（查表顺序：内置宏 → 项目 env → 目标 env（大写键比较）→ process.env 兜底）；
  `commandGenerator/buildEngine/scriptRunner/run()/debug()` 调用点传入 `project.envVars + target.envVars`；
  构建多目标时按目标重算（已有逐目标渲染路径，逐调用点注入即可）。
- **影响**：宏展开结果变化（预期对齐 CB）；无该变量定义的工程零变化。**成本**：≈150 行 + 宏回归测试（含大小写/覆盖/清理 3 组断言）。
- **注意**：CB 中 env 变量可覆盖同名内置宏（ReadMacros 在 RecalcVars 内置宏之后执行）——实现时按 CB 排序，
  同时对 `TARGET_OUTPUT_FILE` 等核心宏做防覆盖测试以免回归。

### R3 调试器源目录搜索（项目级 search_path + 其他工程目录）
- **CB 依据**：`debuggergdb.cpp:321-340 ParseSearchDirs`（`<Extensions><debugger><search_path add="…"/>`）、
  `:832`（启动时逐个 AddSourceDir）、`:994-1015 AddSourceDir`（`ReplaceEnvVars` + `ConvertToGDBDirectory` → 驱动 `directory` 命令）；
  其他工程目录由配置 `add_other_search_dirs`（默认 false，`debuggeroptionsdlg.cpp:130/227`）门控（`debuggergdb.cpp:805-826`）。
- **现状**：扩展调试适配器**未发任何源目录命令**（`src/debug/*.ts` 检索无 `directory/environment-directory`）；未解析 `search_path`。
- **实现方式**：解析 `Extensions/debugger/search_path`（parser 增行）；会话启动后在 loaded/initialized 后逐个发

  以设置 `codeblocks.debug.addOtherProjectDirs` 开启）。
- **影响**：仅调试会话附加命令，无源码搜索时避免“源码找不到”。**成本**：≈100 行 + 解析/转义测试。

### R4 项目级远程调试（嵌入式关键项）
- **CB 依据**：
  - 存储：`remotedebugging.h`（`connType`：TCP=0 / UDP=1 / Serial=2；`IsOk()` 判定“IP+端口”或“串口+波特率”齐备；`MergeWith` 语义 = 目标覆盖项目字段、附加命令**换行追加**）；
    `debuggergdb.cpp:382-437 ParseRemoteDebuggingMap`、`:439-495 SetRemoteDebuggingMap`（字节级节点/属性名取证）。
  - 应用：`gdb_driver.cpp:141-260 Prepare` 固定顺序——… → 源目录命令 → `set args` → `additional_cmds_before` →
    `additional_shell_cmds_before`（`shell ` 前缀）→（Serial 时 `set remotebaud <baud>`）→
    `target [extended-]remote tcp:<ip>:<port> | udp:<ip>:<port> | <串口>`（`gdb_commands.h:1711-1745`，命令经 ReplaceMacros 展开）
    → `additional_cmds` → `additional_shell_cmds_after`；
  - 行为：`gdb_driver.cpp:279-292/315` 远程模式 Start 用 `continue`（连接既有目标而非 `run`）；`debuggergdb.cpp:891/937` `skipLDpath` 控制
    LD_LIBRARY_PATH（Windows 为 PATH）注入；失败信息按 `gdb_commands.h:1754-1798` 典型错误（No route to host / Connection refused / packet error 等）提示。
- **现状**：扩展无远程调试（适配器仅本地 launch/attach；无 remote 概念）；parser/writer 未触该节点（Extensions 原样透传，数据不丢）。
- **实现方式**：① parser 解析 remote_debugging（项目级 + 目标级 `MergeWith` 合并）；② launch 配置增加 remote 字段；
  ③ 会话 Prepare 复刻上述顺序（before → connect → after）；远程时程序启动用 `continue` 而非 `run/start`，断点照常；
  ④ 工程属性面板新增「调试器」tab（search_path + 每目标 remote 表单 + 项目级默认行；Serial 时“波特率/端口”互斥显示，对齐 `debuggeroptionsprjdlg.cpp:293-305`）。
- **影响**：新增工作流（不影响本地调试路径）；对 OpenOCD/串口目标可直达。**成本**：≈400 行 + 32 断言级别测试（命令序列可 mock gdb 验证）。
- **建议**：⭐ 优先（用户环境含 RISC-V 工具链，CB 的嵌入式远程调试是用户迁移的关键场景之一）。

- **评估说明**：`watch_args/watch_locals/eval_tooltip` 为 CB 内部 UI 行为，DAP 已覆盖（变量作用域/悬停求值），不做。

- **成本**：≈200 行 + 测试（对齐导出裁剪规则：仅该目标文件/选项；虚拟目标不导出）。

### R10 书签（Toggle / Goto previous / Goto next / Clear all）
- **CB 依据**：`main_menu.xrc:192-210`；editor 内 marks（行号槽固定书签）。
- **现状**：扩展无；VS Code 无内置替代（M1 已取证）。
- **实现方式**：扩展自管（`globalState` 或工作区存储，文件→行号列表）；命令 4 个 + Edit 菜单项 + 快捷键（避开 VS Code 默认，
  如 Alt+F3/F4? 需与托管表冲突检测联动）；行号槽/装饰（`TextEditorDecorationType`）可选；文件变更（编辑后行号漂移）按“行号近似 + 内容校验”处理。
- **成本**：≈250 行 + 测试。**价值**：中（与“生态书签扩展”重复——也可在文档指引用户安装 Bookmarks 扩展，评估二选一）。

### R11 Open include file（打开光标处 #include）
- **CB 依据**：`codecompletion.cpp:577`（`idMenuOpenIncludeFile _("Open include file")`，clangd_client:908 同款）。
- **现状**：扩展无（clangd 扩展提供 Go to Definition 可间接跳转，但对未构建/未索引工程无效）。
- **实现方式**：命令 + 编辑器右键 when 条件（行匹配 `#include`）；解析引号/尖括号 → 搜索顺序：当前文件目录 →
  目标 includeDirs（宏展开）→ 工作区已打开文件 → 系统 include（跳过）；命中则打开（多候选 QuickPick）。
- **成本**：≈150 行 + 测试。**价值**：中。

### R12 Add TODO item…（+ TODO 关键字设置）
- **CB 依据**：`plugins/todo`：`todolist.cpp:176-190`（Edit 菜单 `Add Todo item...` + View → Todo list）、`addtododlg.cpp`
  （类型/用户/优先级/日期 → 生成注释行）。
- **现状**：扩展有 TODO 扫描（`src/tools/todoScanner.ts`，固定 TODO/FIXME/NOTE/HACK/XXX）+ `codeblocks.todoList` 命令；
  缺“插入 TODO 注释”命令与关键字/大小写设置。
- **实现方式**：命令 `codeblocks.todo.add`（当前行插入 `// TODO(user): …`，QuickInput 类型/用户/文本）+ 设置
  `codeblocks.todo.keywords`（复用扫描器参数）。
- **成本**：≈100 行 + 测试。**价值**：低-中。

### R13 从模板新建 / 保存为模板
- **CB 依据**：`projecttemplateloader.cpp`（`CodeBlocks_template_file`，用户模板目录）+ `newfromtemplatedlg.cpp` +
  `main_menu.xrc:32`（File → New → From template…）+ `:87`（Save project as template…）。
- **现状**：扩展只有内置工程模板（8 类），无用户模板机制（新建文件也无模板）。
- **实现方式**：定义扩展的模板目录（如 `<工程>/templates` 或用户 globalStorage）；「新建工程」向导增加“来自模板”；
  “保存工程为模板”命令（复制 .cbp + 骨架文件）。若采用 VS Code snippet 只能覆盖文件级，工程级需自实现。
- **成本**：≈300 行 + 测试。**价值**：中低（团队脚手架场景）。

### R14 更多工程模板（点名制）
- **CB 依据**：`scriptedwizard/resources/`：AVR、Arduino、MSP430、MCS51、TriCore、OpenCV、Matlab CSF、LF（Lex/Yacc）、Plugins。
- **现状**：扩展已内置 8 类（C/C++ Console / StaticLib / SharedLib / Empty + GLFW/SDL2/wxWidgets/Qt）。
- **实现方式**：纯数据模板追加（每模板 ≈30-60 行 + 说明文件）；按用户点名实施（建议优先 AVR/MSP430——与嵌入式工具链呼应）。
- **成本**：每模板 ≈60 行。**价值**：低（点名）。
