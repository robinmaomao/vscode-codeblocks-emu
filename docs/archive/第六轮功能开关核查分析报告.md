## 1. 核查方法

- **扩展侧**：
  1. 全量清点 `package.json` 设置（7 分区 47 项）及每项的读取点；
  2. 逐条审查激活 / 构建 / 运行 / 调试 / 工程打开 / 编辑器 / 监视器的全部**自动行为**（`activate()` 的 `onDid*` 注册、生命周期函数、定时器、文件监视器）；
  3. 对每个自动行为核对是否存在设置门控。
- **CB 侧**：递归扫描 `codeblocks-src/src` 全部 `Read*/Write*(_T("…"), default)` 配置键（compilergcc、compileroptionsdlg、environmentsettingsdlg、projectmanagerui、debuggergdb、debuggermenu、cbplugin、debuggermanager、main/app、configmanager 等），提取「配置键 + 默认值 + UI 标签（XRC）」。
- **交叉对照**只保留同时满足两个条件者：**① CB 用配置开关控制某行为；② 扩展实现了该（或近似）行为，但没有任何设置可关**。
- 已处理项不再重复：`saveHtmlLog`（69 轮）、`findFileOpen`（批一）、`asmUsesCompilerVar` / `responseFile`（第四轮）等；`clangd.*`、`debug.registers` 等**已有门控**的设置也在 §7 列出以证明覆盖范围。

## 3. 主发现详述（F1–F4）

### F1 构建结束自动聚焦 Build Log（成功/无警告也聚焦）

**扩展现状（无条件）**

- `finishBuildSummary()`（`src/extension.ts:5678`）末尾**无条件**执行 `codeblocks.buildLog.focus`（`extension.ts:5714`）。
- 调用链：`buildWorkspace`（`:4594`）结束 `reportBuildResult :4695` + `finishBuildSummary :4696`；`buildSingleProject`（`:4703`）结束 `:4783-4784`；单文件/清理等流程同理 —— **成功、失败、取消都会把底部面板切到 Build Log**。
- 相关：构建**开始**时 `outputChannel.show(true)`（`:4622 / :4744 / :4815`）——此项**与 CB 一致，不需门控**：CB 在 `PrintBanner()`（`compilergcc.cpp:1788-1791`）中无条件 `SHOW_LOG_MANAGER`，build/clean/run 各路径（`:1972/:2521/:2527/:3156`）都会弹出消息面板。
- 附带：失败 toast 无条件弹（`:4562`）；成功 toast 已由 `codeblocks.ui.quietSuccess` 门控（`:4557`）。

**CB 证据（有开关）**

- `compilergcc.cpp:4064-4107`（`OnJobEnd` 收尾）：
  - 有错误（`:4069` 起）：`/auto_show_build_errors`（**默认 true**）决定是否显示消息面板 → 然后**总是**切到 Build messages（`:4074-4075`）→ `/auto_focus_build_errors`（**默认 true**，`:4077`）决定是否聚焦第一个错误。
  - 无错误（`:4082` 起）：若当时活动日志窗为 Build log —— 有警告且 `/auto_show_build_warnings`（**默认 true**，`:4097`）→ 保持显示；否则 `HIDE_LOG_MANAGER`（`:4107`，配合 `/auto_hide`＝自动隐藏时才收起）。
- 三键属于 **message_manager** 命名空间（`:4069/4077/4097` 处 `GetConfigManager(_T("message_manager"))`）。
- UI：Settings → Environment →
  - `env_settings.xrc:459` **Auto show/hide message pane**（`/auto_hide`，默认 false；开启后才启用下面三项）
  - `env_settings.xrc:482` **Keep open after build errors**（`auto_show_build_errors`，默认 true）
  - `env_settings.xrc:493` **Focus first error in the editor after build finishes**（`auto_focus_build_errors`，默认 true）
  - 读写：`environmentsettingsdlg.cpp:212-220 / 611-615`。

**差异与影响**

- CB 成功（无警告）时**不做任何面板动作**（自动隐藏开启时还会收起）；扩展每次构建都强制聚焦 → 构建成功也会打断用户当前查看的终端 / Problems 面板。

**修复建议（二选一，推荐 A）**

- **方案 A（单枚举，推荐）**：`codeblocks.ui.buildLogAutoFocus`，取值 `errors`（**建议默认**，对齐 CB 默认策略）/ `errorsAndWarnings` / `always`（＝现行为）/ `never`。实现点：`finishBuildSummary(allOk, buildStartMs)` 内经 `buildResultStats()`（`:5058`）即可取得 error/warning 计数。
- 方案 B（三项对齐 CB）：`autoShowErrors` / `autoShowWarnings` / `autoFocusFirstError`（布尔，默认 true/true/true）。
- 备注：CB 的“聚焦”＝跳转编辑器首个错误；如选 `errors`，可顺带用现有 `buildLogTreeProvider.gotoNextError()` 逻辑提供“聚焦首错”。
- 可选附加：失败 toast 静默开关 `codeblocks.ui.quietFailure`（CB 无 toast 对应项，纯扩展选项）。

**落点**：`package.json`（ui 分区）、`src/extension.ts` `finishBuildSummary`、`使用说明.md` §13 设置表、`对齐对照.md`、`test-settings-structure.js`（47→同步）、新增 `tests/test-build-log-focus.js`。

### F2 启动时自动恢复 + 自动打开工程

**扩展现状（无条件）**

- `activate()` 末尾：
  - `await restorePersistedProjects()`（`:1575`；定义 `:2975-2994`）：优先按 `codeblocks.openedWorkspace` 重新打开 **.workspace 全部工程（含依赖）**，否则按 `codeblocks.projectOrder` 列表逐个打开，兜底 `codeblocks.activeProject`。
  - `await autoDetectAndOpenProject()`（`:1578`；定义 `:1605-1650`）：工作区**没有已打开工程**时——唯一未打开 `.cbp`/`.workspace` **直接打开**（`:1636-1640`）；多个则弹多选 QuickPick。
  - `**/*.cbp` 监视器：创建 / 删除时 800ms 去抖重扫（`:1589-1597`）——在工程目录里新建一个 `.cbp` 也可能被自动打开。
- 全程**无任何设置门控**。

**CB 证据（有开关）**

- `/environment/blank_workspace` **默认 true**：`app.cpp:766-769` —— `if (blank_workspace == false) LoadWorkspace();`（即默认**不**加载上次工作区）。
- UI：Settings → Environment → General → **On application start-up**：`Open default workspace` / `Open blank workspace`（`env_settings.xrc:164-169`；读写 `environmentsettingsdlg.cpp:129 / 594`）。
- 相关键：`/open_files`（project_manager，默认 1）——**On project load**：`Open all project files` / `Open last open files` / `Do not open any files`（`env_settings.xrc:200-205`；`cbproject.cpp:643`）——CB 工程加载后默认会打开上次打开的文件。
- 注：CB 没有“扫描目录里的 .cbp 并自动打开”的等价行为——该部分是扩展新增能力，没有 CB 开关可对齐，只能自建开关。

**差异与影响**

- 迁移自 CB 的用户预期「启动＝空白工作区」；扩展默认行为相反（自动恢复 + 自动打开/弹选择）。

**修复建议**

- 新增 `codeblocks.project.autoOpenOnStartup`（字符串枚举）：
  - `restore`＝现行为（恢复上次会话 + 自动打开/提示）；
  - `blank`＝对齐 CB 默认（不恢复、不自动打开，仅保留状态栏入口 / 检测列表）；
  - 可选 `detect`＝扫描但仅提示（不自动打开单文件、不弹多选）。
- 如需保留“单文件直接打开”能力但可关闭，可拆成两个布尔（`restoreOnStartup` / `autoOpenDetectedCbp`）。
- **默认值请用户确认**：改 `blank` 会改变现有体验；改 `restore` 保持现状但需在文档注明与 CB 默认的差异。

**落点**：`package.json`（新增 project 分区或归入 ui）、`extension.ts:1575/1578/1589`、`使用说明.md` §5.1/§13、新增 `tests/test-startup-open.js`（stub `workspaceState`/watcher，三态断言）。

### F3 编辑器激活自动切换活动工程

**扩展现状（无条件）**

- `:666-668`：`onDidChangeActiveTextEditor → syncActiveProjectToEditor()`（定义 `:2699-2722`）：当激活编辑器文件的归属工程**唯一**（或工程树路径唯一包含）时，自动 `setActiveProject(owner)`。
- 活动工程影响：状态栏 Target / Compiler、`F9` 构建对象、**共享文件**的 clangd 编译库归属与重建（`hasSharedFiles()` 时触发 `generateClangdForWorkspace`）。
- 行为已在文档宣传：`使用说明.md:123`「编辑某工程的文件时活动项目会自动跟随」。**无设置**。

**CB 证据（有开关）**

- editor 命名空间 `/sync_editor_with_project_manager` **默认 false**：`main.cpp:5305-5317`（`OnEditorActivated` → `ShowFileInTree(*pf)`，仅**工程树定位**）。
- UI：Settings → Editor → `editor_configuration.xrc:511` **Synchronise Editor with Project Manager**；读写 `editorconfigurationdlg.cpp:152 / 1079`。

**差异与影响**

- CB：默认关、动作弱（树定位，不改构建对象）；扩展：固定开、动作强（切活动工程）。
- 关闭扩展该项后：跨工程编辑时活动工程保持不变，共享文件的补全/诊断需手动切换工程；其余功能不受影响。

**修复建议**

- 新增 `codeblocks.ui.syncActiveProjectWithEditor`（布尔）。
- **默认值请用户确认**：`true`＝保持现状（文档已宣传）；`false`＝对齐 CB 默认。不建议本期实现“仅树定位”的中间态。

**落点**：`package.json`、`extension.ts:666-668 / 2699-2722`、`使用说明.md:123/§13`、`对齐对照.md`、新增 `tests/test-sync-active-project.js`。

### F4 工程树文件固定字母序

**扩展现状（无条件）**

- 文件/目录一律字母序：`sortDirNodes()`（`src/ui/projectTreeProvider.ts:537-543`，目录/分组在前、同类 `label.localeCompare`）；工程根层 `rootNodes.sort`（`:573-581`）；分组子层（`:392` 起）同规则。
- 工程列表本身保持打开顺序（`applyPersistedOrder`，`extension.ts:3013`）。

**CB 证据（有开关）**

- project_manager `/sort_alpha` **默认 false**（＝按 .cbp 中文件的原始顺序显示）：`projectmanagerui.cpp:408`（合成 `ptvsSortAlpha`）、`:892-905`（菜单勾选状态；**开启后禁用 Project Up/Down**）、`:2493-2497`（写入），`:1487-1495`（菜单同步）。
- 即 CB 的 View → *Sort alphabetically* 是可切换项，默认关闭。

**差异与影响**

- 扩展无条件字母序——与 CB 默认（.cbp 原序，通常＝加入顺序）不同；对刻意按功能/层级排列文件的工程，扩展视图顺序与 CB 不一致。

**修复建议**

- 新增 `codeblocks.projectTree.sortAlphabetically`（布尔）。
- **默认值请用户确认**：`true`＝现状；`false`＝对齐 CB 原序（实现上按 `project.files` 插入序即可，目录索引已保序）。

**落点**：`package.json`、`projectTreeProvider.ts`（sortDirNodes / root sort 两处门控）、`使用说明.md` §13、新增 `tests/test-tree-sort.js`。

## 4. 次发现详述（F5–F8，可选/低优先级）

### F5 GDB 启动脚本（`-nx`）

- **扩展现状**：`gdbMiSession.ts:61-66` —— `args = ['-i=mi', '--quiet', ...(userArguments)]`，**不含 `-nx`** → GDB 会执行用户 `%USERPROFILE%\.gdbinit` / `gdb.ini`（可用 `codeblocks.debug.userArguments: ["--nx"]` 手工规避，但默认行为与 CB 相反）。
- **CB 证据**：`disable_init` **默认 true**（`debuggeroptionsdlg.cpp:136`）；`gdb_driver.cpp:104-105 / 127-128` → 传 `-nx`（注释 "don't run .gdbinit"）。UI：`debugger_options_dlg.xrc:93` **Disable startup scripts (-nx) (GDB only)**。
- **建议**：新增 `codeblocks.debug.disableInit`（布尔）。默认值请确认：`true`＝对齐 CB（不执行 .gdbinit，行为变化需写入 release notes）；`false`＝保持现状。
- **落点**：`package.json`（debug 分区）、`gdbMiSession.ts`、`使用说明.md` §13、新增/并入 debug 测试断言启动参数。

### F6 构建进度显示固定开启

- **扩展现状**：每次构建 `withProgress(Notification, cancellable)`（`:4636 / :4756 / :4823`）+ 状态栏 250ms 刷新 `$(sync~spin) Building… (Ns)`（定时器 `:594-609`，tooltip `:4377-4405`）。
- **CB 证据**：compiler `/build_progress/bar` **默认 false**（UI：**Display build progress bar**，`compiler_options.xrc:1249`）；`/build_progress/percentage` **默认 false**（**Display build progress percentage in log**，`:1256`）；读写 `compileroptionsdlg.cpp:627-631`；消费 `compilergcc.cpp:435-438 / 1206-1209 / 1438-1439`。
- **建议（低优先级）**：如需要，新增 `codeblocks.build.showProgress`（`notification`（默认）/ `statusBar` / `none`）。注意 VS Code 通知进度同时承担“取消构建”入口，改 `none` 后仍需保留状态栏停止入口。

### F7 工程树 use_folders / hide_folder_name 无对应开关

- **扩展现状**：仅有 `codeblocks.projectTree.categorize`（默认 true；`:329 / :359-366`）在「类型分组 / 物理目录」间切换——物理目录模式恒等价 CB `use_folders=true`，且无「隐藏文件夹名（平铺文件名）」模式。
- **CB 证据**：`/use_folders` **默认 true**（`projectmanagerui.cpp:406 / 891`；false＝文件平铺、以相对路径文本显示）；`/hide_folder_name` **默认 false**（`use_folders=false` 时以纯文件名显示；`:407 / 893 / 3986-3995`；“use folders 优先”`:410-412`）。
- **建议**：可选新增 `codeblocks.projectTree.useFolders`（默认 true）与 `hideFolderNames`（默认 false），或记录“不移植”（现默认组合与 CB 默认一致，仅缺少数用户才会关闭的开关）。

### F8 HTML 日志缺少 full_command_line 子选项

- **扩展现状**：`saveHtmlBuildLog` 内容固定＝起止时间 + 诊断汇总表（`extension.ts:5725-5762`；纯模块 `htmlBuildLog.ts`），与 CB 默认（不含完整命令行）**行为等价**——仅缺可选的“完整命令行”增强。
- **CB 证据**：`/save_html_build_log/full_command_line` **默认 false**（UI：**Always output the full command line in the generated HTML file**，`compiler_options.xrc:1238`；读写 `compileroptionsdlg.cpp:623 / 2949`；消费 `compilergcc.cpp:1330-1331 / 3901`）。
- **建议**：可选新增 `codeblocks.build.saveHtmlLogFullCommandLine`（默认 false，开启后 HTML 内嵌各编译命令完整命令行）。
