## 1. 已完成层与结果

> **2026-11-04（工程属性面板「无法使用」+ 按钮 UI + 同类配置页复查）**：
> 根因（浏览器实测复现，Chromium 渲染 `dist` 真实 HTML）：
> ① `doSave()` 无条件收集 9 个 tab 的表单，而文件/构建选项/搜索目录/脚本/设置/备注/虚拟目标表单**只在切到对应 tab 时才渲染** ⇒
> 未访问过的 tab 元素为 `null`，`collectFileForm` 抛 `TypeError: Cannot read properties of null (reading 'value')` ⇒
> **保存静默失效**（webview 控制台报错，用户侧只是"点了没反应"）；
> ② 英文界面下内联 `<script>` **整段语法错误**（译文 `compiler's` / `CB's` 的撇号截断了 `'...'` 字符串）⇒ 面板脚本根本不执行（tab/按钮全失效）；
> ③ `.list-actions` 无 `flex-wrap`、`button` 无 `white-space: nowrap`、`.layout` 用 `240px 1fr` ⇒ 窄面板下 6 个中文按钮被压到单字宽度**竖排**、右侧表单被挤成细条。
> 修复：`doSave` 加 `try/catch`（异常写顶栏状态区，复用既有 `保存失败:` 词条，悬停看完整原因）+ 各 `collect*Form` 加元素存在性守卫；
> 目标级 tab（构建选项/搜索目录/构建脚本/调试器）在目标被删除后作用域索引会失效，补 `if (!cur) return;` 跳过；
> 目标改名/删除同步 `remote_debugging`（标题索引，否则保存出孤儿节点）；
> 修正两条英文词条；CSS 加 `button{white-space:nowrap}`、`.list-actions{flex-wrap:wrap}`、`.toolbar{flex-wrap:wrap}`、
> `.layout{minmax(200px,240px) minmax(0,1fr)}` 与 `<720px` 单列堆叠。
> **同类配置页复查**：编译选项面板「应用」此前只改内存模型（不写盘 ⇒ 重开工程即丢），改为经宿主回调

> 手写自定义选项（如 `-pipe`）原样保留；应用失败回发 `error` 在面板可见；应用时目标已被外部改名/删除时直接报错
> （不静默改写工程级选项）；连点「应用」经 promise 队列串行落盘。快捷键面板与编译选项面板同步补 `white-space: nowrap` / `flex-wrap`。

> Makefile 构建/自定义工具按数据块独立解码（跨块汉字被拆成错字）。修复：`src/tools/encoding.ts` 新增
> `decodeOutputLines` / `OutputLineDecoder`（整段 UTF-8 快路径 + 按完整行逐行判定 + 跨块残行保留），
> 覆盖主构建、pre/post 脚本、Makefile 构建、自定义工具输出、GDB 调试输出；工具侧输出捕获
> （探测/版本/反引号/8.3 短路径/clangd）统一改 buffer + `decodeText`；超长命令响应文件按系统 ANSI 代码页写
> （`iconv-lite`，含中文路径 GCC 可读）；`.cbp`/`.workspace` 读取与原文回写保留原编码。
> `npm test` **TOTAL=173 FAIL=0 SKIP=1**（新增 `tests/test-encoding-lines.js`，**25 断言**，含真实 GCC 中文路径用例）；

> 已知限制：`Compile File (Without Project)` 走 VS Code 任务终端（固定 UTF-8），无法解码编译器 GBK 输出（见使用说明 §16）。
