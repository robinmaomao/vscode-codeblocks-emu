## 1. 构建目标选择改为 per-project 记忆

- **状态**：已完成（2026-09-22）
- **实现方式**：`Map<工程filename, 目标标题>` + workspaceState 持久化；工作区构建改为每个工程各自的活动目标；共享文件的 clangd 编译命令按活动工程去重。
- **关联上下文**：与「活动工程跟随编辑器」配套（活动工程切换越频繁，本问题越明显）

### 背景与问题

当前「当前选中的构建目标」用**全局单值**保存：

```ts
// src/extension.ts:54
let selectedTargetTitle: string | undefined;
```

它被 `F9` 构建 / `Ctrl+F10` 运行 / `F8` 调试统一读取（`selectTarget()`）。

问题：多工程共享同一变量，切换活动工程时会互相覆盖/丢失：

1. **目标名不重叠**（如 A 有 `Debug/Release`，B 有 `earphone/earphone_ota`）：在 A 选 `Release`，切到 B 后被重置为 B 的第一个目标；切回 A 又被打回 A 的第一个目标 `Debug`。来回切一次就白选一次。
2. **目标名恰好重叠**（A/B 都有 `Debug`）：在 A 选 `Debug` 会「串味」到 B，反之亦然。

根因在 `selectTarget()` 的兜底：

```ts
if (selectedTargetTitle && titles.includes(selectedTargetTitle)) {
  return selectedTargetTitle;
}
// 未选中 / 目标名对不上：打回第一个目标
selectedTargetTitle = titles[0];
```

### 方案

把单值改成 `Map<工程路径, 目标标题>`，key 用工程的 `filename`（`.cbp` 绝对路径）：

```ts
const selectedTargets = new Map<string, string>(); // filename -> targetTitle
```

切换活动工程时按当前工程的 `filename` 读写自己的目标，缺省才回落 `titles[0]`。

### 改动点清单

1. 声明：`selectedTargetTitle` 单值 → `selectedTargets: Map<string, string>`。
2. `selectTarget()`：按 `activeProject.filename` 从 Map 取值；命中且仍存在于目标列表则返回；否则用 `titles[0]` 并写回 Map。
3. `promptSelectTarget()`：用户选完后写回 Map（当前工程的 key）。
4. `updateTargetStatusBar()`：显示当前工程在 Map 中的值（取不到则显示 `—`）。
5. `openProject()` 里初始化目标那几行（约 L542）：改成「该工程在 Map 中无记忆时才置为 `titles[0]`」。

### 验收标准

- 打开 A、B 两个工程，A 选 `Release`、B 选 `earphone_ota`；来回切换活动工程，两个工程各自保持自己的目标选择，状态栏 `Target:` 正确显示。
- A、B 都有 `Debug` 时，在 A 选 `Debug` 不影响 B 的当前目标。
- 单工程场景行为与之前一致（默认第一个目标）。

### 可选扩展（原为「本次不做」，现已全部实现）

- ✅ 已实现：将 Map 持久化到 `workspaceState`（`codeblocks.selectedTargets`），重载窗口后每个工程的目标选择仍记得。
- ✅ 已实现：该 Map 与 `codeblocks.activeProject` 持久化保持一致的生命周期。
