# 测试方案（Code::Blocks for VS Code）

> 面向本仓库的**分层自动化测试方案**：契约 → 无头单元 → 真实工程 E2E → 像素视觉 → 性能 → 打包 → 真实宿主。
> 运行环境、门禁阈值与产物约定见下；覆盖台账见 [测试覆盖矩阵](./测试覆盖矩阵.md)，性能数据见 [性能基准](./性能基准.md)。

## 1. 分层结构

| 层 | 目录 | 内容 | 运行方式 |
|----|------|------|----------|
| L-1 静态契约 | `tests/contract/` | 贡献点/激活事件/命令注册交叉校验、语言语法、调试器 schema、资源与版本一致性、NLS 键集合 | `npm run test:contract` |
| L0 无头单元/集成 | `tests/test-*.js` | 解析/写回/命令行/宏/缓存/键位/书签/工具等 135+ 项（dist 层，无 VS Code 宿主） | `npm test` |
| L1 真实工程 E2E | `tests/e2e/` | 真实工具链构建矩阵、工作区依赖、工具类功能（临时目录探针工程） | `npm run test:e2e` |
| L2 真实宿主 | `tests/host/` | 用 `@vscode/test-electron` 启动**真实 VS Code**（默认下载 `engines.vscode` 最低版本 1.85.0，可用 `CB_VSCODE_PATH` 指向本机安装）驱动真实命令/视图/调试/设置写入 | `npm run test:host` |
| L3 像素视觉回归 | `tests/visual/` | 12 个 WebView HTML 面 × 2 主题 = 24 基线；pixelmatch 容差判定 | `npm run test:visual` |
| L4 性能基准 | `tests/perf/` | 12 项微基准 + 真实构建耗时；硬预算 fail / 漂移 warn | `npm run test:perf` |
| L5 打包与安装 | `tests/pack/` | VSIX 打包内容核对 + 隔离 user-data-dir 安装激活冒烟 | `npm run test:pack` |
| L6 手工验收 | [手工验收清单](./手工验收清单.md) | 拖拽排序、悬停菜单、原生 UI 截图留档等不可自动化项 | 人工 |
| CI | `.github/workflows/ci.yml` | windows-latest：契约 + 无头 + 打包冒烟必跑；E2E 按工具链门控；视觉/性能/宿主为手动可选作业 | GitHub Actions |

一键串联：

```powershell
npm run test:all          # contract + unit + e2e + visual + perf + pack（不含 host）
npm run test:all:host     # 追加真实宿主集成（需 GUI 会话）
```

## 2. 统一运行器

`tests/run-all.js` 支持分组、筛选与 JSON 报告：

```powershell
node tests/run-all.js --group unit                # 默认（等价 npm test，仍写 .cbtest.txt）
node tests/run-all.js --group visual --filter props   # 只跑工程属性面板相关面
node tests/run-all.js --group all --json out.json
```

- 每层独立退出码；`all` 中任一层失败即整体失败。
- 缺失的层（尚未创建脚本）→ `(无脚本) SKIP`，不计失败。
- 结果 JSON 默认落 `.cb-tools/report-<group>.json`（临时目录，不入库）。

## 3. 视觉回归（L3）

- **范围**：仅 WebView HTML 面（原生 VS Code UI 不做像素门禁，改由宿主测试截图留档 + 手工清单覆盖）。
- **面清单**：工程属性面板 9 个 tab（构建目标/虚拟目标/文件/构建选项/搜索目录/构建脚本/项目设置/备注/调试器）、快捷键面板、编译选项面板、HTML 构建日志 —— 共 12 面 × dark/light 两主题。
- **HTML 来源**：dist 真实代码生成（`ProjectPropertiesPanel.buildHtml()` 等），不维护手写快照。
- **确定性措施**：固定视口与 DPR=1；注入 `--vscode-*` 主题变量与固定字体栈；HTML 头部注入时间/随机冻结与 `acquireVsCodeApi` shim；禁用动画/过渡/光标、隐藏滚动条；等待字体与双 rAF 后截图。
- **判定**（容差）：`pixelmatch threshold=0.1` 且差异像素占比 **≤ 0.5%**。
- **基线**：`tests/visual/baselines/<theme>/<surface>.png`（入库，PR 可评审）。
- **刷新基线**：`npm run visual:baseline`（或 `node tests/visual/test-visual.js --update`）。
- **失败产物**：`.cb-tools/visual-diff/<theme>/<surface>.{expected,actual,diff}.png`。
- **浏览器**：默认系统 Edge（`CB_VISUAL_BROWSER=msedge`）；如需 Chromium 固定版本：`npx playwright install chromium` 并设 `CB_VISUAL_BROWSER=chromium`。
- **注意**：基线是「本机字体/DPI/浏览器版本」基准，跨机差异属漂移而非功能缺陷；换机后重跑 `--update`。

## 4. 性能基准（L4）

- **口径**：warmup 后取 N 次采样，报告 median / p95 / min；单线程串行执行（真实构建类基准独占）。
- **判定**（双阈值）：**预算门禁用 `min`**（最小采样 → 抗机器负载尖峰）`min > 预算` → **失败**；`median > 1.8 × 基线` → **告警（不失败）**；首次超预算会自动**复核一次**，复核通过降级为告警。
- **预算来源**：首次基线固化时自动取 `max(3×median, 下限)`，可在 [tests/perf/baseline.json](../tests/perf/baseline.json) 人工调整后提交。
- **基准清单**：大工程解析（1200 文件/6 目标）、解析缓存命中、序列化往返、编译命令行生成+宏展开（1200 文件）、输出解析→诊断（2 万行/2000 条）、选项 XML 加载、LRU+盘符归一化、虚拟文件夹索引、增量判定 `isUpToDate`、真实全量构建、真实增量 up-to-date、真实单文件编译。
- **产物**：报告 [性能基准.md](./性能基准.md)（生成）；原始结果 `.cb-tools/perf/perf-<时间戳>.json`。
- **刷新基线**：`npm run perf:baseline`。
- **环境前置**：B7–B10 需要 `gcc` 在 PATH；缺失时自动跳过并记录。

### 5.0 工具链安装（W6，可选）

工具链测试层会自动在 **PATH → `CB_TOOLCHAIN_ROOT`（分号分隔多根）→ `<repo>/.cb-tools/toolchains/**/bin`** 中探测，
因此无需改动系统 PATH：解包到 `.cb-tools/toolchains/<name>/`（已 gitignore）即可被识别。

| 工具链 | 下载 | 覆盖场景 | 本机状态 |
|--------|------|----------|----------|
| LLVM/clang | `llvm/llvm-project` releases → `clang+llvm-*-x86_64-pc-windows-msvc.tar.zst` | clang 构建+运行（`--target=x86_64-w64-mingw32` 复用 MinGW 运行时）、`--target=riscv64-unknown-elf` 交叉 | ✅ 23.1.3（riscv 后端可用；官方构建**未含** avr/msp430 后端） |
| AVR GCC | `ZakKemble/avr-gcc-build` releases → `avr-gcc-*-x64-windows.zip` | AVR 交叉编译（`-mmcu=atmega328p`，ELF `e_machine=83`） | ✅ 16.1.0 |
| RISC-V GCC | `xpack-dev-tools/riscv-none-elf-gcc-xpack` releases → `*-win32-x64.zip` | RISC-V 交叉编译（ELF `e_machine=243`） | ✅ 15.2.0 |
| MSP430 GCC | TI MSP430 GCC（需交互下载） | 未装时 SKIP | ❌ 未安装 |
| SDCC / TCC | 官方站点 | MCS51 交叉编译 / 异构 C 编译器 | ❌ 未安装 |

> `.tar.zst` 解包：Windows 自带 `bsdtar` 需要外部 `zstd`，且官方 LLVM 包使用 1GB 窗口 → 需
> `zstd -d --long=30 -c <file> | tar -xf - -C <dest> --strip-components=1`。
>
> 网络受限环境提示：直连 GitHub release 资产可能被限速（实测 ~15 KB/s）；`curl`/Node 若报
> `CRYPT_E_NO_REVOCATION_CHECK` / `UNABLE_TO_VERIFY_LEAF_SIGNATURE`，说明出口代理做了 TLS 中间人，
> 可导出系统根证书后用 `NODE_EXTRA_CA_CERTS=<pem>`；加速可走清华 TUNA
> `mirrors.tuna.tsinghua.edu.cn/github-release/...`（LLVM，实测 13MB/s）或 `ghfast.top` 代理（xpack/ZakKemble）。

## 5.2 L5 打包与安装（`tests/pack/test-pack.js`）

- P1 `vsce ls` 内容核对：包含 `bundle/extension.js`、语法/语言配置、资源 XML、NLS、README/LICENSE/CHANGELOG；**不含** `tests/`、`test-project/`、`src/`、`dist/`、`*.map`
- P2 真实打包（`vsce package --no-dependencies`）→ 产物落 `.cb-tools/pack/`，体积合理性检查
- P3 隔离 `--user-data-dir`/`--extensions-dir` 安装 → `--list-extensions` 校验版本 → 卸载
- 无 `code` CLI 时 P3 自动 SKIP（可用 `CB_CODE_CLI` 指定）

## 5.3 L2 宿主集成（`tests/host/`）

零依赖自研框架（`suite/test/ctx.skip`，不引入 mocha），`runTest.js` 负责启动宿主：

| 用例组 | 断言要点 |
|--------|----------|
| 激活与贡献面 | 扩展激活；**contributes 全表 103 条命令逐一注册**；运行时内部命令（视图焦点/动态菜单）；5 个视图 `<viewId>.focus`；60 设置项默认值齐备；`ld/asm/xm` 语言注册 + 按扩展名正确关联语法 |
| 无工程优雅降级 | 构建/运行类 9 条、面板工具类 16 条、调试辅助 4 条命令在「无工程/无会话」下均不抛异常 |
| keybindings 托管写入 | `check`（QuickPick 场景自动关闭 UI）；`apply` 真实写入 `<user-data>/User/keybindings.json`（含覆盖键的正向条目 + 默认键移除规则）；`reset` 清理文件条目并清空设置 |
| 仓库探针工程 | `test-project` 结构（3 个 `.cbp` + 1 个 `.workspace`）与调试目标产物存在性 |
| 真实调试会话 | 工作区内现场 gcc 编译探针 → F5 启动 `codeblocks` 会话 → 命中断点（行号精确匹配）→ `scopes`/`variables`（`left=2/right=3`）→ 终止事件；全程记录 DAP 报文轨迹 |

**宿主层两条硬约束（实测，勿踩）**：

1. **不要从测试扩展调用 `vscode.debug.startDebugging`**：`--extensionTestsPath` 方式下该 API 会永久挂起（内置 `ms-vscode.js-debug` 的 `pwa-node` 同样挂起，且工作台仍能响应其它命令）——属测试宿主限制而非扩展缺陷。改用「工作台侧发起」：写 `.vscode/launch.json` + 触发 `workbench.action.debug.start`，只以事件与 `activeDebugSession` 观测结果。
2. **断点必须落在会话所属工作区文件夹内**：VS Code 只把该文件夹内的断点下发给适配器（文件夹外的断点不会产生 `setBreakpoints`）。探针源文件因此在工作区内生成并现场编译。
3. 单用例超时（`CB_HOST_TEST_TIMEOUT`，默认 180s）+ DAP 请求级超时：任何 UI 等待都会失败而不是挂死整轮。

## 5.4 L1 调试 E2E（DAP 协议级，`tests/e2e/test-e2e-debug.js`）

直接以 DAP 客户端驱动扩展的 gdb 适配器（真实 gdb 8.1 + MI），覆盖 68 条断言：
断点四类型（普通/条件/命中次数/日志断点）、单步四类（含指令级）、线程与栈、变量嵌套与 `setVariable`、表达式求值、反汇编、内存读写、数据断点、指令断点、运行到光标、SetNextStatement、异常断点、用户命令（MI/CLI）、多会话路由、terminate。

> 本机 GDB 8.1 限制（已实测并据实断言）：被调试进程内函数求值 `-data-evaluate-expression "add(2,3)"` 与全量寄存器读取会触发 GDB 崩溃（0xC0000005），故寄存器全量读取由 `codeblocks.debug.registers`（默认关）门控；`jump file:line` 语义为「从新地址继续执行」。

| 场景 | 工具链 | 验证方式 | 本机结果 |
|------|--------|----------|----------|
| S1 家族台账 | 随包 `resources/compilers/options_*.xml` | 家族清单与公共选项组齐备性（静态核对） | OK（19 个家族） |

| S4 clang | `clang/clang++/llvm-ar`（`--target=x86_64-w64-mingw32` 复用 MinGW 运行时） | 全量构建 + 运行产物校验输出 | OK |
| S5 clang 交叉目标 | `clang --target=<riscv64-unknown-elf\|avr-unknown-unknown\|msp430-unknown-unknown>` | 交叉对象文件 ELF 魔数 + `e_machine` 校验；**先按 `--print-targets` 判定后端是否编译进本机 clang** | RISC-V OK；avr/msp430 SKIP（后端未包含） |
| S6 AVR GCC | `avr-gcc`（`-mmcu=atmega328p`） | 同上（`e_machine=83`） | OK |

工具链探测优先级：`PATH` → `CB_TOOLCHAIN_ROOT` → `.cb-tools/toolchains/**/bin`。**缺失即 SKIP 且计入 SKIP 数**（不静默通过）。
探针工程的编译/链接选项按 Code::Blocks XML 语义注入（单 `<Compiler>`/`<Linker>` 块内多个 `<Add option>`，与用户工程一致）。

## 5.6 CI（`.github/workflows/ci.yml`）

| 作业 | 触发 | 内容 |
|------|------|------|
| `core` | push / PR | `npm ci` → `compile` → `bundle` → `test:contract` → `npm test` → `test:pack` → `coverage:matrix`（产物归档） |

## 6. 产物治理

- 所有临时产物落 `.cb-tools/`（已 gitignore）；E2E 探针工程用 `mkdtemp`；L2 宿主测试使用隔离 `--user-data-dir`。
- 真实构建基准在临时副本上执行，不触碰 `test-project/` 原目录。
- `npm test` 仍写入 `.cbtest.txt`（gitignore，兼容既有习惯）。

## 7. 维护约定

- 新增无头测试：`tests/test-*.js`，末行输出 `N pass, M fail` 摘要。
- 新增分层测试：放对应目录并匹配 `test-*.js`（host 层为 `runTest.js`）。
- 修改 WebView HTML/样式后：`npm run visual:baseline` 刷新基线，并在提交信息中说明视觉变更。
- 产品改动涉及热路径时：`npm run test:perf` 确认预算未被击穿。
- 契约变化（命令/设置/视图/语法）后：`npm run coverage:matrix` 刷新台账。
