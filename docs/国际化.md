# 国际化（中英文）——约定、实现与批次台账

> 语言：**中文** ｜ [English](./国际化.en.md)
>
> 本文件是扩展中英双语的**单一约定来源**：静态贡献走 `package.nls.*.json`（跟随 VS Code 显示语言），
> 运行时文案走 `i18n.t()` + 词条表（受设置 `codeblocks.ui.language` 控制，可即时切换）。
> 批次进度见 §4，未完成部分见 §5。

## 1. 两条链路（为什么是两套机制）

| 链路 | 覆盖对象 | 切换方式 | 生效时机 |
| --- | --- | --- | --- |
| **静态贡献** | 命令标题、设置描述/枚举说明、视图名、视图容器标题、欢迎语、调试器片段描述、`displayName` / `description` | VS Code 显示语言（`package.nls.json` 英文默认，`package.nls.zh-cn.json` 中文） | 语言包/显示语言变化后**重载窗口** |
| **运行时文案** | 弹窗、QuickPick/InputBox 文案、状态栏文本与 tooltip、WebView 面板标题与外壳 | 设置 `codeblocks.ui.language`（`auto` / `en` / `zh-cn`） | **即时生效**（设置变更监听刷新） |

这不是设计冗余，而是 VS Code 的硬约束：`package.json` 里的贡献项由宿主在**扩展加载前**解析，
占位符 `%key%` 只能按当前显示语言展开（实现见 VS Code `extensionNls.ts` 的 `replaceNLStrings`：
**仅当整个字符串恰为 `%key%` 时替换**，键缺失会原样显示 `%key%`），扩展代码无法运行时改写；
反之，运行时文案若只跟随显示语言，就无法满足「界面用英文 VS Code、扩展想看中文」这类需求。

> 因此 `ui.language` 与 VS Code 显示语言**不一致**时会出现「混语言」：命令面板/设置界面跟随显示语言，
> 弹窗/面板跟随 `ui.language`。切换命令的提示里明确说明了这点，并给出「重载窗口」按钮。

## 2. 运行时实现

| 文件 | 作用 |
| --- | --- |
| [`src/i18n/core.ts`](../src/i18n/core.ts) | 纯逻辑（无 vscode 依赖，可无头单测）：`resolveLanguage(setting, envLanguage)`、`formatSource(template, args)`、`lookupTemplate`、`translate` |
| [`src/i18n/index.ts`](../src/i18n/index.ts) | 扩展入口：解析并缓存生效语言（`uiLanguage()`）、`t(source, ...args)`、`tr(中文原文)`、`htmlLang()`、`refreshUiLanguage()`、`translationsTable()` / `webviewTranslationsTable()` |
| `src/i18n/strings.zh-cn.json` | 词条表：**英文源串为键** → 中文译义（与 `package.nls.json` 的「英文默认」一致） |
| `src/i18n/strings.zh-cn.webview.json` | WebView 反查表：**中文原文为键** → 英文源串（面板模板插桩 `i18n.tr()` 用） |
| [`src/build/logLang.ts`](../src/build/logLang.ts) | 构建日志统一入口 `logT(英文源串, ...args)`（受 `codeblocks.log.english` 控制，见下方「三种 API」） |

### 三种运行时 API（选错会破坏语言一致性）

| API | 用于 | 语言规则 |
| --- | --- | --- |
| `i18n.t('English source', ...args)` | 弹窗 / QuickPick / InputBox / 状态栏 / 进度 等**界面文案** | 跟随 `codeblocks.ui.language` |
| `logT('English source', ...args)`（`build/logLang.ts`） | **输出通道日志**（构建日志、诊断转储、clangd 状态行…） | `codeblocks.log.english=true` → **恒英文**（对齐 CB 原文）；否则同 `i18n.t` |
| `i18n.tr('中文原文')` | **WebView 面板模板**（含内联 `<style>`/`<script>` 文本） | 中文即键；英文态按反查表换成英文源串，中文态原样返回 |

- 构建相关日志**必须**用 `logT`：`src/build/**` 直接调用历史 `msg(zh, en)` 已被守卫禁止（S8b），
  历史入口 `msg(zh, en)` 仅为兼容保留。
- `logT` 只在「日志文案」场景替换 `i18n.t`；同样是 `{0}` 占位符规则，两者可互相替换而不改词条。
- 历史 `msg(zh, en)`（`logLang.ts`）仍存在少量「英文侧为 CB 原文、中文侧为通知文案」的双写场景（构建结果 toast），
  新代码不要再新增。

约定：

1. **英文为源串**：代码里写 `i18n.t('Build finished')`，中文只出现在词条文件里。
2. **占位符 `{0}` / `{1}`**（与 `vscode.l10n.t` 一致）：`i18n.t('Jumped to line {0}', line)`；
   参数缺失时**保留占位符原样**（不静默吞掉，便于定位漏参）；中文可重排占位符（`{1} 的 {0}`）。
3. **消息模板不得内插 `${}`**：`i18n.t(\`已完成 ${n} 项\`)` 会被守卫判为违规 —— 一律写成
   `i18n.t('Finished {0} item(s)', n)`（否则源串无法与词条对齐）。
4. **词条缺失回退英文源串**，不会出现空白或键名泄漏。
5. 命名空间调用 `i18n.t(...)`（不是裸 `t(...)`）：文件内已存在名为 `t` 的局部变量（如 `const t = …trim()`）。

### 语言解析

```
设置值 explicit（en / zh-cn）  → 直接采用（覆盖 VS Code 显示语言）
设置值 auto（默认）           → 显示语言以 zh 开头（zh-cn / zh-tw / zh-hans…）→ zh-cn；其余 → en
设置值非法                    → 按 auto 处理
```

- 切换方式：命令面板 `Code::Blocks: Switch UI Language…`（`codeblocks.ui.switchLanguage`，QuickPick 三态 + 当前项标记），
  或直接在设置里改 `codeblocks.ui.language`。
- 设置变更监听会 `refreshUiLanguage()` + 刷新状态栏 + 刷新**已打开面板的标题**；
  面板正文/标签在下次打开时按新语言渲染 —— 有意不重渲染 HTML：工程属性面板的编辑态只存在于 WebView，
  重渲染会整体丢弃未保存改动，而语言属于外观偏好。
- 生效语言是**进程内缓存**：`t()` 不每行读配置（避免热路径开销），只在设置变更与激活时刷新。

## 3. 静态贡献实现

- `package.json` 中所有用户可见文案均为 `%key%`，键命名：

| 对象 | 键样式 | 例 |
| --- | --- | --- |
| 扩展名/描述 | `extension.displayName` / `extension.description` | `Code::Blocks for VS Code` |
| 命令标题 | `command.<命令 id>.title` | `command.codeblocks.newProject.title` |
| 设置描述 | `configuration.<设置键>.description` / `.markdownDescription` | `configuration.codeblocks.parallelJobs.description` |
| 设置枚举说明 | `configuration.<设置键>.enumDescription.<n>` | `configuration.codeblocks.ui.language.enumDescription.0` |
| 视图 / 容器 | `view.<视图 id>.name` / `viewsContainer.<容器 id>.title` | `view.codeblocks.projectTree.name` |
| 欢迎语 | `viewsWelcome.<视图 id>.contents` | `viewsWelcome.codeblocks.projectTree.contents` |
| 调试器片段 | `debugger.snippet.<n>.description` | `debugger.snippet.0.description` |

- 两个 nls 文件**键集合必须一致**、值非空；英文值不得含中文；中文值应为真实译义
  （产品名/专名如 `Code::Blocks`、`IntelliSense (clangd)` 白名单豁免，见测试）。
- nls 值**不得再是 `%key%`**（二级占位符会原样显示）。
- 测试侧读静态文案请用 [`tests/_harness/nls.js`](../tests/_harness/nls.js)（`cmdTitle()` / `nlsText()` /
  `setLanguage('en'|'zh-cn')`），不要直接断言 `%key%`。

## 5. 已知限制

1. **命令标题 / 设置界面无法运行时切换**（VS Code 约束，见 §1）；`ui.language` 与显示语言不一致时存在混语言现象。
2. **面板正文语言在打开时固定**：切换语言后已打开面板的正文/标签不变（标题会刷新），重新打开即按新语言渲染。
3. **`zh-cn` 是唯一中文词条**：`zh-tw` / `zh-hk` 等显示语言在 `auto` 下按 `zh-cn` 处理（不区分繁简）。
4. **一键一值**：词条表以英文源串为键，同一英文只能有一个中文译义；需要两种中文表述的场景（如 `Clean` 的
   快捷键行双语标签 vs 确认按钮「清理」）用**不同英文源串**区分（`Clean` / `Clean now`），不引入第二份表。
5. **构建日志的双开关**：`log.english=true` 时日志恒英文（忽略 `ui.language`）；其余界面文案仍跟随 `ui.language`。
   这两个设置分别控制「CB 原文对齐」与「界面语言」，属有意设计。
6. 新增语言（如 `ja`）需：新增 `src/i18n/strings.<lang>.json` + `resolveLanguage` 分支 + `UI_LANGUAGE_VALUES` /
   `package.json` 枚举 + 两个 nls 文件（静态贡献）。
