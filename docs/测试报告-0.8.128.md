> 调试 E2E 的相应断言已从「据实记录」翻转为「期望行为」，回归与决策记录见 [遗留问题决策清单 §6](./遗留问题决策清单.md)。
> 测试侧的稳定性问题（非产品缺陷）：真实进程类性能基准在 Windows 负载下 median 会被抬高 10x（如 B8 min 294ms / median 2721ms），已通过「预算门禁用 min + 首次超预算自动复核」解决。
> CI（windows-latest）首跑暴露 3 个**既有用例的机器相关性**（写死本机 `E:\` 绝对路径与带空格引号、依赖「仓库在非 C: 卷」、`make` 与 `sh` 的组合），已在测试侧做最小可移植化处理（期望值按当前环境推导 / 前置不满足即 SKIP，断言语义不变）。
> 宿主层的**测试框架限制**（非产品缺陷）：`--extensionTestsPath` 运行方式下，从测试扩展调用 `vscode.debug.startDebugging` 会永久挂起（内置 `ms-vscode.js-debug` 的 `pwa-node` 同样挂起，且工作台仍响应其它命令）。已改用「工作台侧发起调试」（F5 命令 + launch.json），详见方案 §5.3。
